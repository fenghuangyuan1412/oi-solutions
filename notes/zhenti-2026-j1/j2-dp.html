阅读程序(2)：一个"四不像"的二维 dp —— 逐格填表

它看着像编辑距离、又看着像 LCS，其实两个都不是：相等时取左上 +1（像 LCS），不等时取 min(上,左) +1（像编辑距离）。两个分支都加 1，数值只会一路往上涨，靠直觉必错，只能老实填表。下面按代码里 i 外层 / j 内层 的真实顺序一格一格算，表上每个数字都是现场模拟出来的（和编译运行 r2.cpp 的结果一致）。

对照：同一对字符串，三种写法各算出什么（真 LCS / 真编辑距离都由本页现场计算，不是抄来的）

算法字符相等时字符不等时本题结果
本程序（四不像）dp[i-1][j-1] +1min(dp[i-1][j], dp[i][j-1]) +1-
真 LCS（最长公共子序列长度）f[i-1][j-1] +1max(f[i-1][j], f[i][j-1])，不 +1-
真编辑距离（增 / 删 / 改 代价都是 1）g[i-1][j-1] +0（字符相同不用花钱）min(g[i-1][j]+1, g[i][j-1]+1, g[i-1][j-1]+1)-
  • 差别就在这两个"+1 还是 +0 / max 还是 min"上：真正的 LCS 在不等时取 max 且不 +1；真正的编辑距离在相等时是 +0。本程序两个分支都 +1 —— 等于"每往右下走一格就强制记 1 笔"，所以数值只会往上涨，绝不会像编辑距离那样在字符相同处停下来，也绝不会像 LCS 那样把不好的分支丢掉不要。
  • 所以它算的不是标准编辑距离，也不是 LCS；直观上更接近"沿对角线的相等匹配数 + 剩下没匹配上的步数"这一类东西。这句话只用来帮助记忆，卷面不需要给它名字 —— 讲义的结论是：不要拿"LCS / 编辑距离"的直觉去猜答案，必须老老实实填表。
  • 可以现场验证的一条：第 0 行是 0,1,2,…，第 0 列是 0,1,2,…，右下角永远不超过 n+m（题 22）；但当 a == b 时它正好等于 min(n,m)（题 23 把">"写成"≥"就错在这里 —— 试试预设 `a / a`）。

卷面结论（全部机器实测，见 verify/RESULTS.md）

  • 题 21（T）：交换 a 和 b，输出不变。把 (a,b) 换成 (b,a) 只是把整张表沿主对角线转置：第 0 行 / 第 0 列的定义互换后仍成立；"相等"分支用的还是 dp[i-1][j-1]；"不等"分支的 min(dp[i-1][j], dp[i][j-1]) 两项互换、min 不变。右下角 dp[n][m] 与 dp[m][n] 同步互换 → 值不变。实测：`aba bab` 与 `bab aba` 都输出 4；`abcddd acbded` 反过来也输出 8；随机 20000 组 + 穷举（长度 1..4、字母 {a,b} 全部 900 个有序对）不同 = 0 组。
  • 题 22（T）：输出 ≤ n+m。归纳"任意格 dp[i][j] ≤ i+j"：边界 dp[0][j]=j ≤ 0+j、dp[i][0]=i ≤ i+0；相等分支 dp[i-1][j-1]+1 ≤ (i-1)+(j-1)+1 = i+j-1；不等分支 min(dp[i-1][j], dp[i][j-1])+1 ≤ (i+j-1)+1 = i+j。实测 20000 组随机（长度 1..6、字母 a~d）+ 900 组穷举，最大输出 8，未见超过。
  • 题 23（F）：说"输出 > min(n,m)"是假的。最小心输入 `a` / `a`：dp[1][1] = dp[0][0] + 1 = 1，min(n,m)=1，"1 > 1" 为假。同样 `ab ab` → 2、`abcd abcd` → 4。实测规律（未见反例）：输出 ≥ min(n,m) 恒成立，等号当且仅当 a == b；随机 20000 组里反例 172 组、穷举 900 组里反例 30 组，正好都是 a == b 的那些。
  • 题 24 = A（4）：`aba` / `bab` → dp[3][3] = 4（真 LCS = 2，真编辑距离 = 2，和 4 完全不同，用直觉一定错）。
  • 题 25 = B（8）：`abcddd` / `acbded` → dp[6][6] = 8（真 LCS = 4，真编辑距离 = 3；选项里的 7 / 9 / 10 都是差一错误的产物）。
  • 题 26 = D（156）：长度 2、字母只有 a/b/c/d，16×16 = 256 个有序对全穷举实测：输出 2 有 16 组（= A 选项，正是 a == b 的对角线），输出 3 有 156 组，输出 4 有 84 组（= C 选项；题问的是 3）。16 + 156 + 84 = 256 校验通过。
