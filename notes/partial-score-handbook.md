# 骗分 / 部分分技术手册（配合本仓库 10 道题使用）

> 定位：**这是一份教案，不是题解。** 题解在 `solutions/` 各目录里。
> 受众：能写 `for` 循环、会用 `sort`、知道 `long long` 的学生（普及组水平）。
> 目标课时：2 课时（90 分钟），每讲一个技术点就现场跑一份库里的代码。

---

## 0. 先说清楚"骗分"是什么

"骗分"是我们的行话，指的是**在不会（或来不及）写正解时，用有保证的写法把能拿的分一块块搬回来**。它不是投机取巧，而是评测机制的直接推论：

1. 竞赛题是**按测试点/子任务给分**的。洛谷、CSP-J/S、NOIP 的每题都由多个测试点组成，每个点独立计分，题目页会写明"对于 xx% 的数据，满足 ……"。
2. **部分分不需要你承认自己不会做**。写一个只会处理小数据的正确程序，比写一个"看起来很大数据但其实错"的程序得分高得多。
3. 反过来，**Runtime Error / 编译错误 / 输出空行 = 这个点 0 分**。所以"兜底输出"这件事本身就值钱。

一句话结论：**骗分 = 把"我会的那部分"完整、正确地输出出来。** 下面 10 个技术点，每个都在本仓库有对应的题和实测数据。

## 1. 第一项技能：把数据范围翻译成"允许的复杂度"

拿到题先做三件事，共约 3 分钟：

| 步骤 | 做什么 | 例：P7074 方格取数 |
| --- | --- | --- |
| ① 抄下分档表 | 逐字抄，别"大概记住" | 20% `n,m≤5`；40% `≤50`；70% `≤300`；100% `≤1000` |
| ② 估每档的操作量 | 代进你猜的复杂度 | $O(n^2m)$：$300^3=2.7\times10^7$ ✅；$1000^3=10^9$ ⚠️ |
| ③ 和"本机一秒能跑多少"比 | 别背"1e9 一秒"，自己在评测前用极限数据测一次 | 见下表 |

**本仓库自己实测出来的换算尺**（同一台机器，`g++ -static -O2 -std=c++14`）：

| 实测来源 | 循环规模 | 用时 | 推出来的换算 |
| --- | --- | --- | --- |
| P7074 `solution_mid.cpp`（$n^2m$ 三重循环）在 $1000\times1000$ | $\approx 10^9$ 次 | 1.71~1.78 s | $10^9$ 次简单循环 ≈ 1.7 s，**时限 1 s 时不能赌** |
| P1309 暴力（每轮 `sort`，$\approx 1.8\times10^8$ 次比较）在 $N=10^5,R=50$ | $\approx 2\times10^8$ 次比较 | 0.48~0.50 s | 带函数调用的 `sort` 比较 ≈ $4\times10^8$/s |
| P1563 玩具谜题最坏指令（$n=m=10^5$） | 一次平移 $O(1)$ | ~0.06 s | 说明"逐格走 $10^{10}$ 步"和"一次平移"差 5 个数量级 |

**课堂演示（3 分钟）**：把 P7074 的中间档直接喂 $1000\times1000$，让学生先猜"能不能过"，再跑给他们看 1.7 秒 —— 幻觉当场破掉。

## 2. 十个技术点

### T1 暴力本身就是分数
- **哪道题**：P1309 瑞士轮（30% $N\le100$ / 50% $N\le10^4$ / 100% $N\le10^5$，暴力是每轮全排序）。
- **证据**：同一份随机极限数据上，暴力 $0.47\sim0.50$ s，归并 $0.149\sim0.153$ s（各两轮、每轮三次），两版每轮输出同一个数。
- **要点**：暴力"在本机没超时"**不等于**在评测机能过。分档表算出的操作量要真代入，最后拿分要靠提交实测。

### T2 按数据范围写"三级阶梯"
- **哪道题**：P7074 方格取数 —— DFS（20 分）→ $O(n^2m)$（70 分）→ $O(nm)$（100 分），三份代码都在目录里。
- **额外收益**：三个版本互为对拍。小数据 DFS 拍中间档，中间档拍满分档，任一环节写错都会被自己的另外两版抓到（实测 1500 组 + 600 组两两 0 不一致）。
- **要点**：阶梯之间往往只差"一个 $\max$ 能不能提前算好"，看破这层就升一档。

### T3 分数藏在**数据类型**里
- **哪道题**：P1005 矩阵取数游戏。题面 60% 档明写"答案不超过 $10^{16}$" ⇒ 这一档 `long long` 直接够，等于白送 60 分；剩下 40 分才需要高精度/`__int128`。
- **证据**：`long long` 版在 $m=40/45/50$ 时对，$m=58$ 起错（实测输出 `4611686018427385904`，真值 `576460752303423486000`）。溢出边界是量出来的，不是猜的。
- **同款坑**：P2241 统计方形，$n,m\le5000$ 时答案可达 $1.5\times10^{14}$，**`n`、`m` 也要声明成 `long long`**，否则乘法先按 `int` 算完再转类型照样溢出。

### T4 特殊性质分档：只做"有保证的那一类"
- **哪道题**：P9750 一元二次方程（题面给了特殊性质 A/B/C）。
- **推理链（这一段值得板书）**：性质 B（$c=0$）⇒ $\Delta=b^2$ 必为完全平方；性质 C（两根为整数）⇒ $\Delta=a^2(r_1-r_2)^2$ 必为完全平方。⇒ **只写"有理根"分支**，测试点 1/3/5/6/7/8 是稳稳的，无理根那一档先放着。
- **诚实的边界**：性质 A（$b=0$）⇒ $\Delta=-4ac$，**不保证**是完全平方 ⇒ 那一档拿不到。实测 20 万组 $b=0$ 的数据里 49.8% 输出 `NO`、0.2% 有理、49.9% 无理。
- **要点**：骗分要挑"有正确性保证"的分支写，**不要靠浮点数蒙**。

### T5 只算前 k 步 / 小数据精确
- **哪道题**：P1095 守望者的逃离。不会推公式就先**逐秒 DP**（状态=当前魔法值，值=最远距离），$T\le3\times10^5$、魔法值有界 ⇒ 稳拿部分分；会推公式再枚举闪光次数 $k$，$O(S)$ 以内直接满分。
- **要点**：写不出闭式时，"把每一秒都算一遍"几乎总是可行的兜底。

### T6 漏一条规则的代价（反面教材）
- **哪道题**：P1095。有个看起来很顺的贪心：只会跑和闪，**从不休息**。
- **实测**：500 组随机数据上它与正确答案一致 **106~125 组（三轮：21.2% / 21.4% / 25.0%）**，而且**官方样例 2 都过不去**（输出 `Yes 8`，正解 `Yes 6`）。
- **同款坑**：P1540 机器翻译。题面写的是"最早进入内存的那个单词被清除"（FIFO），很多人读成 LRU。同一份数据两种读法在 2000 组随机测试里有 **36.9%** 给出不同答案。
- **要点**：**读题时把每条规则单独打勾**。"少实现一条规则"的代价通常比"复杂度差一档"更大。

### T7 输出格式逐字实现
- **哪道题**：P9750 满分版 —— 题面 5 条输出规则（`q1` 是否为 0、`q2` 是否为 1、分母是否为 1、`sqrt(r)` 的写法、以及 `NO`），一条写错这一档就是 0 分。
- **要点**：**格式分不是小分**。检查器是逐字符比对的；`1*sqrt(5)` 和 `sqrt(5)` 是两个答案。

### T8 预处理 / 换成"按类计数"
- **哪道题**：P2241 统计方形。枚举四条边是 $O(n^2m^2)=6.25\times10^{14}$，必死；改成"按尺寸 $h\times w$ 分类"，个数 $=(n-h+1)(m-w+1)$，$O(nm)$。
- **要点**：超时不一定是"算法档次不够"，常常是**计数对象选错了**。

### T9 化"逐格模拟"为"一次平移"
- **哪道题**：P1563 玩具谜题。$n,m\le10^5$，逐格走最坏 $10^{10}$ 步；把每条指令看成"下标整体位移"就成 $O(n+s)$。
- **附带坑**：C++ 的 `%` 对负数返回负值，环形下标必须写 `((x % n) + n) % n`。

### T10 倒序 / 换枚举方向，省掉整张数组
- **哪道题**：P1003 铺地毯。"最上面"= 编号最大 ⇒ **倒序枚举、第一个命中就 `break`**，$O(n)$；正面模拟要开一张覆盖 $10^5\times10^5$ 的网格数组（约 40 GB，根本开不下）。
- **要点**：当"记录全过程"撑不住时，先问自己能不能**只记录答案**。

> **本仓库还没有实测过的技术**：打表（把小范围的表写死）、随机化/模拟退火骗期望分、以及 NOI 系列"提交部分解"的评测细节。这几项我目前只有一般性认识、没有本机数据支撑，因此**故意没写进上面的清单**，讲课时不要引用"某某题实测证明"。

## 3. 考场时间预算表（CSP-J 第二轮 3.5 小时 4 题）

| 时间点 | 该做的决定 |
| --- | --- |
| 0:00–0:15 | 四题都读一遍，抄下每题的分档表和数据范围 |
| 0:15–0:45 | 每题**先写暴力/兜底版**并跑通样例（哪怕只值 20~40 分） |
| 0:45–2:15 | 挑最有把握的一题升档：T4 特殊性质 → T3 数据类型 → T2 结构观察 |
| 2:15–3:00 | 对拍：小数据暴力 vs 大数据优化版（库里的 `verify.js` 就是这个思路） |
| 3:00–3:20 | 检查输出格式（T7）、检查会不会 RE、检查数组大小 |
| 3:20–3:30 | 每题**至少留一个能编译、能输出、不会 RE 的版本**在提交框里 |

**红线（务必讲）**：
- 千万别为了"看起来像正解"交一份跑不出的代码 —— **RE / TLE 的点是真的 0 分**，而"能跑对的暴力"是实分。
- 不要交"用 `double` 四舍五入蒙整数"的版本还指望它得分。库里的 P9750 骗分版对无理根就是这么兜底的，它的作用是**别输出空行**，README 里明写了"考场里不要指望它得分"。
- 不要靠"样例过了"来判断正确性。本仓库两个真实 bug（P7074 的 `pre[i]`、初值 `0`）在样例 1 上**都还是对的**，只有全负的样例 2 才暴露。

| 题号 | 分组 | 版本 | 随机对拍 | 极限计时（本机） |
| --- | --- | --- | --- | --- |
| P1003 铺地毯 | 暴力模拟 | 倒序枚举 | 800 组 0 不一致（vs 真涂网格） | $n=10^4$：13 ms（冷启动 136 ms） |
| P2670 扫雷游戏 | 暴力模拟 | 八方向偏移 | 600 组 0 不一致（vs 逐格计数） | $100\times100$：6 ms（冷启动 124 ms） |

| P1563 玩具谜题 | 暴力模拟 | 环形下标一次平移 | 800 组 0 不一致（vs 逐格走） | $n=m=10^5$ 最坏指令：57 ms |
| P2241 统计方形 | 暴力模拟 | 按尺寸分类 + 闭式 | 400 + 40 组 0 不一致（vs BigInt 闭式） | $5000\times5000$：17~19 ms |
| P1309 瑞士轮 | 骗分 ① | 暴力 / 归并 | 1500 组 0 不一致（两版 + JS 参照） | $N=10^5$：0.47~0.50 s / 0.15 s |

| P1095 守望者的逃离 | 骗分 ③ | 枚举 $k$ / 反面教材 | 1200 组 0 不一致（vs 逐秒 DP） | $T=3\times10^5$：6~7 ms |
| P7074 方格取数 | 骗分 ④ | DFS / $O(n^2m)$ / $O(nm)$ | 1500 + 600 组两两 0 不一致 | $1000\times1000$：1.7 s / 0.17 s；DFS $8\times8$：约 0.14 s |
| P9750 一元二次方程 | 骗分 ⑤ | 有理档 / 满分档 | 四万余个方程（两轮 43652 / 43694）满分档 0 错；骗分档逐字对有理分支 0 不一致 | 按行判对 74.4%~74.6%（随机数据） |

复现方式：每个目录里 `node verify.js`（脚本头部有对应的 `g++` 编译命令）。JS 只做验算，题解代码一律 C++。

**关于"极限计时"的两条口径说明**（课堂上一定会有学生问）：
- 这些毫秒数是用 node 起子进程测的，**包含进程启动**；同一份 exe 首次冷启动可比重复运行慢 100 ms 以上（本机安全软件扫描所致）。评测机不含这层开销，所以看**重复运行的数字**更接近真实。
- 只有 P7074 / P1309 / P1005 这类真正吃规模的题，毫秒差才有判分意义；模拟题（P1003、P2670、P1540）的极限都在 10 ms 量级，重点是"算法档次对上了"，不是抢那几毫秒。

## 5. 布置作业的顺序建议

1. **P2670 → P1540 → P1003**：纯模拟，把"读题逐条打勾"练成习惯。
2. **P2241 → P1563**：第一次被"操作量"卡住，学会代入而不是背结论。
3. **P1309 → P7074**：完整走一遍"暴力 → 观察 → 阶梯"，并**自己写对拍**。
4. **P1095 → P1005 → P9750**：三课收官 —— 漏规则的代价、数据类型里的分、特殊性质与输出格式。
