## 题目大意

一排 $n$ 只怪物，血量 $a_i$ 全为**正整数**。一次连击打一段**连续**区间，伤害 = 区间和。问最多能打出多少段伤害**恰好等于 $k$** 且**两两不重叠**的连击（可以不连续，允许跳过怪物）。

- 输入：第一行 $n, k$；第二行 $n$ 个正整数 $a_i$
- 输出：一个整数，最多段数
- 数据范围：$1 \le n \le 10^6$，$1 \le k \le 10^9$，$1 \le a_i \le 10^3$
- 术语：**前缀和**指 $pre[i] = a_1 + \dots + a_i$，于是区间和 $= pre[r] - pre[l-1]$；**尺取法**（双指针）指左右端点都只朝一个方向移动、各自最多走 $n$ 步的枚举技巧。

本机实测（`g++ -static -O2 -std=c++14 solution.cpp -o /tmp/s1t3.exe`）：

| 输入 | `solution.cpp` | `brute.cpp` |
| --- | --- | --- |
| `6 5` + `2 3 1 4 2 3` | `3` | `3` |
| `3 7` + `3 3 3` | `0` | `0` |
| `8 3` + `1 2 1 2 1 1 1 3` | `4` | `4` |
| `3 3` + `1 2 1` | `1` | — |
| `5 5` + `5 5 5 5 5` | `5` | — |

## 思路推导

### 1. 暴力想法与瓶颈

最朴素的两层循环枚举所有 $(l, r)$ 判断和是否为 $k$，但"互不重叠"让"数出来几个就答几个"变成错的：例如 `3 3 / 1 2 1`，和恰为 3 的区间有 $[1,2]$ 和 $[2,3]$ **两个**，可它们重叠，真实答案是 **1**（本机实测输出 `1`）。所以暴力版 `brute.cpp` 用 DP：$f[i]$ = 前 $i$ 只怪物最多能打几段，枚举最后一段 $[j, i]$：

```cpp
f[i] = f[i - 1];
for (int j = i; j >= 1; j--) { s += a[j]; if (s > k) break; if (s == k) f[i] = max(f[i], f[j - 1] + 1); }
```

这是 $O(n^2)$。先说一个实测事实：**仓库里的 `brute.cpp` 数组只开到 305，只能喂 $n \le 300$ 的数据**（本机喂 $n = 2000$ 就已经越界、输出为空）。为了量化瓶颈，我把同一份暴力的数组临时放大到 200005（只改数组大小、逻辑一字未动）后计时：

| 数据（$k = 10^9$，$a_i \in [1,1000]$ 随机） | 放大后的暴力 | 正解 |
| --- | --- | --- |
| $n = 50000$ | 1.187 s | 0.098 s |
| $n = 200000$ | 16.163 s | 0.175 s |

按 $O(n^2)$ 外推到 $n = 10^6$，暴力约需 $16.163 \times 25 \approx 400$ 秒（约 6 分 40 秒），而正解实测 0.750 s。瓶颈是**每个右端点都把左端点从头试一遍**。

另一个常见思路"前缀和 + 哈希表数区间个数"能 $O(n)$ 数出所有和为 $k$ 的区间，但如上面 `1 2 1` 的例子，它管不了重叠，所以不够。

### 2. 关键观察

- **观察 A（正数 ⇒ 单调 ⇒ 可以尺取）**：$a_i \ge 1$，所以固定右端点 $r$ 时，$sum(l..r)$ 随 $l$ 右移**严格变小**；固定 $l$ 时随 $r$ 右移严格变大。于是左端点永远不需要后退：`while (sum > k) sum -= a[l], l++` 就能把窗口压回 $\le k$，$l, r$ 各自最多走 $n$ 步 ⇒ $O(n)$。
- **观察 B（以 $r$ 结尾的合法段至多一个）**：还是因为全正数，$sum(l..r)$ 对 $l$ 严格单调，等于 $k$ 的 $l$ 最多一个。所以"窗口和恰好等于 $k$"这件事**没有选择困难**，判一次就够。
- **观察 C（能收割就收割）**：问题本质是**区间调度**（在一堆候选区间里挑尽量多互不重叠的）。经典结论是"按结束位置最早挑"最优：$r$ 从左往右扫，第一次出现 $sum == k$ 时立刻计数，因为此时这段结束得最早，给后面留的空间最大。
- **观察 D（收割即重置）**：选中 $[l, r]$ 后，$r$ 及之前的怪物全部作废，直接 `sum = 0; l = r + 1;`，等价于在剩余部分重新起一段尺取。

### 3. 算法设计

```
读 n, k 与 a[1..n]
ans = 0, sum = 0, l = 1
for r = 1 .. n:
    sum += a[r]
    while l <= r 且 sum > k: sum -= a[l]; l++      // 观察 A：左端点只前进
    if sum == k: ans++; sum = 0; l = r + 1         // 观察 C+D：立刻收割
输出 ans
```

三个变量各自单调：`r` 每轮 +1，`l` 只在 `sum > k` 时 +1，且收割时直接跳到 `r+1`，因此 `l` 全程不回退。

### 4. 正确性说明

**引理 1（尺取不遗漏）**：对每个 $r$，循环结束时 $sum = a[l..r] \le k$，且 $l$ 是"从当前段起点开始、使窗口和 $\le k$"的最靠左下标（因为 $l-1$ 会让和 $> k$）。若存在某个 $l' \le r$ 使 $a[l'..r] = k$，由 $a$ 全正，$a[l..r]$ 是窗口和的最大可能值（$l$ 最靠左），故 $a[l..r] \ge a[l'..r] = k$；又 $a[l..r] \le k$，得 $a[l..r] = k$，即 $l' = l$（唯一性见观察 B）。**结论：以 $r$ 结尾的合法段存在当且仅当算法在该轮判到 $sum == k$。**

**引理 2（最早结束贪心最优）**：设算法第一段为 $[l_1, r_1]$，则 $r_1$ 是所有合法段中最小的右端点（引理 1 保证按 $r$ 递增扫描第一次命中）。取任一最优解，其第一段为 $[l_1', r_1']$，有 $r_1' \ge r_1$。把最优解的第一段换成 $[l_1, r_1]$：其余各段的左端点都 $> r_1' \ge r_1$，故仍与 $[l_1, r_1]$ 不重叠，段数不变，于是存在一个"以算法第一段开头"的最优解。对 $r_1$ 右侧的子问题归纳，可得算法段数 $\ge$ 最优段数；又算法每段都合法，故等于最优值。$\blacksquare$

### 5. 复杂度分析

- 时间：$r$ 走 $n$ 步，$l$ 全程只前进（收割时更是直接跳过一段），故 `while` 里的总执行次数 $\le n$，合计 $O(n)$。本机实测：

| 极限数据 | 答案 | 用时 |
| --- | --- | --- |
| $n=10^6$，$a_i \in [1,1000]$ 随机，$k=500000$ | `658` | 0.692 s |
| $n=10^6$，$a_i \equiv 1$，$k=1000$（子任务 8—11） | `1000` | 0.596 s |
| $n=10^6$，$a_i \in [1,1000]$ 随机，$k=10^9$（总和约 $5\times10^8$，一段都凑不出） | `0` | 0.750 s |

  第二行正好等于 $n / k = 10^6 / 1000 = 1000$，与"$a_i \equiv 1$ 时每段占 $k$ 只怪物"的手算一致。
- 空间：`a[10^6+5]` 的 `int` 数组约 4 MB，$O(n)$。

## 讲解代码

完整逐段注释版见 [`solution.cpp`](./solution.cpp)，关键片段：

```cpp
long long ans = 0, sum = 0;
int l = 1;
for (int r = 1; r <= n; r++) {
    sum += a[r];
    while (l <= r && sum > k) { sum -= a[l]; l++; }   // 全为正才敢只前进
    if (sum == k) { ans++; sum = 0; l = r + 1; }      // 最早结束 → 立刻收割
}
printf("%lld\n", ans);
```

## 易错点与坑

- **忘记"互不重叠"**：`1 2 1`、$k=3$ 时把区间个数当答案会输出 2，正解是 1。这是本题最贵的错。
- **尺取的前提是正数**：一旦允许 $0$ 或负数，`sum > k` 时收缩左端点就不再单调，必须换成"前缀和 + 哈希表"类做法（真题 P14359 的异或和正是这种情况，异或没有大小单调性）。
- **收割后忘记重置**：只写 `ans++` 而不写 `sum = 0; l = r + 1;`，下一轮会把已用过的怪物再算进窗口，答案偏大。
- **`while` 里加 `l <= r`**：$a_r$ 本身可能 $> k$，此时窗口会被收缩到空，缺这个判据 `l` 会越过 `r` 并把后面的和算错。
- **类型**：$k \le 10^9$，$sum$ 与 $k$ 比较请用 `long long`（$n \cdot a_i$ 最大 $10^9$，贴着 `int` 上限，稍有改动就溢出）。
- **输入规模**：$n = 10^6$，用 `scanf` 或关掉同步的 `cin`，别在循环里 `endl`。

## 常见变式

| 变式 | 差异 | 对应题号 |
| --- | --- | --- |
| 异或和恰为 k 的区间计数（真题原型） | 异或**无单调性**，尺取失效，改用前缀异或 + 哈希表计数 | P14359（CSP-J 2025 T3） |
| 和恰好为 $k$ 的区间**个数**（不要求不重叠） | 前缀和 + 哈希表，$O(n)$ 计数 | 本题退化版 |
| 和 $\ge k$ 的最短区间 | 同样是尺取，但判据变成"能缩就缩并更新答案" | 讨论课练习 |
| 最多不相交区间（区间调度模板） | 先枚举出所有候选区间，再按右端点排序贪心 | 讨论课练习 |
| 座位/网格定位 | 同为"贪心/模拟 + 定位"，但无最优性证明 | P14358（CSP-J 2025 T2） |

## 一句话提炼（板书）

**全是正数时，"和恰好等于 k"用尺取：右端点扩、太大就缩左端点；一旦等于 k 立刻收割并跳到下一段——最早结束的区间永远值得先要。**
