## T1 伤害溢出 / power

**核心思路一句话**：题面只问"$a^b$ 是否**严格大于** $10^9$"，是一句比较不是一个值——把 $a$ 除到右边判 `res > LIM / a`，乘法还没发生、溢出就无处发生；$a=1$ 与 $b=0$ 必须特判，否则 $b=10^9$ 时空转。

核心代码（摘自 [`t1-power/solution.cpp`](t1-power/solution.cpp)）：

```cpp
const ll LIM = 1000000000LL;
if (b == 0 || a == 1) { printf("1\n"); return 0; }   // 不特判就要空转 b 次
ll res = 1;
for (ll i = 0; i < b; i++) {
    if (res > LIM / a) { puts("over"); return 0; }    // 溢出前判定：除法在乘之前
    res *= a;                                         // 走到这里 a*res <= LIM，不会绕
}
printf("%lld\n", res);
```

**样例正确答案**（与 README 实测一致）：`10 9` → `1000000000`（恰好等于 $10^9$，**不算** over）；`10 10` → `over`；`2 29` → `536870912`；`1 1000000000` → `1`。

**部分分怎么给**（子任务见 `problem.txt` 第 56—62 行）：

| 子任务 | 分值 | 能过的做法 | 判分提示 |
| --- | --- | --- | --- |
| 1—3 | 15 | $b \le 3$：`brute.cpp` 的 `__int128` 硬乘到底再比也够 | 数据太小，别在这档挑剔写法 |
| 4—7 | 20 | $b \le 20$ 且 $a \le 100$：循环乘、一超就立刻退出 | 必须"即超即退"：硬乘满 $100^{20}$ 连 `__int128` 也绕 |
| 8—11 | 20 | $a = 2$：背下 $2^{30} = 1073741824 > 10^9$，$b \ge 30$ 直接 `over` | 完整判定在本档实测 `2 1000000000` 也只循环 30 次 |
| 12—14 | 15 | 保证答案 $\le 10^9$：可以删掉 over 分支直接输出值 | 但删不掉 $a=1$ 特判：实测暴力 `1 1000000000` 要 1.607 s |
| 15—20 | 30 | 完整除法判定 + $a=1$、$b=0$ 特判 | 见下方扣分点 |

**常见扣分点**：① 硬算 $b$ 次完再比（README 实测 $2^{70}$ 绕成 `0`、$3^{40}$ 绕成负数，样例最大才 $10^{10}$ 测不出来）；② `>` 写成 `>=`（实测 `10 9`、`1000 3` 会错报 over）；③ 先乘再判且 `int` 存 `res`（实测 `6 13` 输出 `175792128`、`1000000000 2` 输出 `-1486618624`）；④ 忘特判 $a=1$；⑤ `LIM` 写成 `1e9`（`double`）。

**详解**：[t1-power/README.md](t1-power/README.md) ｜ 演示：[t1-power/visualization.html](t1-power/visualization.html)

## T2 暗号解码 / decode

**核心思路一句话**：$N\le 10^9$ 时 $x$ 至多 9 位、$S(x)\le 81$，所以解只能躲在 $[N-81,\,N]$ 里；代码把窗口放宽到 $[N-200,\,N]$ 从左往右扫，第一个命中即最小解（$x\mapsto x+S(x)$ 不单调，不能二分）。

核心代码（摘自 [`t2-decode/solution.cpp`](t2-decode/solution.cpp)）：

```cpp
ll S(ll x) { ll s = 0; while (x) { s += x % 10; x /= 10; } return s; }  // 传值，不弄脏外面的 x
for (ll x = max(1LL, N - 200); x <= N; x++) {   // 从小到大 => 第一个命中就是最小解
    if (x + S(x) == N) { printf("%lld\n", x); return 0; }
}
puts("-1");                                     // 窗口内没有 => 全局没有
```

**样例正确答案**（与 README 实测一致）：`8` → `4`；`100` → `86`（$86+8+6=100$）；`1` → `-1`。附加实测：`1000000000` → `999999932`，`999999937` → `-1`。

**部分分怎么给**（子任务见 `problem.txt` 第 106—112 行）：

| 子任务 | 分值 | 能过的做法 | 判分提示 |
| --- | --- | --- | --- |
| 1—3 | 15 | $N \le 100$：`brute.cpp` 从 $x=1$ 线性枚举报满 | 暴力已对 $N \le 20000$ 全量核对过，本档稳过 |
| 4—7 | 20 | $N \le 10^5$：线性枚举到 $N$ 也只有 $10^5$ 次，瞬间跑完 | 本档比的是枚举逻辑而不是收缩技巧 |
| 8—11 | 20 | 保证解存在：窗口枚举 + 第一个命中，`-1` 分支可以不写 | 窗口仍不能开太小（见扣分点①） |
| 12—14 | 15 | 解恰好是 $N-10$：即使只会输出 `N-10` 也给这 15 分 | 窗口方向写反的代码常在这一档"碰巧对"，要结合样例判 |
| 15—20 | 30 | 完整 $[N-200,\,N]$ 窗口 + 无解判 `-1` | 见下方扣分点 |

**常见扣分点**：① 窗口只开 $[N-10,\,N]$ 漏解（README 实测 $N=999999979$ 的最小解间隔 **80**，$N\le 200000$ 最大间隔 45，理论上界 81）；② 从右往左扫拿到的是**最大**解；③ 想二分（实测 $f(99)=117 > f(100)=101$，不单调）；④ 忘 `max(1, N-200)`，$x$ 从 0/负数试起；⑤ `-1` 写在循环里；⑥ $S(x)$ 用引用改坏 $x$。

**详解**：[t2-decode/README.md](t2-decode/README.md) ｜ 演示：[t2-decode/visualization.html](t2-decode/visualization.html)

## T3 连招公式 / expr

**核心思路一句话**：调度场算法——数字压 `val`、运算符压 `op`，新运算符进来前把栈顶"不比自己优先级低"的全结算掉，`(` 当墙、`)` 算到墙为止；每一步都 `% 998244353`。第二问深度根本不用解析，读串时对未闭合 `(` 计数取 max 即可。

核心代码（摘自 [`t3-expr/solution.cpp`](t3-expr/solution.cpp)）：

```cpp
void apply() {                       // 先弹出的是右操作数 b
    ll b = val.back(); val.pop_back();
    ll a = val.back(); val.pop_back();
    char c = op.back(); op.pop_back();
    if (c == '+') val.push_back((a + b) % MOD);
    else val.push_back(a * b % MOD);
}
if (c == '(') { op.push_back(c); now++; depth = max(depth, now); }
else if (c == ')') { while (op.back() != '(') apply(); op.pop_back(); now--; }
else { while (!op.empty() && op.back() != '(' && prec(op.back()) >= prec(c)) apply();
       op.push_back(c); }
```

**样例正确答案**（与 README 实测一致，双栈版与递归下降版输出相同）：`1+2*3` → `7` / `0`；`(1+2)*3` → `9` / `1`；`((1+2)*(3+4))*2` → `42` / `2`；`1+(2+3*(4+(5+6)))*7` → `330` / `3`。附加实测：`999999999` → `1755646` / `0`（单数字也要取模）。

**部分分怎么给**（子任务见 `problem.txt` 第 174—180 行）：

| 子任务 | 分值 | 能过的做法 | 判分提示 |
| --- | --- | --- | --- |
| 1—3 | 15 | 无括号：两遍扫描先 `*` 后 `+` 也能报满 | 递归下降在本档同样过（没有深层嵌套） |
| 4—7 | 20 | 只有 `+`：边读边模求和 + 深度计数器 | 第二问在本档根本不依赖解析（README 观察 C） |
| 8—11 | 20 | 长度 $\le 100$：`brute.cpp` 递归下降过得去，嵌套至多 100 层 | 实测递归下降 8000 层还能算、**10000 层崩**（`0xC00000FD` 栈溢出，无输出），本档才安全 |
| 12—14 | 15 | 数字全是个位：漏写 `while (isdigit)` 只读一位的写法恰好能过 | 用这一档区分"读数字"是否真会 |
| 15—20 | 30 | 完整双栈（或压栈改递归 + 深度限制） | 见下方扣分点 |

**常见扣分点**：① 结算条件漏 `op.back() != '('`，括号外运算符被提前算掉；② 数字只读一位，`123` 变三个数；③ 只在最后取模（`int` 存中间乘积必爆；`long long` 存两个已模数相乘约 $9.96\times 10^{17}$ 才装得下）；④ `apply()` 里 $a,b$ 顺序反了——本题 `+`/`*` 可交换**样例查不出**，批改时单独问一句；⑤ 递归下降遇深嵌套崩（双栈版实测 49999 层安然无恙）；⑥ 数字分支走完又 `i++`，跳过下一个运算符。

**详解**：[t3-expr/README.md](t3-expr/README.md) ｜ 演示：[t3-expr/visualization.html](t3-expr/visualization.html)

## T4 谷价走势 / trend

**核心思路一句话**：$f[i]$ = 以第 $i$ 天结尾的最长合法选取长度、$g[i]$ = 达到它的方案数；转移只看左边 $d$ 格窗口内的 $j$（要求 $p_j < p_i$），**更长就覆盖方案数、一样长就累加**；全局答案只汇总 $f[i] = \text{best}$ 的 $g[i]$，模 998244353。

核心代码（摘自 [`t4-trend/solution.cpp`](t4-trend/solution.cpp)）：

```cpp
for (int i = 1; i <= n; i++) {
    f[i] = 1; g[i] = 1;                              // 只选第 i 天：长度 1，方案 1
    for (int j = max(1, i - d); j < i; j++) {
        if (p[j] >= p[i]) continue;                  // 严格上升：相等必须跳过
        if (f[j] + 1 > f[i]) { f[i] = f[j] + 1; g[i] = g[j]; }               // 更长 => 覆盖
        else if (f[j] + 1 == f[i]) { g[i] += g[j]; if (g[i] >= MOD) g[i] -= MOD; }  // 相等 => 累加
    }
    if (f[i] > best) { best = f[i]; cnt = g[i]; }
    else if (f[i] == best) { cnt += g[i]; if (cnt >= MOD) cnt -= MOD; }
}
```

**样例正确答案**（与 README 实测一致）：`6 2 / 3 1 2 1 3 4` → `4 1`；`5 5 / 1 1 2 2 3` → `3 4`（README 附 $f,g$ 表：$g_5 = g_3 + g_4 = 2+2$）；`5 1 / 1 5 2 3 4` → `3 1`。附加实测：`4 3 / 2 2 2 2` → `1 4`。

**部分分怎么给**（子任务见 `problem.txt` 第 241—247 行）：

| 子任务 | 分值 | 能过的做法 | 判分提示 |
| --- | --- | --- | --- |
| 1—3 | 15 | $n \le 18$：`brute.cpp` 状压枚举全部非空子集逐个验证 | 实测暴力 $n=18$ 要 0.327 s、$n=24$ 已 21.919 s，别让学生把它拖向 5000 |
| 4—7 | 20 | $d = 1$：只能连选，退化为"最长连续严格上升段 + 计数"，线性一遍 | 写不出完整 DP 的学生靠这一档抢分 |
| 8—11 | 20 | $d \ge n$：窗口失效，普通 $O(n^2)$ 计数 DP 即可 | 样例 2 恰是 $d=5=n$，专门用来查这一档 |
| 12—14 | 15 | $p_i$ 互不相同且 $n \le 500$：$O(n^2)$ DP（仍要按窗口截左端点）跑得动 | 值互不相同 ⇒ `>=`/`>` 判错在本档**查不出来**，严格上升要在满档盯 |
| 15—20 | 30 | 完整 $O(nd)$ 窗口 DP + 覆盖/累加计数 | 见下方扣分点 |

**常见扣分点**：① 相等也允许接（$p=1,1,2,2,3$ 若写成 $p_j \le p_i$，样例 2 长度会变 5，当场暴露）；② 两处"覆盖/累加"混成一律累加或一律覆盖（README 实测一律覆盖时样例 2 输出 `3 1`，正确 `3 4`；样例 1、3 恰好只有 1 种方案查不出）；③ 忘 `g[i]=1` 初值（`4 3 / 2 2 2 2` 应 `1 4`，缺初值输出 `1 0`）；④ 窗口左端点漏 `max(1, i-d)` 越界读；⑤ 全局汇总把 $f[i] < \text{best}$ 的 $g[i]$ 也加进去；⑥ $g$、$\text{cnt}$ 不取模。

## 批改时的三个通用提醒

1. **对齐关系**：本套考点对齐 CSP-J 2021—2022 第二轮（题面首行注明），四题具体对标 2022 年 T1—T4（P8813 乘方 / P8814 解密 / P8815 逻辑表达式 / P8816 上升点列），但**都是自编模拟卷，不是任何一年的真题原题**。学生整段背真题代码会在三处直接错：T1（本题多出 $b=0$ 约定，且不超过时要输出具体值）、T3（真题是按位逻辑运算 + 短路求值 + 输出赋值方案，本题是四则运算 + 每步取模 + 深度）、T4（真题另需输出具体点列，本题只输出长度与方案数）。
2. **`brute.cpp` 只用于对拍**：T1 的用 `__int128` 硬乘到底且没有 $a=1$ 特判（实测 1.607 s）；T2 的枚举到 $N$，$N=10^9$ 实测 11.4 s；T3 的递归下降 10000 层嵌套直接崩掉；T4 的枚举子集 $n=24$ 已 21.919 s。它们本身就是"部分分实现"，别当满分参考。
3. **本卷按标准输入输出练习**（`problem.txt` 开头注明）：正式复赛要求文件读写（`freopen`）。本套 $10^5$/$5000$ 规模不卡 `cin/cout`，但 T1/T2 的类型是硬要求——`LIM` 必须写 `1000000000LL` 而非 `1e9`，`unsigned` 在 $N-200$ 为负时会绕飞；批改时按"实现细节"提醒而不必判死。
