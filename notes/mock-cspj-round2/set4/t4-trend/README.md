## 题目大意

$n$ 天均价 $p_1 \dots p_n$，选出下标 $i_1 < i_2 < \dots < i_m$，要求**价格严格上升**且**相邻两个下标之差 ≤ d**。求 $m$ 的最大值，以及取到最大 $m$ 的**选取方案数**（模 998244353）。只选 1 天合法。

- 输入：第一行 $n, d$；第二行 $n$ 个整数 $p_i$
- 输出：一行两个整数：最大 $m$ 与方案数
- 数据范围：$1 \le n \le 5000$，$1 \le d \le 5000$，$1 \le p_i \le 10^9$
- 术语：**严格上升**指后一个必须**大于**前一个，相等不算（$p = 1,1$ 不能连选）；**方案**指"选了哪几天"这个下标集合，价格相同但日子不同算不同方案。

本机实测（`g++ -static -O2 -std=c++14 solution.cpp -o /tmp/s4t4.exe`，stdin 重定向喂数据）：

| 输入 | 期望 | `solution.cpp` | `brute.cpp`（$n \le 18$ 枚举子集） |
| --- | --- | --- | --- |
| `6 2 / 3 1 2 1 3 4` | 4 1 | `4 1` | `4 1` |
| `5 5 / 1 1 2 2 3` | 3 4 | `3 4` | `3 4` |
| `5 1 / 1 5 2 3 4` | 3 1 | `3 1` | `3 1` |
| `1 1 / 7` | 1 1 | `1 1` | 同 |
| `4 3 / 2 2 2 2` | 只能选 1 天，4 种选法 | `1 4` | `1 4` |
| `6 6 / 1 2 1 2 1 2` | 2 6 | `2 6` | `2 6` |

## 思路推导

### 1. 暴力想法与瓶颈

`brute.cpp` 枚举每个非空下标子集（$2^n - 1$ 个），逐个检查"是否严格上升 + 相邻间隔 ≤ d"。逻辑最直白，但 $2^n$ 是指数级：本机实测同一批随机数据（$d = n/2$）——

| $n$ | 暴力耗时 | 暴力输出 | 正解耗时 | 正解输出 |
| --- | --- | --- | --- | --- |
| 14 | 0.027 s | `5 1` | 0.009 s | `5 1` |
| 16 | 0.090 s | `6 6` | 0.006 s | `6 6` |
| 18 | 0.327 s | `4 9` | 0.007 s | `4 9` |
| 20 | 1.371 s | `5 4` | 0.006 s | `5 4` |
| 22 | 5.522 s | `7 1` | 0.007 s | `7 1` |
| 24 | 21.919 s | `7 21` | 0.006 s | `7 21` |

每加 2 天耗时约 ×4，$n = 5000$ 完全不可行。瓶颈：子集之间有大量重复计算——"以第 $i$ 天结尾的最优解"被反复重算。

### 2. 关键观察

- **观察 A（后缀可分离 = 最优子结构）**：任何合法选取方案，去掉最后一天仍然合法（严格上升性和间隔限制都对"前缀子列"封闭）。所以"以 $i$ 结尾"的最长方案，前面接的一定是"以某个 $j$ 结尾"的最长方案。
- **观察 B（只需要看左边 $d$ 个）**：约束 $i - j \le d$ 把转移来源限制在 $j \in [\max(1, i-d),\ i-1]$，这就是"窗口"。$d \ge n$ 时窗口就是全部左边，退化成普通 LIS。
- **观察 C（方案数按"最后一个元素"分类不重不漏）**：每个方案有唯一的最后一天 $i$。把 $i$ 固定后，方案数 = 以 $i$ 结尾且长度等于 $f[i]$ 的方案数 $g[i]$。因此总方案数 = 所有满足 $f[i] = \text{best}$ 的 $g[i]$ 之和。
- **观察 D（计数要跟着"更长"走）**：转移时若 $f[j] + 1 > f[i]$，是**发现更长**，方案数要**覆盖**成 $g[j]$（不是累加）；只有 $f[j] + 1 == f[i]$ 才**累加** $g[j]$。这是所有"DP 数方案"题的通病，也是最容易写错的一行。

### 3. 算法设计

状态：$f[i]$ = 以第 $i$ 天结尾的合法选取的最大长度；$g[i]$ = 达到 $f[i]$ 的方案数。

$$f[i] = 1 + \max_{\substack{j \in [\max(1,i-d),\, i-1] \\ p_j < p_i}} f[j], \qquad (\text{无合法 } j \text{ 时 } f[i] = 1)$$

转移按"更长就覆盖、相等就累加"实现：

```
f[i] = 1; g[i] = 1;                       // 只选自己这一天
for j = max(1, i-d) .. i-1:
    if p[j] >= p[i]: continue             // 严格上升
    if f[j] + 1 >  f[i]: f[i] = f[j]+1; g[i] = g[j];
    elif f[j] + 1 == f[i]: g[i] = (g[i] + g[j]) % MOD;
```

全局答案 $\text{best} = \max_i f[i]$，$\text{cnt} = \sum_{f[i] = \text{best}} g[i] \pmod{M}$，边算边更新即可，不必第二遍扫。

### 4. 正确性说明

**引理 1（状态覆盖完整）**：任一合法方案 $i_1 < \dots < i_m$，其去掉 $i_m$ 后的部分仍是"以 $i_{m-1}$ 结尾的合法方案"，且 $i_{m-1} \in [i_m - d,\ i_m - 1]$、$p_{i_{m-1}} < p_{i_m}$。故 $f[i_m] \ge f[i_{m-1}] + 1$，归纳可得 $f[i_m] \ge m$。反过来，$f$ 的每次转移都显式检查了这两个条件，所以 $f[i]$ 一定对应某个真实存在的合法方案，即 $f[i] \le$ 真实最长长度。两端夹住 ⇒ 相等。

**引理 2（方案数不重不漏）**：对固定 $i$，把"以 $i$ 结尾且长度为 $f[i]$"的方案按**倒数第二天** $j$ 分类。不同 $j$ 给出的下标集合必然不同（倒数第二天不同），故各类互不相交；每个这样的方案去掉 $i$ 后就是"以 $j$ 结尾、长度 $f[j] = f[i]-1$"的方案，故第 $j$ 类恰好有 $g[j]$ 个。求和即 $g[i]$，正是代码"相等就累加"的语义。只选一天这一类贡献 $g[i] \mathrel{+}= 1$ 的初值。
**引理 3（全局计数）**：由观察 C，方案按其最后一天互不相同地划分，故 $\text{cnt} = \sum_{f[i]=\text{best}} g[i]$ 恰好数完所有最长方案，且不数任何短方案。$\blacksquare$

**样例 2 复核**（本机用同一份逻辑打印的 $f, g$ 表）：$p = 1,1,2,2,3$，$d = 5$ 时 $f = 1,1,2,2,3$，$g = 1,1,2,2,4$ —— 第 5 天的 4 来自 $j=3$ 的 2 种与 $j=4$ 的 2 种，正是题面说的 $(1,3,5),(2,3,5),(1,4,5),(2,4,5)$。

### 5. 复杂度分析

- 时间：$\sum_i \min(d, i-1) = O(nd)$，$n = d = 5000$ 时约 $2.5 \times 10^7$ 次比较。本机实测（四档各跑 5 次取最快；第一档就是 `../../verify.js` 里 `perf` 用的 `rng(41)` 数据，`verify/RESULTS.md` 记的 41 ms 与它对上）：
  - 随机 $p \in [1,10^9]$（`rng(41)`，$n = d = 5000$）：`141 426508052`，**0.041 s**；
  - 严格递增 $p_i = i$（每个前驱都合法，内层几乎不跳过）：`5000 1`，**0.017 s**；
  - 全部相等 $p_i \equiv 2$（只能选 1 天）：`1 5000`，**0.010 s**；
  - $d = 1$ + 严格递增（必须连续）：`5000 1`，**0.007 s**。
  三档递增/相等的数据比随机档还快，是因为 `continue` 提前跳过的比例不同——同一个 $O(nd)$ 上界，常数差别可以很大。
- 空间：$p, f, g$ 三个长度 5005 的数组，$O(n)$。
- 对拍：5000 组随机（$n \in [1,14]$、$d \in [1,n]$、$p_i \in [1,12]$——值域故意压得很小，一半以上的数会相等，专门制造"严格上升判据写错"的场景），与 `brute.cpp` 全部一致。生成器在 `../../verify.js` 的 SPEC 里。

| $i$ | $p_i$ | 窗口 $[i-d, i-1]$ | 合法前驱（$p_j < p_i$） | $f[i]$ | $g[i]$ |
| --- | --- | --- | --- | --- | --- |
| 1 | 3 | 空 | 无 | 1 | 1 |
| 2 | 1 | $[1]$ | 无（$3 > 1$） | 1 | 1 |

| 4 | 1 | $[2,3]$ | 无 | 1 | 1 |

## 讲解代码

完整逐段注释版见 [`solution.cpp`](./solution.cpp)，关键片段：

```cpp
for (int i = 1; i <= n; i++) {
    f[i] = 1; g[i] = 1;                              // 只选第 i 天：长度 1，方案 1
    for (int j = max(1, i - d); j < i; j++) {
        if (p[j] >= p[i]) continue;                  // 严格上升：相等必须跳过
        if (f[j] + 1 > f[i]) { f[i] = f[j] + 1; g[i] = g[j]; }        // 更长 ⇒ 覆盖
        else if (f[j] + 1 == f[i]) { g[i] += g[j]; if (g[i] >= MOD) g[i] -= MOD; }  // 相等 ⇒ 累加
    }
    if (f[i] > best) { best = f[i]; cnt = g[i]; }
    else if (f[i] == best) { cnt += g[i]; if (cnt >= MOD) cnt -= MOD; }
}
```

## 易错点与坑

- **`>` 写成 `>=`**：题面是**严格**上升。$p = 1,1,2,2,3$ 若允许相等，样例 2 的长度会变成 5，直接暴露。
- **`g[i] = g[j]` 与 `g[i] += g[j]` 混用**：见观察 D。两处都写成"覆盖"，本机实测样例 2 输出 `3 1`（正确值 `3 4`），样例 1、3 恰好只有 1 种方案所以看不出问题——这正是要拿样例 2 查计数的原因。
- **忘写 `g[i] = 1` 初值**：长度为 1 的方案（只选自己）也是方案，$n = 4, p \equiv 2$ 时答案是 `1 4`，缺初值会输出 `1 0`。
- **窗口左端点没夹住 1**：`max(1, i - d)`，$i \le d$ 时 $i - d \le 0$，直接当下标就是越界读。
- **$d$ 可能大于 $n$**：$d \le 5000$、$n \le 5000$ 互相独立，$d \ge n$ 时窗口自动退化成"左边全部"，代码不用特判，但别写 `i - d` 到 `int` 下溢。
- **最后统计方案数时把短方案也加进去**：只有 $f[i] == \text{best}$ 的 $g[i]$ 能加。$n = 5000$ 全相等时 best=1，5000 个 $g$ 全要加 ⇒ `1 5000`（本机实测）。
- **取模时机**：$g$ 是指数级增长的计数，必须每次加法后取模；`cnt` 也要。用 `int` 存 $g$ 时先加后判 `>= MOD` 是安全的（两个 $< 10^9$ 的数相加不超 $2 \times 10^9$，仍在 `int` 范围内），换成 $2 \cdot 10^9$ 级别的模数就要 `long long`。
- **想优化到 $O(n\log n)$**：加"窗口 ≤ d"后普通 LIS 的贪心+二分不再适用（要维护"长度 → 最小价格"还要按窗口滑动删除），考场写 $O(nd)$ 拿满本题 5000 规模即可。

## 一句话提炼（板书）

**带窗口的上升子序列计数：f[i] 只管"以 i 结尾最长多长"，g[i] 只管"这么长的有几种"；转移时更长就覆盖方案数、一样长就累加方案数，最后只把 f[i] 等于全局最大的那些 g[i] 加起来。**
