## 题目大意

给一个只含**非负整数、`+`、`*`、`(`、`)`** 的合法公式（长度 ≤ $10^5$），求两件事：

1. 公式的值，**每一步运算都模 998244353**（中间结果也模，不只最后模）；
2. 括号的**最大嵌套深度**（最多几层左括号套在一起）。

- 输入：一行字符串，无空格，公式保证合法，每个数字 ≤ $10^9$
- 输出：第一行值，第二行最大深度
- 术语：**栈**是一种"只准从最上面放、最上面取"的容器（后进先出，LIFO），本机的 `std::vector` 用 `push_back` / `back` / `pop_back` 就能当栈用。

本机实测（`g++ -static -O2 -std=c++14 solution.cpp -o /tmp/s4t3.exe`，stdin 重定向喂数据；`brute.cpp` 是递归下降写法）：

| 输入 | 期望 | `solution.cpp`（双栈） | `brute.cpp`（递归下降） |
| --- | --- | --- | --- |
| `1+2*3` | 7 / 0 | `7` `0` | `7` `0` |
| `(1+2)*3` | 9 / 1 | `9` `1` | `9` `1` |
| `((1+2)*(3+4))*2` | 42 / 2 | `42` `2` | `42` `2` |
| `1+(2+3*(4+(5+6)))*7` | 330 / 3 | `330` `3` | `330` `3` |
| `999999999` | 单数字也要取模 | `1755646` `0` | `1755646` `0` |
| `999999999+999999999` | 加法也要模 | `3511292` `0` | 同 |
| `1000000000*1000000000` | 乘法先模再乘 | `716070898` `0` | 同 |

## 思路推导

### 1. 暴力想法与瓶颈

最 naive 的想法是"从左往右顺手算"：`1+2*3` 先算 $1+2=3$ 再算 $3*3=9$。**错**，因为 `*` 优先级更高，正确答案是 7。瓶颈是：**看到 `+` 的那一刻，你还不知道它右边是一个乘积还是一个数**，必须先往后看。

另一种"暴力"是把整棵运算树先建出来再算，但 $|s| = 10^5$，建树本身也要一套解析规则，绕不开同一个问题。

### 2. 关键观察

- **观察 A（优先级 = 谁先出栈）**：`*` 比 `+` 急。扫到一个新运算符 $c$ 时，栈顶凡是优先级 ≥ $c$ 的运算符都可以立刻结算——因为它们左边的两个操作数已经全部读完了。这就是**调度场算法**（Dijkstra 发明的"两个栈读一遍"）。
- **观察 B（括号 = 强制出栈到某个标记）**：`(` 入栈当**墙**；遇到 `)` 就一直结算到碰到这堵墙，把墙弹出。于是"括号优先"不需要任何特殊比较逻辑。
- **观察 C（深度就是 `(` 的前缀计数）**：扫串时 `(` 让当前层数 +1、`)` 让 -1，取最大值即答案。这一问**根本不需要解析**，一遍计数就够（`brute.cpp` 就是这么做的）。
- **观察 D（递归下降是"免费的栈"）**：把优先级写成文法
  $$E \to T\ (+\ T)^*, \qquad T \to F\ (*\ F)^*, \qquad F \to \texttt{num}\ |\ (\ E\ )$$
  三个函数互相调用，调用栈天然就是那个"栈"。代码短、好学，但**深度靠系统栈**：本机实测 `brute.cpp` 在嵌套 8000 层还能算（输出 `1 / 8000`），**10000 层直接崩掉**（没有任何输出，Windows 状态码 `0xC00000FD`＝栈溢出；在 Git Bash 里看到的会是另一个数字），而双栈版 `solution.cpp` 跑 49999 层嵌套（$|s| = 99999$）只用 **0.017 s**、输出 `1` 和 `49999`。
- **观察 E（取模是同余环上的运算）**：$(a+b) \bmod m$ 与 $(a \bmod m + b \bmod m) \bmod m$ 相等，乘法同理，所以"每步都模"不改变最终结果；数字本身也要边读边模（`x = (x*10 + d) % MOD`），因为题面虽说数字 ≤ $10^9$，但写法上不留隐患。

### 3. 算法设计（双栈版，即 `solution.cpp`）

维护 `val`（数字栈）与 `op`（运算符栈），`prec('+')=1`、`prec('*')=2`：

1. 逐字符扫，`i` 只在"不是数字"时自增（数字要一次吃掉一整段）。
2. **数字**：连续读 digits，边读边 `% MOD`，压入 `val`。
3. **`(`**：压入 `op`，`now++`，`depth = max(depth, now)`。
4. **`)`**：`while (op.back() != '(') apply();` 然后弹出 `(`，`now--`。
5. **`+` / `*`**：`while (op 非空 且 栈顶不是 '(' 且 prec(栈顶) >= prec(c)) apply();` 然后把 $c$ 压入。
6. 扫完把 `op` 里剩下的全部 `apply()`，`val.back()` 即答案。

`apply()`：弹出两个数 $a, b$ 和一个运算符，算 $(a+b) \bmod M$ 或 $a \cdot b \bmod M$ 压回。注意**先弹的是右操作数**。

### 4. 正确性说明

**引理 1（不变式）**：任意时刻，`op` 栈里从底到顶优先级**严格递增**，且 `val` 栈里从底到顶是"已经算完的段"。
证明：只有第 5 步会压运算符，压之前把所有 ≥ 自己的栈顶都结算掉了，所以压进来后栈顶仍 < 自己；`(` 视为优先级 $-\infty$（代码里用 `op.back() != '('` 挡住），不会误结算括号外的内容。$\blacksquare$

**引理 2（结算时机正确）**：`apply()` 弹出时，栈顶的两个数正是该运算符的左右操作数。因为由引理 1，比它优先级高的都已经算完并压回成一个数；比它低的还没算，说明它在更外层括号或更靠左的位置，不影响它当前的两个操作数相邻。

**引理 3（括号处理正确）**：`)` 触发的循环把该括号内部**所有**运算符结算干净（栈里 `(` 以上的部分只属于这一层，因为 `(` 挡住了更外层的运算符），弹出 `(` 后这一层的值就是一个普通数字，等价于文法 $F \to (\ E\ )$。

**引理 4（深度正确）**：`now` 是已读前缀中未闭合的 `(` 个数，即当前嵌套层数；对每个前缀取 max 就是最大嵌套深度。

由引理 1—3，双栈版与文法 $E, T, F$ 的递归下降版（`brute.cpp`）产生同一棵表达式树，故两者输出一致——本机 5000 组随机表达式（最深 5 层嵌套、操作数取满 $10^9$、含 0）实测**两版一致**，抽查的几组也等于用大整数直接算出来再取模的结果。

### 5. 复杂度分析

- 时间：每个字符入栈常数次、每个运算符 `apply()` 一次，$O(|s|)$。本机实测 $|s| = 99999$ 的 `1+2+3+…` 长串（$1,2,\dots,7$ 循环相加 50000 项）**0.012 s**，输出 `199997`，与闭式 $\sum_{i=0}^{49999}(i \bmod 7 + 1) = 199997$ 一致；$2^{25000}$ 型长乘串（25000 个 `2` 相乘，$|s| = 49999$）**0.009 s**，输出 `48389869`，与大整数快速幂 $2^{25000} \bmod 998244353$ 一致。这两组都是用同一份 `solution.cpp` 编译后喂 stdin 跑出来的。
- 空间：`val` + `op` 最坏 $O(|s|)$。
- 递归下降版时间同样 $O(|s|)$，但**空间换成了系统栈**，深度 $10^5$ 时爆栈（见观察 D）。

## 讲解代码

完整逐段注释版见 [`solution.cpp`](./solution.cpp)，关键片段：

```cpp
void apply() {                       // 注意顺序：先弹出的是右操作数 b
    ll b = val.back(); val.pop_back();
    ll a = val.back(); val.pop_back();
    char c = op.back(); op.pop_back();
    if (c == '+') val.push_back((a + b) % MOD);
    else val.push_back(a * b % MOD);
}
if (c == '(') { op.push_back(c); now++; depth = max(depth, now); }
else if (c == ')') { while (op.back() != '(') apply(); op.pop_back(); now--; }
else { while (!op.empty() && op.back() != '(' && prec(op.back()) >= prec(c)) apply();  // 栈顶不比我低就先算
       op.push_back(c); }
```

## 易错点与坑

- **`apply()` 里 a、b 顺序反了**：减法除法会错；本题 $+,*$ 满足交换律，所以**样例测不出来**，一旦改成带 `-` 或 `/` 的变式立刻全错。
- **忘了 `op.back() != '('`**：会把括号外的运算符提前结算，`1+(2*3)` 这类会算错。
- **数字只读一位**：`while (isdigit(...))` 这段不能少，否则 `123` 被读成 `1`、`2`、`3` 三个数，结果变成 `1*2*3` 之类。
- **只在最后取模**：中间乘积会溢出。`a * b % MOD` 里 $a, b < 998244353$，乘积约 $9.96 \times 10^{17}$，`long long` 装得下（上限约 $9.22 \times 10^{18}$），但用 `int` 存就爆。
- **递归下降 + 深嵌套**：本机实测 10000 层括号就崩（`0xC00000FD` 栈溢出、无输出；双栈版 `solution.cpp` 的 49999 层安然无恙，0.017 s）。考场写递归下降要么先把嵌套深度限制住，要么改手工栈。
- **`i++` 的位置**：数字分支里 `i` 已经在 `while` 中走到下一个非数字，必须 `continue` 而不是再 `i++`，否则会跳过那个运算符。
- **深度别用 `op` 里 `(` 的个数现算**：扫完再数也行，但结算过程中 `(` 会被弹掉，所以要在**读入时**同步维护 `now`（或用 `brute.cpp` 那样单独扫一遍）。

## 一句话提炼（板书）

**表达式求值 = 两个栈读一遍：数字压值栈，运算符压符号栈；新运算符进来前，把栈里不比自己优先级低的先算掉，左括号当墙，右括号算到墙为止——优先级和括号就全解决了。**
