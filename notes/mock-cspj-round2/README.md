> **这不是任何一年的 CCF 真题。** 四套卷的题面、背景、数据全部自编，只是**知识点、题型结构、
> 数据规模、子任务给分方式**对齐 CSP-J 第二轮（2021—2025）。出题依据见
> [考情趋势分析](../cspj-trend-2021-2025.md)。

> `notes/mock-cspjs-round1/`。目录名前缀就是防混淆用的：`zhenti-` = 你提供的卷子，`mock-` = 我自己出的。

## 每套卷的赛制参数（照抄真题）

- 4 题 × 100 分 = 400 分，`1000ms / 512MB`。
- 每题 4—6 个子任务，按档给部分分——**这一栏是故意做成"读表就能抢分"的**，讲评时先带学生读子任务表。
- 程序文件名 / 输入文件名 / 输出文件名一栏和真题格式一致（如 `plate.cpp` / `plate.in` / `plate.out`）。

## 正确性是怎么保证的

题目文字只有 `problem.txt` 一份，其余全由脚本生成，所以"抄错题"不可能发生；
16 道题的解法则全部**编译运行 + 与独立写的暴力程序随机对拍**验证过：

```bash
node notes/mock-cspj-round2/verify.js all --rounds 5000 --perf   # 编译 + 样例 + 对拍 + 极限数据计时
node notes/mock-cspj-round2/verify/sheetshots.js set1 set2 set3 set4   # 逐页截图核对题面排版
node notes/mock-cspj-round2/verify/vizcheck.js set1 set2 set3 set4     # 可视化：狂点按钮查 NaN/报错/溢出
```

结果记录在 [`verify/RESULTS.md`](verify/RESULTS.md)：**合计 120 项检查，失败 0 项**，16 题**每题都是 5000 组随机对拍**（题解里出现的"对拍 N 组"就是这个数）。
`metadata` 意义上的状态是「对拍验证」，不是「AC」——模拟卷没有 OJ 可交。

## 已知边界

- **同一题的"极限数据耗时"在不同文档里可能不一样，这是正常的**，有两个原因：① **数据不同**——`verify/RESULTS.md` 用 `verify.js` 里固定种子的生成器，题解里如果另写一批数据，数字就对不上；② **冷热不同**——同一个 exe、同一份输入，本机在"刚编译完第一次跑"和"连着跑第五次"之间能从 5 ms 差到 50 ms（进程启动 + 杀软扫描），跟算法无关。所以这些计时只用来说**量级**，别当基准分数。现在各题解里凡引用极限量级的，都尽量改成 `verify.js` 那份生成器（写清种子），并对同一份输入再跑一次独立实现交叉核对：
  - set1 T1：771 408 个数字按桶重拼，逐字符与程序输出一致；
  - set2 T1：`Set` 去重与 `sort+unique` 两种写法都数到 631 932 种；
  - set4 T2：$N \le 20000$ 全量，"窗口 200"与"x 升序反推最小原像"两份实现对撞 0 处不符（窗口取 10 则 16909 处错，正好演示漏解）；
  - set4 T3：$|s| = 99999$ 长加串 = $\sum_{i<50000}(i \bmod 7 + 1) = 199997$，$2^{25000}$ 长乘串 = $48389869$，都由大整数单独算过。
- 本次 `--rounds 5000` 是命令行覆盖，`RESULTS.md` 页眉那行命令没带上这个参数（行里写的"对拍 5000 组"才是真实组数）；`verify.js` 已改成以后覆盖时会一并写进页眉。
- 第 1 套 T2 的可视化里 `n, m` 输入框限制到 12（网格画得下），题面本身允许到 30。
- 各题 `brute.cpp` 只为对拍而生，数组按小数据开（如 T4 的 `a[25]`、掩码用 `int`），**不能**当正解讲。
- 题面里的样例输出全部来自 `solution.cpp` 的真实运行结果，不是手算。
