题 16　n=20 会数组越界吗？　答案 T（本题 1 分）
f 声明成 int f[1 << N]，N=20 ⇒ 容量 1<<20 = 1048576，合法下标 0..1048575。程序里 i 最大取 (1<<n)−1 = 1048575 ⇒ 正好压线，不越界。a[20][20] 的下标 0..19 也刚好够用。
学生最爱怀疑的一处：__builtin_popcount(i)−1 在 i=0 时是 −1！但 i=0 时第 15 行 0>>j&1 全为假，第 16 行一次都不执行，所以 −1 这个下标永远不被使用（演示里就是开头 i=0 的那几帧"为假"判定）。实测 n=20 随机矩阵 exit=0。
题 17　"无论输入什么，输出都是正整数"？　答案 F
输出是对 998244353 取模之后的值，范围 0..998244352，取到 0 就不是正整数。
反例（点上面"题 17 反例"按钮逐帧看）：
n=2, A=[[1,1],[998244352,1]]
per(A) = 1·1 + 1·998244352 = 998244353 ≡ 0 ⇒ 输出 0。
另一组 [[1,119],[8388608,1]]：1 + 119×8388608 = 998244353 ≡ 0，同理。
判断题里出现"无论…都"这种全称命题 ⇒ 只需要一个反例；带 mod 的题里"能不能取到 0"永远是第一件要试的事。
题 18　删掉第 16 行的 1ll* 有没有影响？　答案 F
两个都可能接近 10⁹ 的数相乘 ≈ 10¹⁸，而 int 只有 2.1×10⁹。第 16~17 行的类型流动：
1ll * f[i ^ (1<<j)]      -> long long    (< 998244353)
      * a[|i|-1][j]        -> long long    乘积可达 9.96e17，64 位装得下
      % mod                -> long long    < 998244353
f[i] += ...                -> int   两边都 < mod，和 < 1.996e9 < 2^31，安全
       %= mod              -> int

去掉 1ll* 之后，第一步就变成 int * int  ->  32 位有符号溢出（UB），实际按 mod 2^32 回绕
本机实测：n=2,3 共 401 组随机矩阵里 277 组结果不同。最干净的一组：n=2 全 100000 ⇒ 正确 35112940；去掉 1ll* 得 823642110（100000×100000 = 10¹⁰ 回绕成 1410065408，再 % mod = 411821055，两列各一份相加）。
