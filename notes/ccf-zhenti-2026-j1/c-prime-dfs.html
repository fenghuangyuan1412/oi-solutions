  • 机器实测：ip3.exe 与 ip3_odd.exe 在 n = 2..100 上逐行 diff，完全相同（本机实跑，不一致 0 个），比题面要求的 n > 10 还宽。
  • 为什么必然相同：添上偶数位 d 得到的 x*10+d 个位是偶数，而它 ≥ 10，是大于 2 的偶数，一定是合数；原程序里它进到第 12 行 if (!check_prime(x)) return; 就当场 return，既不打印也不展开。把这些分支删掉，只是少算几步，一个字的输出都不会少。
  • 切换开关后，紫色虚线 ✗skip 节点就是"本来也会被第 ① 行 return"的那批：位置还留在树上，方便和原样模式一对一对比。
  • 等价性题的通用打法：先问"被删掉的分支能产出输出吗"，注定被 return 的分支删了等于没删。

⑨ 题 32：四个选项的实测判定（答案 D）

A. 输出的数一定按从小到大排列错 ×

反例（实测 n=3）：输出 23 29 3 5 7 —— 29 后面跟着更小的 3。DFS 先把 2 的分支钻到底（23、29），回到 main 才轮到 i=3、5、7。n=24 也一样：233、239 之后才冒出 29。选 n=3 或 n=24 自己看 ⑤ 的橙色行。

B. 随着 n 增大，输出行数一定不增加错 ×

反例（实测）：n=2 是 4 行，n=3 变成 5 行，反而变多。原因：n 一大，原本满足 x ≥ n 的一位质数不再够大，于是它们转而展开成两位、三位，每展开一层都可能多出打印点。

C. 输出数的个位只可能是 3 或 7错 ×

反例（实测 n=24 的输出）：239 29 31 59 71 79 —— 个位 9、1 都出现了。大质数的个位只能是 1/3/7/9 四个，C 把 1 和 9 漏掉了。

D. 每个 ≥10 的输出，删去末位后仍是质数对 √

结构性原因：能打印 x 说明它是由 search_result(前缀) 的第 18 行 x*10+i 生成的，而那个"前缀"在上层已经通过过一次 check_prime（第 12 行），否则走不到这一步。实测：ip3_optD.exe 把 n = 2..3000 的所有输出逐个"删末位再判质数"，反例 0 个。

⑩ 人话版：这段程序在算什么

  • check_prime(x)：标准的试除判质数，for (i = 2; i * i <= x; i++) if (x % i == 0) return false;，只试到平方根。
  • search_result(x) 三行骨架：① 第 12 行不是质数就 return；② 第 13-15 行是质数且 x ≥ n 就打印并 return；③ 第 17-18 行是质数但 x < n 就往末尾添 0~9 各试一次。
  • main 从 1~9 起步逐个调用，所以画面是 9 棵小树并排（本页一次画一棵）。
  • 教学核心：打印条件是"整条前缀链每一步都是质数"，比"这个数本身是质数"强得多。10~99 的两位质数有 21 个，可 n=10 时程序只印 9 个：十位不是质数的 11、13、17、19、41、43、47、61、67、83、89 全部到不了。
  • 另一条容易被忽略的剪枝：打印之后紧跟 return，所以 够大就停，不会把更大的后代一起印出来（n=24 时印 29 就停，290~299 根本不看）。
  • 做 DFS 阅读题第一件事：把每一个 return 标出来。本题有两个 return（合数、够大），少看任何一个，数出来的行数就不对。
