### 2.3 题 18 / 题 21（`src/ip1_scan.cpp` → `ip1_scan.exe`，耗时 4.6 s）

```
等价性核对 0..16777215：不一致 0 个
题18  0..16777215 中 x<y 的反例 0 个
题21  0..2^31-1 中 y==2 共 31 次
题20  n=6 -> 4 3
```

做法：先把卷面循环原样搬进 `paper(n,x,y)`，再在 0..2²⁴ 上逐个核对
"x = 二进制位数+1（n=0 时为 1）、y = popcount+1"这个等价式，**0 个不一致**；
核对通过后才用等价式在 0..2³¹−1 全范围统计（否则 21 亿次 × 31 层循环跑不完）。
题 18 直接在 0..2²⁴ 上用原循环逐个查反例。

### 2.4 题 19：`while (n > 0)` 改成 `while (n >= 0)`（`src/ip1_ge0.cpp`）

```
n=0     -> （3 秒无任何输出）[退出码 124]
n=3     -> （3 秒无任何输出）[退出码 124]
```

退出码 124 是 `timeout` 杀掉的返回值 —— 程序根本不结束，就是选项 A 说的"陷入死循环"。
原因：`n` 变成 0 以后 `0 >= 0` 仍为真，而 `0 / 2` 还是 0。

### 5.1 卷面题干和代码对不上（照抄，不改）

卷面在完善程序 (1) 的代码前写的是：

> 以下程序按"逐位除以 n"的方法完成进制转换。请补全程序。

但代码（第 13—22 行）做的是**当前数 × (m·n) + x，再按 n 进位**，从头到尾没有一次除法把数拆开。
实测支持代码而不是支持这句话：把 ③ 填成 `b[j] / n`（D）才全对，
而"逐位除以 n"的写法根本不可能长成卷面那个 `for (j = len; j >= 1; j--) b[j] = ...` 的循环。
讲评时按代码讲，同时把这句话指出来，别让学生以为自己看错了。

### 5.2 逐步中间状态（`src/fill1_trace.cpp` → `fill1_trace.exe`）

README 里完善程序(1) 那张手推表的**每一个中间状态**都来自这里的真实输出，不是心算。
输入 `2 10 3` + `1 2 3`（n=2、m=10，把 **mn 进制 = 20 进制**下从高位到低位的 `1 2 3` 换成 2 进制）：

```
初始  len=1  b = 0   （按 n=2 位权读回 = 0）
--- 读入位 x=1（移位+放置，还没进位）
  移位后  len=2  b = 1 0   （按 n=2 位权读回 = 1）
  规格化  len=2  b = 1 0   （按 n=2 位权读回 = 1）
--- 读入位 x=2（移位+放置，还没进位）
  移位后  len=3  b = 2 10 0   （按 n=2 位权读回 = 22）
  规格化  len=5  b = 0 1 1 0 1   （按 n=2 位权读回 = 22）
--- 读入位 x=3（移位+放置，还没进位）
  移位后  len=6  b = 3 0 10 10 0 10   （按 n=2 位权读回 = 443）
  规格化  len=9  b = 1 1 0 1 1 1 0 1 1   （按 n=2 位权读回 = 443）
输出（高位到低位）：1 1 0 1 1 1 0 1 1
```

**这里纠正一个极易读错的地方**：A 是 **mn 进制**（= 20 进制）的数，不是十进制。
"1 2 3"在 20 进制下 = 1×400 + 2×20 + 3 = **443**，二进制 `110111011`，程序输出的正是这 9 位。
读回值那一列（1 → 22 → 443）恰好是 Horner 式 `v = v*(mn) + x` 的三步，
说明"整体左移一格（= ×n）+ 每格乘 m（= ×m）"确实等价于 ×(mn)。

第二组交叉验证：输入 `2 8 2` + `1 10`（16 进制的 1A = 26）→ 输出 `1 1 0 1 0`，
即 26 的二进制 `11010` ✓。
