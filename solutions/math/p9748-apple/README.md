## 题目大意

$n$ 个苹果排成一列，编号 $1 \sim n$。每天小苞从**最左边第 1 个**开始、**每隔 2 个拿走 1 个**（也就是拿走当前第 $1, 4, 7, \dots$ 个，位置从 1 起算），拿完把剩下的苹果按原顺序重排。问：

1. 多少天能把苹果全部拿完？
2. 编号为 $n$ 的那个苹果是第几天被拿走的？

样例 `n = 8` ⇒ `5 5`：

| 天 | 拿之前（左→右） | 拿走 | 剩下 |
| --- | --- | --- | --- |
| 1 | 1 2 3 4 5 6 7 8 | 1, 4, 7 | 2 3 5 6 8 |
| 2 | 2 3 5 6 8 | 2, 6 | 3 5 8 |
| 3 | 3 5 8 | 3 | 5 8 |
| 4 | 5 8 | 5 | 8 |
| 5 | 8 | 8 | （空） |

编号 8 的苹果在第 5 天被拿走，共 5 天 ⇒ 输出 `5 5`。

## 一、骗分：这一档怎么拿

**先说结论**：这道题的骗分空间只有"模拟整列苹果"，因为 $n \le 10^9$ 一上来就把数组方案全堵死了。它的教学价值不在"骗多少分"，而在于**一次干净的"把模拟换成递推"的示范**。

### 骗分思路 1：直接模拟（拿小数据的分）

按题意老老实实模拟：开一个数组存当前从左到右的苹果编号，每天扫一遍，把下标 $0, 3, 6, \dots$ 的元素拿走，其余按序保留。

- **复杂度**：每天处理的元素数是 $n, \tfrac{2n}{3}, \tfrac{4n}{9}, \dots$，总和 $< 3n$，即 $O(n)$。
- **能拿多少**：$n \le 10^7$ 左右能过；$n = 10^9$ 时数组根本开不下（约 8 GB），必挂。
- **为什么值得先交**：它**一定能编译、一定能跑、不会 RE、样例一定对**。考场上前 20~40 分就是这样稳住的。

### 骗分思路 2：只处理特殊性质

题目给了一个特殊性质：**小苞第一天就取走编号为 $n$ 的苹果**。在这个性质下，第二问的答案直接是 $1$，只需要算第一问的天数。

- 这是"**特殊性质分档**"的典型用法（手册 T4）：把第二问写死成 $1$，第一问照常递推，这一档就稳了。
- 判断条件是 $(n-1) \bmod 3 = 0$（见下面正解的位置公式），一行 `if` 就能识别。

### 骗分思路 3：兜底输出（反面提醒）

有同学会想"不会做就输出 `n n` 或者样例答案"。**不要这么做**：

- 本题两问都是**精确值**，没有任何"蒙一个近似值"的空间；
- 而 `solution_partial.cpp` 的模拟版是**真能拿分**的——两者的成本差不多，效果差很多。
- 手册里的红线：**能跑对的暴力 > 跑不出的正解**。

## 二、正解：盯住两个数就够了

**核心观察：这道题根本不需要知道"哪些苹果还在"，只需要知道"还剩几个"和"目标排在第几"。**

### 第一问：多少天拿完

设当天还剩 $cnt$ 个苹果。被拿走的是第 $1, 4, 7, \dots$ 个，个数是

$$\left\lceil \frac{cnt}{3} \right\rceil = \left\lfloor \frac{cnt+2}{3} \right\rfloor$$

于是每天更新

$$cnt \leftarrow cnt - \left\lfloor \frac{cnt+2}{3} \right\rfloor = \left\lfloor \frac{2\,cnt}{3} \right\rfloor$$

每轮至少乘 $\tfrac{2}{3}$，所以 $O(\log n)$ 轮就归零。

### 第二问：编号 $n$ 的苹果第几天被拿走

设它当天排在第 $pos$ 位（从 1 起）。判断标准很简单：

- 若 $pos \equiv 1 \pmod 3$（即 $(pos-1) \bmod 3 = 0$），**这一天它正好落在"第 1、4、7…"这些位置上，被拿走**；
- 否则它今天安全，但它**前面**有 $pos-1$ 个苹果，其中被拿走的是第 $1, 4, 7, \dots \le pos-1$ 个，个数为

$$\left\lceil \frac{pos-1}{3} \right\rceil = \left\lfloor \frac{pos+1}{3} \right\rfloor$$

  所以它的新位置是

$$pos \leftarrow pos - \left\lfloor \frac{pos+1}{3} \right\rfloor$$

用样例 $n=8$ 走一遍：

| 天 | $pos$ | $(pos-1)\bmod 3$ | 结论 | 新 $pos$ |
| --- | --- | --- | --- | --- |
| 1 | 8 | 1 | 安全 | $8-\lfloor 9/3\rfloor = 5$ |
| 2 | 5 | 1 | 安全 | $5-\lfloor 6/3\rfloor = 3$ |
| 3 | 3 | 2 | 安全 | $3-\lfloor 4/3\rfloor = 2$ |
| 4 | 2 | 1 | 安全 | $2-\lfloor 3/3\rfloor = 1$ |
| 5 | **1** | **0** | **被拿走** | — |

答案第 5 天 ✓

### 两问其实是同一个循环

注意两问都是"$x \leftarrow x - \lceil x/3\rceil$"形式的递推，只是**判停条件不同**：第一问是 $cnt = 0$，第二问是 $pos \equiv 1 \pmod 3$。这就是为什么代码只有十行。

## 三、正确性说明

**引理 1（数量递推）**：当天剩 $cnt$ 个苹果时，被拿走 $\lceil cnt/3 \rceil$ 个。

*证明*：被拿走的编号是 $1, 4, 7, \dots, 3k+1$，要求 $3k+1 \le cnt$，即 $k \le (cnt-1)/3$，故 $k$ 的个数是 $\lfloor (cnt-1)/3 \rfloor + 1 = \lceil cnt/3 \rceil$。$\blacksquare$

**引理 2（位置递推）**：$pos$ 位置的苹果，若 $pos \not\equiv 1 \pmod 3$，则它前面有 $\lfloor (pos+1)/3 \rfloor$ 个苹果被拿走。

*证明*：它前面有 $pos - 1$ 个苹果，其中被拿走的编号是 $1, 4, \dots \le pos-1$。当 $pos \not\equiv 1 \pmod 3$ 时，最大的那个 $\le pos-1$ 的 $3k+1$ 是 $3\lfloor (pos-1)/3 \rfloor + 1$，个数为 $\lfloor (pos-1)/3 \rfloor + 1 = \lfloor (pos+1)/3 \rfloor$。$\blacksquare$

**定理**：两个循环分别给出总天数和编号 $n$ 被拿走的天数。

*证明*：由引理 1，第一问每轮精确减少 $\lceil cnt/3 \rceil$ 个，$cnt=0$ 时的轮数即总天数。由引理 2，第二问每轮把 $pos$ 精确更新为新位置，一旦 $pos \equiv 1 \pmod 3$ 即命中，故轮数即天数。$\blacksquare$

**复杂度**：两个循环各自 $O(\log n)$，空间 $O(1)$。

## 五、讲解代码

### 正解（`solution.cpp`，$O(\log n)$）

```cpp
long long n;  cin >> n;

long long cnt = n, days = 0;            // ① 多少天拿完
while (cnt > 0) {
    cnt -= (cnt + 2) / 3;               // 拿走 ceil(cnt/3) 个
    ++days;
}

long long pos = n, day = 0;             // ② 编号 n 第几天被拿走
while (true) {
    ++day;
    if ((pos - 1) % 3 == 0) break;      // 它正好落在「第 1、4、7…」位置上
    pos -= (pos + 1) / 3;               // 前面被拿走 (pos+1)/3 个
}

cout << days << " " << day << "\n";
```

### 骗分版（`solution_partial.cpp`，$O(n)$ 模拟）

```cpp
vector<long long> cur(n);
for (long long i = 0; i < n; ++i) cur[i] = i + 1;   // 当前从左到右的编号

long long days = 0, dayOfN = -1;
while (!cur.empty()) {
    ++days;
    vector<long long> nxt;
    for (size_t i = 0; i < cur.size(); ++i) {
        if (i % 3 == 0) {                           // 第 1、4、7… 个被拿走
            if (cur[i] == n) dayOfN = days;
        } else nxt.push_back(cur[i]);
    }
    cur.swap(nxt);
}
cout << days << " " << dayOfN << "\n";
```

两份代码在本机对拍 **200 组 0 不一致**（$n \le 4000$），互为验证。

## 六、易错点与坑

1. **把"每隔 2 个"读成"每 3 个里拿最后 1 个"**：题面是"从左侧第 1 个开始、每隔 2 个拿走 1 个"，即拿 $1, 4, 7, \dots$（**不是** $3, 6, 9, \dots$）。读错这一条，样例 1 就会算出 `4 4` 之类的错答案。
2. **模拟版开 `vector` 时用 `int`**：$n$ 到 $10^9$ 时下标已经越界。虽然模拟版本来就过不了大数据，但**至少别让它 RE**——`long long` 更保险。
3. **第二问忘了"位置会变"**：不能只算一次 $(n-1) \bmod 3$ 就下结论。$pos$ 每天都在变小，要一直递推到命中为止。
4. **用 `ceil(cnt/3.0)` 走浮点**：$cnt$ 到 $10^9$ 时浮点仍然精确（双精度能表示到 $2^{53}$），但这是**运气**。养成用整数写法的习惯：`ceil(a/b) = (a+b-1)/b`。
5. **循环写成 `while (cnt)` 但忘了更新 `cnt`**：会死循环。递推题的调试第一件事就是打印每轮的变量。

## 七、常见变式

| 变式 | 差异 | 备注 |
| --- | --- | --- |
| 每隔 $k$ 个拿 1 个 | 把 3 换成 $k+1$，递推式不变 | 复杂度仍是 $O(\log n)$ |
| 求编号为 $x$ 的苹果（而非 $n$） | 起始 $pos = x$，其余完全相同 | 直接复用 |
| 求第 $t$ 天时还剩几个 | 递推 $t$ 轮即可 | $t$ 大时仍要递推，不能直接算 |
| 反向问：第几天时剩 $m$ 个 | 二分天数 + 递推判定 | 递推单调，可二分 |

## 八、一句话提炼

**"还剩几个"和"目标排第几"是两个只靠递推就能维护的量**——当模拟的对象是一整列元素、而题目只问一个计数和一个位置时，就该问自己：**我真的需要知道每一列里是谁吗？** 这道题用十行代码把 $O(n)$ 的模拟压成 $O(\log n)$ 的递推，是"**把模拟换成计数**"最干净的一次示范。
