## 题目大意

题面关键原文（逐字，完整版见 [`problem.txt`](problem.txt)）：

> 排列与组合是常用的数学方法，其中组合就是从 $n$ 个元素中抽出 $r$ 个元素（不分顺序且 $r \le n$），我们可以简单地将 $n$ 个元素理解为自然数 $1,2,\dots,n$，从中任取 $r$ 个数。现要求你输出所有组合。
> 例如 $n=5,r=3$，所有组合为：$123,124,125,134,135,145,234,235,245,345$。
>
> 输出格式：所有的组合，每一个组合占一行且其中的元素按由小到大的顺序排列，每个元素占三个字符的位置，所有的组合也按字典顺序。
>
> **注意哦！输出时，每个数字需要 $3$ 个场宽。** 以 C++ 为例，你可以使用 `cout << setw(3) << x;`，注意你需要头文件 `iomanip`。

用自己的话说：

- **输入**：$n$ 和 $r$。
- **要算**：从 $1..n$ 里挑 $r$ 个数（**不看顺序**），把每一种挑法一行一个打出来。
- **三条格式要求**：① 行内元素**从小到大**排；② 各行之间按**字典序**；③ 每个元素占 **3 个字符宽**。

$n=5,r=3$ 共 $\binom{5}{3}=10$ 种；题面上限 $n=20$ 时最多 $\binom{20}{10}=184\,756$ 种。

## 思路推导

### 1. 直觉想法：把 P1706 的代码搬过来改一改？

刚讲完全排列，最省力的想法是"照抄再加个条件"：

```cpp
// 抄排列：每层从 1 试到 n，用 vis[] 去重，选够 r 个就输出
for (int x = 1; x <= n; x++) { if (vis[x]) continue; ... }
```

问题是：排列把 `1 2 3`、`1 3 2`、`2 1 3`……$3!=6$ 个顺序都当成不同答案，而组合只要 `1 2 3` 一个。
本机把这份"排列写法"真编出来跑 $n=5,r=3$：**输出 60 行**（$=P(5,3)$），是正确答案 10 行的 6 倍 —— 多出来的全是重复的换序。

那怎么只留一个？给序列加一条规定：**组合里的数必须越往后越大**。加上这条约束，每种挑法只剩唯一一种写法（升序那种），而且它恰好就是题面要的"元素按由小到大排列"。

### 2. 关键观察：把"每层的候选起点"设为"上一个数 + 1"

一句话就够了：

> **第 $d$ 个数一旦取了 $x$，第 $d+1$ 个数就只能从 $x+1$ 开始试。**

于是 DFS 签名变成 `dfs(start, dep)`：`start` = 本层允许出现的最小数，`dep` = 已经选了几个。

| | 排列 P1706 | 组合 P1157 |
| --- | --- | --- |
| 每层循环 | `for (x = 1; x <= n; x++)` **每层都从 1** | `for (x = start; x <= n; x++)` **从上一个数 + 1** |
| 去重靠什么 | `vis[]` 数组 | 靠"只能往后走"，**不需要 `vis[]`** |
| 递归传什么 | `dfs(d + 1)` | `dfs(x + 1, dep + 1)` |
| 撤销什么 | `vis[x] = false`（必须！） | 只改了 `a[dep]`，下一轮循环会覆盖，**无可撤销** |
| 输出条数 | $n!$ | $\binom{n}{r}$ |
| 字典序 | 每层升序枚举 ⇒ 天然有序 | 同上，且行内自动升序 |

"起点单调递增"这一条同时解决了三件事：**不重复**（同一个数不可能被选两次，因为选完就只准往大走）、**行内升序**（题面要求①）、**行间字典序**（要求②，还是因为每层按 $x$ 从小到大、走完一棵子树才回头）。

回溯三句话在这一版里变成：

| 步骤 | 代码 | 说明 |
| --- | --- | --- |
| 做了什么 | `a[dep] = x;` | 第 dep 个数取 $x$（**只有这一句**，没有 `vis` 要登记） |
| 往下递归 | `dfs(x + 1, dep + 1);` | 传下去的起点是 $x+1$ —— 这是本题的全部灵魂 |
| 撤销什么 | （无） | 递归返回后 `a[dep]` 会被下一轮循环直接覆盖；参数 `start` 是局部的，返回即失效 |

**组合比排列"省心"，但省心的地方恰恰是最容易写错的地方**：忘写 `x + 1` 里的 `+1`，程序照样跑得欢，只是答案少一批（见"易错点"第 1 条的实测数字）。

### 3. 算法设计（伪代码）

```
dfs(start, dep):                      # start：本层可用的最小数；dep：已选了几个
    if dep == r: 输出 a[0..r-1]（每元素 3 场宽）; return
    for x = start .. n:
        a[dep] = x
        dfs(x + 1, dep + 1)           # 只能选比 x 大的
```

初始调用 `dfs(1, 0)`。

### 4. 正确性论证

- **不重**：任一输出行满足 $a[0]<a[1]<\cdots<a[r-1]$（由传参 $x+1$ 归纳）。若两种不同路径输出同一集合 $S$，取 $S$ 的升序排列，它对应唯一的一条路径（第 $d$ 步必须恰好选升序第 $d$ 个元素），故不可能出现两次。
- **不漏**：任给一个 $r$ 元子集 $S$，把它排序成 $s_1<\cdots<s_r$。第 0 层循环从 1 到 $n$ 必经过 $s_1$；进入后下一层起点是 $s_1+1 \le s_2$，循环必经过 $s_2$……归纳到底，这条路径存在，所以 $S$ 一定被输出。
- **行内升序 / 行间字典序**：见 §2 末段。字典序的论证与 P1706 相同 —— DFS 把"本层取较小 $x$"的整棵子树走完后才试下一个 $x$，故输出顺序就是字典序。
- **边界**：$r = 0$ 时 `dfs(1,0)` 第一句就命中边界，输出 1 个空行 —— 对应"空集唯一一个"，本机实测确实输出 `"\n"`（见验证结论）。$r = n$ 时只有 $\binom{n}{n}=1$ 个组合，程序输出 1 行 $1\;2\;\cdots\;n$。

### 5. 复杂度

- 输出行数 $\binom{n}{r}$，每行 $r$ 个元素 ⇒ 时间下限 $\Theta(r\binom{n}{r})$。
- 递归结点（`dfs` 调用次数）$=\sum_{d=0}^{r}\binom{n}{d}$：深度 $d$ 的结点恰好对应一个长度为 $d$ 的升序序列。本机实测两处校验：$n=5,r=3$ 调用 **26** 次，$\sum_{d=0}^{3}\binom{5}{d}=1+5+10+10=26$ ✅；$n=20,r=10$ 调用 **616666** 次，$\sum_{d=0}^{10}\binom{20}{d}=(2^{20}+\binom{20}{10})/2=616666$ ✅。
- 最坏在 $r \approx n/2$：$\binom{20}{10}=184756$ 行、约 $6\times10^5$ 次调用，瞬间完成（实测 92~118 ms，其中大部分是 5.7MB 输出的写出时间）。
- 空间 $O(n)$。

## 板书演示（$n = 5, r = 3$，官方样例）

下表是**把带打印语句的同一份 DFS 实际跑出来的调用顺序**（`#` = 第几次进入 `dfs`），最后一列是我在黑板上要圈出来的点：

| # | 调用 | 已选前缀 | 动作 |
| --- | --- | --- | --- |
| 1 | `dfs(1, 0)` | — | 第 1 个数可以从 1 开始试 |
| 2 | `dfs(2, 1)` | `[1]` | 取 1，下一个从 2 起 |
| 3 | `dfs(3, 2)` | `[1,2]` | 再取 2，下一个从 3 起 |
| 4 | `dfs(4, 3)` | `[1,2,3]` | **→ 输出第 1 个组合 `1 2 3`**（`dep==r` 命中边界） |
| 5 | `dfs(5, 3)` | `[1,2,4]` | **→ 输出 `1 2 4`** |
| 6 | `dfs(6, 3)` | `[1,2,5]` | **→ 输出 `1 2 5`**（注意 `start=6 > n=5`，但 `dep==r` 先命中，照样输出） |
| 7 | `dfs(4, 2)` | `[1,3]` | 回到第 2 个数：取 3，起点 $3+1=4$ |
| 8 | `dfs(5, 3)` | `[1,3,4]` | **→ 输出 `1 3 4`** |
| 9 | `dfs(6, 3)` | `[1,3,5]` | **→ 输出 `1 3 5`** |
| 10 | `dfs(5, 2)` | `[1,4]` | |
| 11 | `dfs(6, 3)` | `[1,4,5]` | **→ 输出 `1 4 5`** |
| 12 | `dfs(6, 2)` | `[1,5]` | ⚠ **死路**：`dep=2 < r=3`，但循环 `for (x = 6; x <= 5; ...)` 一次都不进，直接返回 —— 这个分支白走 |
| 13–19 | `dfs(3,1)` 展开 `[2]` 这一支 | `[2] …` | 依次输出 `2 3 4`、`2 3 5`、`2 4 5`，中间同样有 `dfs(6,2)` 死路 |
| 20–23 | `dfs(4,1)` 展开 `[3]` 这一支 | `[3] …` | 输出 `3 4 5`；`dfs(6,2)` 死路 |
| 24–26 | `dfs(5, 1)` → `dfs(6, 2)` → `dfs(6, 1)` | `[4]` / `[4,5]` / `[5]` | ⚠ 后两个都是**死路**：`[4,5]` 只差一个数但起点 6 已越界；`[5]` 之后干脆没数可取 |

实测汇总：**`dfs` 被调用 26 次，其中 10 次命中边界输出组合（$=\binom{5}{3}$），5 次是 `start > n` 而 `dep < r` 的空转分支（实测编号 #12 `[1,5]`、#19 `[2,5]`、#23 `[3,5]`、#25 `[4,5]`、#26 `[5]`）**，其余 11 次是正常的内部结点。输出 10 行：

```
  1  2  3      1  2  4      1  2  5      1  3  4      1  3  5
  1  4  5      2  3  4      2  3  5      2  4  5      3  4  5
```

与官方样例**逐字一致**（每元素 3 场宽、行末无空格）。

那 5 次空转分支就是"剪枝"要砍的东西：把循环上界从 `x <= n` 改成 `x <= n - (r - dep) + 1`（"剩下的数刚好够凑满 $r$ 个"），本机实测调用次数从 **26 → 20**；在 $n=20,r=10$ 上是 **616666 → 352716**（省 43%）。**注意那个 `+1` 不能少**，少了它反而会漏答案，见"易错点"第 2 条的实测。

## 讲解代码

完整逐段注释见 [`solution.cpp`](solution.cpp)，核心 10 行：

```cpp
void dfs(int start, int dep) {
    if (dep == r) {                                            // 选够 r 个就是一个组合
        for (int i = 0; i < r; i++) cout << setw(3) << a[i];    // 每元素 3 场宽，行末不多打空格
        cout << '\n';
        return;
    }
    for (int x = start; x <= n; x++) {                         // 从"上一个数 + 1"起：组合的全部秘密
        a[dep] = x;                                             // ① 做了什么
        dfs(x + 1, dep + 1);                                    // ② 往下递归（传 x+1，不是 start）
        // ③ 撤销什么：没有 vis 要还原，a[dep] 下一轮被覆盖
    }
}
```

## 易错点与坑

1. **下一层起点写成 `x`（漏 `+1`）** —— 最阴的坑。程序**不会报错、不会死循环**，只是同一个数被允许再用一次：实测 $n=5,r=3$ 输出 **35 行**（正确 10 行），多出来的是 `1 1 1`、`1 1 2` 这类"重复元素组合"。
   检查方法：数行数，必须等于 $\binom{n}{r}$；或看第一行是不是 `1 2 3`（如果是 `1 1 1` 就中招了）。
2. **剪枝上界的 `+1` 不能少** —— `for (x = start; x <= n - (r - dep) + 1; x++)` 里那个 `+1` 表示"最后一个位置可以取到 $n$"。
   实测少写 `+1` 的后果是**永远选不到最大的那个数**：$n=5,r=3$ 只剩 4 行（全是含不到 5 的），$n=20,r=10$ 剩 92378 行 —— 这个数恰好等于 $\binom{19}{10}$，也就是"从 $1..19$ 里选 10 个"，把 bug 的数学后果算得明明白白。
   **不剪枝也能过（$n<21$ 时 616666 次调用完全来得及），所以初学阶段建议先写 `x <= n`，等对拍无误再考虑剪枝。**
3. **把组合写成排列** —— 每层都从 1 试、用 `vis[]` 去重，实测 $n=5,r=3$ 输出 60 行（$P(5,3)$），而且顺序也不对（第 4 行 `1 3 2`）。反过来把排列写成组合（$r=n$）就只剩 1 行。**"要不要 `vis[]`" 是这两种题型的分界线**，做题前先问自己：$\{1,2,3\}$ 和 $\{3,2,1\}$ 算不算同一种？
4. **`setw(3)` 忘了 `#include <iomanip>`** —— 题面专门用一自然段提醒了，还是在编译期挂：实测错误原文 `error: 'setw' was not declared in this scope`，附带 note `did you forget to '#include <iomanip>'?`。
5. **场宽 / 行末空格** —— 每个元素必须是 **3 个字符宽**（`  1` 而不是 `1`），所以 $r=3$ 的一行长度恰好 9 字符。自己 `cout << a[i] << ' '` 手拼空格会得到宽度不对的输出；在行尾多打一个空格也不符合"逐字"要求（本地无法验证洛谷 checker 的宽容度，所以按题面逐字最稳）。
6. **$r = 0$ 的边界** —— 我的程序输出**一个空行**（`"\n"`，参照实现也是 1 个空组合），因为"从 $n$ 个里选 0 个"有一种方案（空集）。如果评测数据出现 $r=0$ 而期望是"什么都不输出"，就要在这里加分支；题面写 $0 \le r \le n$ 但本机没有洛谷的判定环境，**这一点只能提醒学生注意，不能替洛谷下结论**。
7. **$n$ 与 $r$ 的读入顺序** —— 题面第一行是 `n r`，写成 `cin >> r >> n` 会立刻全错（$n=5,r=3$ 变成 $n=3,r=5$，实测输出 0 行）。

| [P1036 选数](../p1036-choose-prime/) | 组合之上加"和为素数"判定 | 同一模板，`sum` 当参数带走，命中边界时判一次 |
| 可重复元素的组合（$n$ 个数里可重复选 $r$ 个） | 就是上面误写②的语义 | 下一层传 `x`（不 `+1`），实测 $n=5,r=3$ 得 35 行 $=\binom{n+r-1}{r}$ |
| 组合数只问"多少种" | 不用输出方案 | $\binom{n}{r}$ 递推 $f[i][j]=f[i-1][j]+f[i-1][j-1]$，$O(nr)$ |
| 元素本身有重复值（如 `1 1 2 3` 选 3 个） | 值相同要跳过 | 排序后在同一层里 `if (x == 上一个尝试值) continue;` |
| 位掩码写法 | $n \le 20$ 时可枚举 $2^n$ 个子集 | 能算个数，但**顺序不是字典序**（实测见验证结论），要额外排序 |

## 一句话提炼

> **组合 DFS 只有一处灵魂：下一层的起点是"上一个数 + 1"（`dfs(x + 1, dep + 1)`），于是自动不重复、行内自动升序、行间自动字典序；排列才需要 `vis[]`。**
