## 题目大意

题面关键原文（逐字，完整版见 [`problem.txt`](problem.txt)）：

> 已知 $n$ 个整数 $x_1,x_2,\cdots,x_n$，以及 $1$ 个整数 $k$（$k<n$）。从 $n$ 个整数中任选 $k$ 个整数相加，可分别得到一系列的和。例如当 $n=4$，$k=3$，$4$ 个整数分别为 $3,7,12,19$ 时，可得全部的组合与它们的和为：$3+7+12=22$、$3+7+19=29$、$7+12+19=38$、$3+12+19=34$。现在，要求你计算出和为素数共有多少种。

用自己的话说：

- **输入**：$n$、$k$，再一行 $n$ 个数。
- **要算**：所有"任取 $k$ 个相加"的取法里，**和是素数**的有几种。
- **输出**：一个整数（种数），没有格式陷阱 —— 输出只一个数，场宽之类的坑这道题没有。

三个必须掰清的概念：

1. **是组合不是排列**：$3+7+12$ 和 $12+3+7$ 是同一种选法（题面例子里 4 个数取 3 个，只列了 $\binom{4}{3}=4$ 种，没列 $4\times3\times2=24$ 种）。
2. **按"选法"计数，不按"和的值"去重**：如果有两种不同的取法得到同一个素数和，要算 2 种。
   本机实测：$n=4,k=2$、$x = 1\;1\;1\;1$ ⇒ 6 种取法的和全是 2（素数），程序输出 **6**，不是 1。
3. **每个数最多用一次**，所以是"下标的组合"，不是"可重复取数的组合"。

## 思路推导

### 1. 直觉想法：$k$ 个 for 循环？

$n=4, k=3$ 时可以直接写三重循环，但 $k$ 是**输入变量**（最大 19），层数不固定，循环写不出来 ⇒ 必须递归。这就是 [P1706](../p1706-permutation/) 教过的那一课。

另一种更"暴力美学"的写法是**位掩码**：$n \le 20$ ⇒ 枚举 $0 \dots 2^{20}-1$ 这 $2^{20} \approx 1.05\times10^6$ 个数，每个数代表"哪些位置的数被选中"，数一下 1 的个数是不是 $k$。这个写法在本题**完全可行**（$10^6$ 级别），我的验算参照实现就是用它 —— 但讲课时它不适合当正解：它把"组合"这个概念藏进了二进制里，而且顺序也不是字典序（[P1157 的验证结论](../p1157-combination/)里实测过这点）。

### 2. 关键观察：这题是**两层**，一层都不要混

| 层 | 职责 | 用到的知识 |
| --- | --- | --- |
| 外层：枚举 | 把 $\binom{n}{k}$ 种取法**不重不漏**地走一遍 | P1157 的组合 DFS：下一层起点 = 上一个下标 + 1 |
| 内层：判定 | 给定一个和 $v$，回答"是不是素数" | 试除到 $\sqrt{v}$；$v < 2$ 直接否 |

分层的好处：写的时候互不干扰，查错的时候也知道该查哪一层。**"选法枚举错了"和"判素错了"是两个完全不同的 bug，不要混在一次调试里。**

### 3. "和"怎么带：当参数往下传，不要回头再累加

```cpp
void dfs(int start, int dep, long long sum)     // sum = 已选 dep 个数的和
    ...
    dfs(i + 1, dep + 1, sum + x[i]);            // 做选择 = 改传参
```

三点好处：① 命中 $\text{dep} == k$ 时和已经算好了，$O(1)$；
② `sum` 是**值传递**，递归返回时上一层的 `sum` 自动保持原样 ⇒ **回溯免费**，一个 `sum = sum - x[i]` 都不用写；
③ 顺手就能剪枝（如果题目要求最小/最大，可以带 `sum` 做 bound）。

这正是"组合题不需要 `vis[]`"的第二个好处：状态全在参数里，返回即恢复。

### 4. 素数判定：为什么试到 $\sqrt{v}$ 就够

若 $v$ 是合数，则 $v = a \times b$（$a, b > 1$）。若 $a$ 和 $b$ 都 $> \sqrt{v}$，则 $a b > v$，矛盾。
所以必有一个因子 $\le \sqrt{v}$ ⇒ **只要把 $2..\lfloor\sqrt v\rfloor$ 都试一遍，没找到因子就是素数**。

三个边界要写在黑板上：

- $v = 1$：**不是**素数（素数定义要求恰有两个正因子）。必须显式 `if (v < 2) return false;`。
- $v = 2$：进入 `for (i = 2; i*i <= 2; ...)`，$4 > 2$ ⇒ 循环一次都不进 ⇒ 返回 `true` ✅ 正确，不用特判。
- $v = 4$（完全平方数）：$i=2$ 时 $2\times 2 \le 4$ 成立 ⇒ 查到因子 ⇒ `false` ✅。**如果把条件写成 `i * i < v`，$4 < 4$ 不成立就跳过，4 会被判成素数**（实测见"易错点"第 3 条）。

判素里我写的是 `i * i <= v` 而不是 `i <= sqrt(v)`：后者每次比较都要调用浮点函数，精度抖动时边界上会错，而且慢。

### 5. 数据范围的账（讲课时要当场按计算器）

- 组合数上限：$\binom{20}{10} = 184\,756$（$k$ 接近 $n/2$ 时最多）。$k=19$ 只有 $\binom{20}{19}=20$ 种。
- 和的上限：$k \le 19$，$x_i \le 5\times10^6$ ⇒ $\text{sum} \le 19 \times 5\times10^6 = 9.5\times10^7$。
  `int` 上限约 $2.1\times10^9$ ⇒ **`int` 装得下**（这点要算给学生看，不要凭感觉上 `long long`）。
  但判素循环里的 $i^2$ 到 $9.7\times10^7$ 也还在 `int` 范围内 —— 一旦 $x_i$ 或 $k$ 变大（变式里常见 $10^9$），`int` 的 $i\times i$ 就会爆，所以**本代码统一用 `long long`，把"先算账再决定类型"的习惯留下来**。
- 判素单次成本：$\sqrt{9.5\times10^7} \approx 9747$ 次试除（本题写法是逐个整数试，不是只试素数）。
- 悲观上界 $184756 \times 9747 \approx 1.8\times10^9$ 次运算，看着吓人。**但实际远达不到**：随机和有一半是偶数（1 次试除就出局）、$1/3$ 被 3 整除……绝大多数和在小因子处就返回了。本机实测最耗时档 **458~514 ms**（时限 1500 ms），见下表。

## 板书演示（官方样例 $n=4,k=3$，$x = 3,7,12,19$）

下表**每一行都是把带打印语句的同一份 DFS 真跑出来的**（按 `dfs(0,0,0)` 的实际访问顺序），不是我手推的：

| 序 | 组合（按 $x$ 的**下标**取，$\text{start}$ 递增） | 和 | 判素过程（实测输出） | `ans` |
| --- | --- | --- | --- | --- |
| 1 | $\{3, 7, 12\}$（下标 0,1,2） | $22$ | $i=2$：$22\bmod 2 = 0$ ⇒ 第一个因子就是 2，立刻 `false` | 0 |
| 2 | $\{3, 7, 19\}$（下标 0,1,3） | $29$ | 试 $i=2,3,4,5$ 都非因子；$i=6$ 时 $6^2=36 > 29$ ⇒ 循环结束 ⇒ **素数** | **1** |
| 3 | $\{3, 12, 19\}$（下标 0,2,3） | $34$ | $i=2$：$34\bmod 2=0$ ⇒ `false` | 1 |
| 4 | $\{7, 12, 19\}$（下标 1,2,3） | $38$ | $i=2$：$38\bmod 2=0$ ⇒ `false` | 1 |

最终输出 `1` ✅ 与官方样例一致，也正是题面例子里说的"只有一种的和为素数：$3+7+19=29$"。

板书要圈两处：

- **第 2 行为什么只试到 5**：判据是 $i \times i \le v$，$6^2 = 36 > 29$ 就停了 —— 不是试到 $28$。这一步把 $\sqrt{}$ 的含义讲实。
- **第 3、4 行的顺序**：DFS 先固定"选 3"，所以第 3 个组合是 $\{3,12,19\}$，$\{7,12,19\}$ 最后。题面举例写的是 $22,29,38,34$，顺序和我们的输出（$22,29,34,38$）不同，**但计数完全一样** —— 这正好说明"枚举顺序不影响答案，只影响好不好看"。字典序是 P1157 那种"要输出方案"的题才必须在意的。
- 顺带一提，同一形状的组合 DFS 在 $n=4,k=3$ 上实测共 **15 次调用**（其中 4 次命中边界结算），加上剪枝 `i <= n - (k - dep)` 后降到 **10 次**。

## 讲解代码

完整逐段注释见 [`solution.cpp`](solution.cpp)，核心两层各 5 行：

```cpp
bool isPrime(long long v) {                    // 数学层
    if (v < 2) return false;                   // 1（和 0）不是素数 —— 本题最大的坑
    for (long long i = 2; i * i <= v; i++)     // 只试到 sqrt(v)：因子成对出现
        if (v % i == 0) return false;
    return true;
}
void dfs(int start, int dep, long long sum) {   // 搜索层：start = 能选的最小下标
    if (dep == k) { if (isPrime(sum)) ans++; return; }
    for (int i = start; i < n; i++)             // 只往后选 ⇒ 组合不重复、无需 vis[]
        dfs(i + 1, dep + 1, sum + x[i]);        // 和当参数带走 ⇒ 回溯免费
}
```

主函数读完数据只需 `dfs(0, 0, 0); cout << ans << '\n';`。

## 易错点与坑

1. **把 1 当成素数** —— 题面 $x_i \ge 1$，$k$ 可以等于 1，于是"和"完全可能就是 1。
   必须 `if (v < 2) return false;`。实测删掉这句：官方样例**照样输出 1**（碰巧不含 1），只有在 `3 1 / 1 2 4` 上才暴露成 `2`（正确 `1`）。**这就是"必须自己造边界数据"的理由。**
2. **判素循环从 $i=3$ 开始、或者先 `if (v%2)` 忘了写全** —— 偶数和全体误判。实测官方样例直接变成 `4`（正确 `1`），因为样例的和 22/34/38 全是偶数。这题的样例其实挺"狠"，写错判素当场就露。
3. **循环条件 `i * i < v` 而不是 `i * i <= v`** —— 完全平方数被误判为素数。实测 `3 2 / 2 7 9`：和 9 被当成素数，答案从 `1` 变 `2`。
   同理 `for (i = 2; i < sqrt(v); i++)` 有两个毛病：每轮算一次浮点 `sqrt`（慢），且浮点误差在平方数附近抖一下就可能漏判 —— **写 `i * i <= v` 是唯一稳妥的选择**。
4. **把组合写成排列** —— 同一选法重复计 $k!$ 倍。实测官方样例输出 `6` 而不是 `1`（$k=3$，$3!=6$）。分界线还是那句：**下一层的起点必须比当前下标大**（`dfs(i + 1, ...)`），于是 `vis[]` 根本不需要。见 [P1157](../p1157-combination/) 的对照表。
5. **忘了 $k < n$ 与下标边界** —— 循环写成 `for (i = start; i <= n; i++)` 会读到 `x[n]`（越界垃圾值）。数组下标是 $0..n-1$，上界必须是 `i < n`。
6. **`ans` 统计的是"选法"而不是"不同的和"** —— 见"题目大意"第 2 点，实测 $n=4,k=2,x=1\,1\,1\,1$ 输出 6。如果题目改口径为"有多少种不同的素数和"，就得把和丢进 `set` 再计数 —— **读题时把"种"字指向什么写清楚**。
7. **类型与溢出的账要算** —— $19\times5\times10^6 = 9.5\times10^7$，`int` 够；但 $i\times i$ 这类"看着小"的乘法在变式（$x_i \le 10^9$ 或 $n$ 更大）里会爆 `int`，写成 `long long` 或用 `1LL * i * i` 才安全。别把"这题刚好不爆"当成"这样写永远对"。
8. **想上埃氏筛优化判素？** 可以先不算。实测本题逐个整数试除，最耗时档（$k=10$，18 万种组合）也只要 458~514 ms，时限 1500 ms；把 $2..\sqrt{9.5\times10^7}$ 里的素数预先筛出来（本机算得 $\pi(9747)=1202$ 个）再试除，只是把单次成本从最多 9747 轮降到最多 1202 轮，属于"锦上添花"，代码反而长（见"常见变式"）。
9. **$n = 1$ / $k = 0$ 的下边界** —— 题面写 $1\le n\le20$ 且 $k<n$，$n=1$ 时只能 $k=0$。实测本程序输出 `0`（选 0 个数和为 0，非素数），不崩、不挂；但真数据大概不会给，写个 `return` 兜底即可。

## 常见变式

| 变式 | 差异 | 应对 |
| --- | --- | --- |
| 判素改成"先筛再判" | 单次试除从最多 $9746$ 轮降到最多 $\pi(\sqrt v)=1202$ 轮（本机算得 $\pi(9747)=1202$） | 预处理 $[2, 10^5]$ 的素数表，判素只试这些素数；实测本题**不优化也够** |
| Miller–Rabin / $x_i \le 10^{18}$ | `long long` 乘法都会爆 | 用 `__int128` 或龟速乘，判素换概率性算法 |
| 求"和的最大值/最小值"且要求素数 | 不只是计数 | 枚举时维护 `best`，或按和排序后判素 |
| 元素可重复取（同一个数能用多次） | 组合 → 可重组合 | 下一层传 `i`（不是 `i+1`）；实测 [P1157](../p1157-combination/) 的这个错法在 $n=5,r=3$ 上给 35 行 $=\binom{n+r-1}{r}$ |
| 问"是否**存在**一种取法使和为素数" | 只要一个解 | 命中即 `exit(0)` / 提前 return，剪枝效果最好 |
| $n \le 40$ | $\binom{40}{20}\approx1.4\times10^{11}$，DFS 不可行 | 折半搜索（meet in the middle）：两边各枚举 $2^{20}$ 再合并 |

## 一句话提炼

> **枚举归搜索（下一层起点 = 上一个下标 + 1，`sum` 当参数带走所以回溯免费），判定归数学（$v<2$ 先否，只试除到 $i\times i \le v$）—— 两层分开写，各查各的 bug。**
