## 题目大意

题面关键原文（逐字，完整版见 [`problem.txt`](problem.txt)）：

> 按照字典序输出自然数 $1$ 到 $n$ 所有不重复的排列，即 $n$ 的全排列，要求所产生的任一数字序列中不允许出现重复的数字。
>
> 输出格式：由 $1 \sim n$ 组成的所有不重复的数字序列，每行一个序列。每个数字保留 $5$ 个场宽。

用自己的话再说一遍：

- **输入**：一个整数 $n$。
- **要算**：把 $1..n$ 这 $n$ 个数排成一排，所有可能的排法**一行一个**全打出来。
- **两个附加要求**（判题卡的就是这两条）：① 按**字典序**输出；② 每个数字占**5 个字符宽度**（右对齐，前面补空格）。

$n=3$ 一共 $3! = 6$ 个排列，$n=9$ 一共 $9! = 362\,880$ 个 —— 这就是题面上限，也是本题"最极限"的规模。

## 思路推导

### 1. 直觉想法：为什么非要递归

初学者第一反应是"那就多重循环呗"：

```cpp
for (int i = 1; i <= n; i++)
  for (int j = 1; j <= n; j++)
    for (int k = 1; k <= n; k++) ...   // 还要判断 i、j、k 互不相同
```

$n=3$ 能写，$n=9$ 就要写 9 层、而且 `for` 的个数得跟着输入变 —— **循环的层数是一个输入变量**，这在 C++ 里写不出来。
"层数不固定 + 每层做同一个动作（挑一个还没用过的数）"，这正是递归的形状。

另一个直觉是"生成 + 检查"：$n^m$ 个序列全生成再筛掉重复 —— $n=9$ 时是 $9^9 = 387{,}420{,}489$，比正解的 $9!=362{,}880$ 大了一千倍，不可取。**DFS 的本质进步就是：绝不生成非法序列，而是边走边禁止非法选择。**

### 2. 关键观察：把排列想成"给位置填数"

排列是 $n$ 个**位置**，我们从左往右逐个位置填：

- 状态只有两样：**现在填第几个位置**（$d$）、**哪些数已经被用掉了**（`vis[]`）。
- 第 $d$ 层能填的数 = 所有 `vis[x] == false` 的 $x$。
- 填到 $d = n$（$n$ 个位置全填满）就说明攒出了一个完整排列，直接输出。

三句话概括回溯（讲课时让学生背这三句，每写一个 DFS 都自问一遍）：

| 步骤 | 本题对应的代码 | 大白话 |
| --- | --- | --- |
| **做了什么** | `a[d] = x; vis[x] = true;` | 把 $x$ 放到第 $d$ 个位置，并且在本子上记一笔"$x$ 用过了" |
| **往下递归** | `dfs(d + 1);` | 带着这个新状态，去填下一个位置 |
| **撤销什么** | `vis[x] = false;` | 从下面回来后，把"$x$ 用过了"这条记录擦掉，位置 $d$ 空出来，本层接着试下一个数 |

第三条最容易忘。**撤销必须和登记严格成对、一一对称**：登记在递归之前，撤销在递归之后。

### 3. 字典序是从哪来的（不是巧合）

题面要求"按字典序输出"。我们**没有**写任何排序代码，为什么顺序天然就对？

因为每一层的循环都是 `for (x = 1; x <= n; x++)`，即**从小到大**试；而 DFS 会把"本层选了 1"这一整棵子树**完全走完**才回头选 2。
这正是"深度优先 + 每层按候选值升序"= 输出按字典序 —— 和翻字典一样：先固定第一位是 1，再穷举后两位。

对比：如果先递归再改循环方向（从 $n$ 到 1），输出就是反字典序；如果中途用 `sort` 排，那是多余的 $O(n!\log n!)$。

### 4. 算法设计（伪代码）

```
dfs(d):                       # 我要给第 d 个位置填数
    if d == n: 输出 a[0..n-1]（每个数占 5 场宽）; return
    for x = 1 .. n:
        if vis[x]: continue   # 这个数已经在序列里，跳过
        a[d] = x; vis[x] = true
        dfs(d+1)
        vis[x] = false        # 回溯：擦掉登记
```

初始调用 `dfs(0)`。

### 5. 正确性论证（不重不漏）

- **不漏**：任取一个排列 $p_1p_2\cdots p_n$。第 0 层循环必然经过 $x=p_1$（`vis` 此时全 false，不会被跳过），递归进第 1 层后 $p_2 \ne p_1$ 故 `vis[p_2]` 为 false，也能被选中……归纳到底，这条路径存在，因此该排列一定被输出。
- **不重**：一次输出对应递归栈上唯一的一条"从根到叶"路径，即唯一的 $(a[0],a[1],\dots,a[n-1])$ 取值序列；两条不同路径必然在某个位置选了不同的数，输出的序列就不同。所以不会有重复行。
- **合法性**：`vis[x]` 保证同一个数在同一条路径上至多被选一次 ⇒ 序列内无重复数字；候选范围 $1..n$ 保证数字恰好是 $1..n$。$n$ 个互不相同的 $1..n$ 中的数 ⇒ 就是一个排列。
- **顺序**：由 §3 的"每层升序 + 完整走完子树"⇒ 字典序。

### 6. 复杂度

- 输出行数 $= n!$，每行 $n$ 个数 ⇒ 时间 $\Omega(n\cdot n!)$，这是**输出量的下限**，谁写都快不了。
- 递归调用次数 $=$ 所有"长度 $\le n$ 的互不相同序列"个数 $= \sum_{k=0}^{n} \dfrac{n!}{(n-k)!}$。本机实测：$n=3$ 时 **16** 次 `dfs` 调用（其中 15 次"选数"、15 次撞上"已用过，跳过"、6 次命中边界输出），$n=9$ 时 **986410** 次调用（其中叶子 362880 个）。
- 空间：`a[]`、`vis[]` 各 $O(n)$，递归栈深 $n$ ⇒ $O(n)$。$n\le 9$，怎么开都够。

## 板书演示（$n = 3$，官方样例）

下表是**真的把带打印语句的同一份 DFS 跑出来的事件顺序**（事件编号 = 进入/撤销的先后，缩进 = 递归深度），不是我手推编的：

| 事件 | 动作 | `a[]`（位置 0/1/2） | `vis[1..3]` | 说明 |
| --- | --- | --- | --- | --- |
| 1 | `dfs(0)` 进入 | `[ , , ]` | `0 0 0` | 一开始谁都没用 |
| | 位置 0 选 `x=1` | `[1, , ]` | `1 0 0` | 做了什么：放 1、登记 1 |
| 2 | `dfs(1)` 进入 | `[1, , ]` | `1 0 0` | 往下递归 |
| | 位置 1 试 `x=1` | — | `1 0 0` | **已用过，跳过**（第一次体现 `vis` 的价值） |
| | 位置 1 选 `x=2` | `[1,2, ]` | `1 1 0` | |
| 3 | `dfs(2)` 进入 | `[1,2, ]` | `1 1 0` | |
| | 位置 2 试 `x=1`、`x=2` | — | `1 1 0` | 两次都被跳过 |
| | 位置 2 选 `x=3` | `[1,2,3]` | `1 1 1` | |
| 4 | `dfs(3)` 进入 → **输出 `    1    2    3`** | `[1,2,3]` | `1 1 1` | 递归边界：$d==n$ |
| 5 | 位置 2 **撤销** `x=3` | `[1,2, ]` | `1 1 0` | 撤销什么：`vis[3]=0`；本层 $x$ 已到 3，循环结束返回 |
| 6 | 位置 1 **撤销** `x=2` | `[1, , ]` | `1 0 0` | 回到第 1 层，接着试 $x=3$ |
| | 位置 1 选 `x=3` | `[1,3, ]` | `1 0 1` | |
| 7 | `dfs(2)` 进入 | `[1,3, ]` | `1 0 1` | |
| | 位置 2 试 `x=1` 跳过、选 `x=2` | `[1,3,2]` | `1 1 1` | |
| 8 | `dfs(3)` 进入 → **输出 `    1    3    2`** | `[1,3,2]` | `1 1 1` | 第 2 个排列 |
| 9 | 位置 2 撤销 `x=2` | `[1,3, ]` | `1 0 1` | |
| 10 | 位置 1 撤销 `x=3` | `[1, , ]` | `1 0 0` | 第 1 层 $x$ 试完 1(跳过)/2/3，返回 |
| 11 | 位置 0 **撤销** `x=1` | `[ , , ]` | `0 0 0` | **`vis` 全部归零**，第 0 层接着试 $x=2$ |

实测整棵树的汇总：**16 次 `dfs` 调用、15 次选数、15 次"已用过跳过"、6 次输出**，输出顺序
`123 → 132 → 213 → 231 → 312 → 321`，与官方样例逐字一致（每数 5 场宽、行末无空格、末尾有换行）。

黑板上讲评第 11 步这一格最有价值：**"撤销"不是可选项，它是在为兄弟分支恢复世界**。
如果 `vis[1]` 不归零，接下来"位置 0 选 2"这条分支里 1 仍然是"已用过"，整个后半棵树都会长歪。

## 讲解代码

完整逐段注释见 [`solution.cpp`](solution.cpp)，核心 12 行：

```cpp
void dfs(int d) {
    if (d == n) {                                   // 边界：n 个位置填满
        for (int i = 0; i < n; i++) cout << setw(5) << a[i];   // 场宽 5 是题面硬性要求
        cout << '\n';                              // '\n' 不是 endl
        return;
    }
    for (int x = 1; x <= n; x++) {                 // 每层都从 1 试到 n（排列）—— 顺序保证字典序
        if (vis[x]) continue;                      // vis[] 去重：同一个数不能出现在两个位置
        a[d] = x;  vis[x] = true;                  // ① 做了什么
        dfs(d + 1);                                // ② 往下递归
        vis[x] = false;                            // ③ 撤销什么
    }
}
```

`setw(5)` 需要 `#include <iomanip>`；`ios::sync_with_stdio(false); cin.tie(nullptr);` 是为了 $n=9$ 那 362880 行输出不卡格式（见"验证结论"的计时对比）。

## 易错点与坑

1. **忘写 `vis[x] = false`（回溯漏了）** —— 实测 $n=3$ 只剩 1 行、$n=4$ 也只剩 1 行。
   而且它**不是"输出变少"这么温和**：第一位选过 1 之后，后面所有分支都以为 1 还在用，$n$ 稍大就直接少掉绝大部分输出。检查方法：拿 $n=3$ 数一下行数，必须是 6。
2. **登记/撤销不对称**：把 `vis[x] = false;` 写到了 `dfs(d + 1)` **之前**，等于"刚登记就把自己的记录擦掉"，`vis[]` 全程全 false，去重彻底失效。
   实测这份错码在 $n=3$ 上输出 **27 行**（$=3^3$，第一行是 `    1    1    1`，即允许数字重复的全部序列），而正确答案只有 6 行；
   照这个规律，$n=9$ 就要输出 $9^9 = 387{,}420{,}489$ 行 —— 当场超时。**"撤销"必须写在递归返回之后**，位置紧贴 `dfs(d+1)` 下一行。
3. **组合写成排列 / 排列写成组合**（这三题最容易混的地方）：
   - 排列：`for (x = 1; x <= n; x++)` + `vis[]` 去重 —— **每一层都从 1 开始试**，因为"下一个位置放谁"和上一个位置放的数没有大小关系。
   - 组合：`for (x = start; x <= n; x++)` + 传 `x + 1` 下去 —— **不需要 `vis[]`**，靠"只能往后选"天然不重复、天然字典序。
   - 混用的代价实测：把 P1157（$n=5,r=3$）按排列写 ⇒ 输出 **60 行**（$=P(5,3)$，多出 6 倍）；把本题按组合写 ⇒ $n=3$ 只剩 **1 行**。详见 [P1157 的"排列 vs 组合"小节](../p1157-combination/README.md)。
4. **`setw` 忘 `#include <iomanip>`** —— 编译直接挂（错误原文见上表）。反过来说，这题**格式错误比逻辑错误更容易犯**：`setw(5)` 写成 `setw(3)`、或者 `cout << a[i] << " "`（自己加空格）都不能过。
5. **行末多打空格 / 末尾换行** —— 本题正解的输出每行恰好 $5n$ 个字符、**行末没有空格**（因为最后一个数打完就结束了），最后一行**后面有一个换行**。这两个都不该手动"补一下"。
   注意：本地没法验证洛谷 checker 对行末空白的宽容度，所以**唯一安全的做法是逐字照题面输出**。
6. **`endl` 的性能** —— 362880 行 × 每行一次 flush，实测慢 3~4 倍。数据规模再大一点（$n=10$，$10! = 3{,}628{,}800$ 行）就可能踩时限。
7. **$n = 1$ 边界** —— 应输出 1 行 `    1`（实测程序输出正好如此）。别在 `if (d == n)` 里写成 `d > n` 之类的偏移，否则 $n=1$ 时不输出。

## 一句话提炼

> **回溯三句话：做了什么 → 往下递归 → 撤销什么；`vis[]` 记住"正在用的"，返回时必须原样还回去。**
> 排列每层从 1 试（靠 `vis` 去重），组合每层从"上一个 + 1"试（天然去重）—— 这一字之差就是 P1706 和 P1157 的全部区别。
