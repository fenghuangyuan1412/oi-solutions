## 题目大意

用 $n$ 根等长木棍按七段数码管摆一个**正整数**（每个数字固定耗棍：0→6、1→2、2→5、3→5、4→4、5→5、6→6、7→3、8→7、9→6），要求**恰好用完 $n$ 根**、**无前导 0**、数**尽可能小**；无解输出 `-1`。

官方样例（problem.txt）：输入 `5 / 1 / 2 / 3 / 6 / 18`，输出：

```
-1
1
7
6
208
```

样例手算表：

| n | 输出 | 为什么 |
| --- | --- | --- |
| 1 | -1 | 摆任何数字至少 2 根 |
| 2 | 1 | 只有数字 1 用 2 根 |
| 3 | 7 | 用 3 根的最小数字是 7 |
| 6 | 6 | 一位数里 6 根的方案有 0/6/9，正整数且最小 ⇒ 6（题面解释：9、41、111 也都用 6 根，但不是最小） |
| 18 | 208 | 5+6+7=18；题面逐字："可以证明摆出任何一个小于 208 的正整数需要的小木棍数都不是 18"；"拼出 006 也需要 18 根…因为有前导零…并不是一个满足要求的方案" |

## 一、骗分：这一档怎么拿

problem.txt 的数据范围表（逐字）：

| 测试点编号 | $n\leq$ | 特殊性质 |
| :----------: | :----------: | :----------: |
| $1$ | $20$ | 无 |
| $2$ | $50$ | ^ |
| $3$ | $10^3$ | A |
| $4,5$ | $10^5$ | ^ |
| $6$ | $10^3$ | B |
| $7,8$ | $10^5$ | ^ |
| $9$ | $10^3$ | 无 |
| $10$ | $10^5$ | ^ |

特殊性质 A：保证 $n$ 是 $7$ 的倍数且 $n \geq 100$。特殊性质 B：保证存在整数 $k$ 使得 $n = 7k + 1$，且 $n \geq 100$。
（problem.txt 只给了总分 100 与上表，**没有给每个测试点的分值**，下面一律按"测试点编号"计档，不虚报分数。）

### 档 1：测试点 1~2（n ≤ 20、n ≤ 50）—— 裸 DFS 回溯（本目录 `solution_partial.cpp`）

位数从小到大枚举 $L$，从最高位往低位**按数字升序**试 0~9，唯一剪枝是"后面每格至少 2 根也不能超"（`used + 2*(L-depth) > n` 回头）。因为按升序试，**第一个找到的解就是最小数**。

本机实测（程序 stderr 打印结点数）：

| n | 搜索结点数 | 说明 |
| --- | --- | --- |
| 18 | 123 | 官方样例第 5 组 |
| 20 | 655 | 答案 688 |
| 50 | 987657 | 答案 10888888，单组约几十毫秒 |
| 50 组 n=50 | —— | 实测 78 ms（含进程启动），测试点 2 稳过 |
| 65 | 987654323 | 实测 3072 ms —— 已经超时限 |
| 70 | —— | **实测跑不完，20 秒后手动终止** |

结论：这版能拿下测试点 1、2；n 一过 60 立刻爆炸，**数据范围是硬墙**（手册 T2）。

### 档 2：测试点 3~5（特殊性质 A）—— 一行公式

$n$ 是 7 的倍数（设 $n = 7k$，$k \ge 15$）：位数下界是 $\lceil n/7 \rceil = k$，而 $k$ 位数恰好用满 $7k$ 根**只能全是 8** ⇒ 答案就是 $k$ 个 `8`。
本机用正解程序对 $k = 15..200$（即 $n = 105..1400$）逐组核对：输出全部等于 $k$ 个 8，无一例外。

### 档 3：测试点 6~8（特殊性质 B）—— 两行公式

$n = 7k + 1$（$n \ge 100$）：最少位数 $k+1$，把"一个 8 换成 1 和 0"正好省 6 根 ⇒ 答案 = `10` 后接 $k-1$ 个 `8`。
本机对 $k = 1..200$ 与正解程序逐组核对一致（如 $n=15 \Rightarrow 108$，$n=22 \Rightarrow 1088$）。

### 骗分的天花板

把档 1 的 DFS 再补**一行**上界剪枝 `used + 7*(L-depth) < n → 回头`，n=18 的结点数就从 **123 降到 13**（本机实测），而且此后 DFS 再也不需要回溯——这条剪枝就是正解的一半。见 [visualization.html](visualization.html) 最后一步。

## 二、正解：最少位数 + 逐位贪心

### 关键观察

1. **位数越少数越小**：任何 $L$ 位数 < 任何 $L+1$ 位数 ⇒ 先定最少位数 $L = \lceil n/7 \rceil$（每位最多 7 根）。$n=1$ 时无解（$2L > n$ 恒成立）。
2. **可行性判据（充要）**：还剩 $k$ 个空位、$r$ 根棍 ⇔ 能摆完 ⇔ $2k \le r \le 7k$。
   必要性显然；充分性：先全放"1"（耗 $2k$ 根），剩下的 $r - 2k \le 5k$ 根逐个加到各位上（每位最多加 5 根，且 2~7 根的数码都存在）。
3. 有了充要判据，**逐位贪心**：从最高位开始，数字从小到大试，选"填完后剩余仍可行"的最小数字。可行判据精确 ⇒ 贪心永不会把自己堵死。

### 正确性

位数 $L$ 取的是下界（每位 ≤ 7 根），任何合法数位数 ≥ L ⇒ 我们的数位数最少。同位数下逐位取"使后缀可行的最小数字"：若某个更小的数存在，它第一位与我们不同的位置 $i$ 上填了更小的数字 $d' < d_i$，但 $d'$ 在判据下不可行（否则贪心早就选它），矛盾。$\blacksquare$

### 复杂度

时间 $O(L \times 10) = O(n)$，空间 $O(L)$（存答案串）。实测 50 组 $n = 10^5$（每组输出 14286 位）共 **74 ms**（含进程启动）；输出串经脚本核验棍数恰为 100000。

## 三、板书演示：n = 18 逐位贪心

$L = \lceil 18/7 \rceil = 3$。判据：剩 $k$ 个空位、$r$ 根棍 ⇔ $2k \le r \le 7k$。

| 位 | 尝试 | 花费 | 剩余 r | 空位 k | 判据 2k ≤ r ≤ 7k | 结果 |
| --- | --- | --- | --- | --- | --- | --- |
| 百 | 1 | 2 | 16 | 2 | 16 > 14 | ✗ 剪掉 |
| 百 | 2 | 5 | 13 | 2 | 4 ≤ 13 ≤ 14 | ✓ 定 2 |
| 十 | 0 | 6 | 7 | 1 | 2 ≤ 7 ≤ 7 | ✓ 定 0 |
| 个 | 0..7 | —— | 1~5 根凑不齐 | 0 | r 必须 = 0 | ✗ |
| 个 | 8 | 7 | 0 | 0 | ✓ | 定 8 ⇒ **208** |

## 四、讲解代码

正解核心（`solution.cpp`）：

```cpp
if (n == 1) { puts("-1"); continue; }
int L = (n + 6) / 7;                       // 最少位数 ceil(n/7)
string s; int rem = n;
for (int pos = 0; pos < L; ++pos) {
    int slots = L - pos - 1;               // 这一位之后还剩的空位
    for (int d = (pos == 0 ? 1 : 0); d <= 9; ++d) {   // 首位不能是 0
        int r = rem - C[d];
        if (r < 2 * slots || r > 7 * slots) continue; // 可行性判据
        s.push_back(char('0' + d)); rem = r; break;
    }
}
```

骗分版核心（`solution_partial.cpp`，只卡下界的 DFS）：

```cpp
bool dfs(int depth, int used) {
    if (depth == L) return used == n;               // 叶子：恰好用完才算成功
    if (used + 2 * (L - depth) > n) return false;   // 剪枝①：全放 1 也超了
    // 故意没写剪枝②：used + 7*(L-depth) < n 必失败 —— 补上它正解就出来了
    for (int d = (depth == 0 ? 1 : 0); d <= 9; ++d)
        if (dfs(depth + 1, used + C[d])) { sol[depth] = d; return true; }
    return false;
}
```

`verify.js`（仅用于验证，非讲解代码）：确定性扫 n=1..60，比较两版输出，60/60 一致。

## 五、易错点与坑（每条都是编译一个故意写错的版本、跑官方样例的实际输出）

1. **忘了"无前导 0"**（首位候选从 0 开始）——官方样例实测输出：
   ```
   -1
   1
   7
   0
   000
   ```
   n=6 输出 `0`（0 不是正整数）、n=18 输出 `000`——题面解释点名批评过的正是这种方案。
2. **位数用下取整 `L = n / 7`**（应为 $\lceil n/7 \rceil$）——实测输出：
   ```
   -1
   （后面 4 行全部是空行）
   ```
   位数不够时装不下，内层循环一位都选不出来，程序**安静地输出空行**——不崩但全错，最难查。
3. **判据只写下界 `r < 2*slots`，漏掉上界 `r > 7*slots`**——实测输出：
   ```
   -1
   1
   1
   1
   100
   ```
   n=3 输出 `1`（只用了 2 根！）、n=18 输出 `100`（14 根）：贪心一路选小数字，剩余棍数根本装不进空位，"恰好用完"被破坏。
4. **删掉 `n == 1` 特判和 `2*L > n` 兜底**：官方样例实测第一行变成**空行**（应为 `-1`），后四行照常：
   ```
   （空行）
   1
   7
   6
   208
   ```
   两道防线要至少留一道：无解情形必须显式输出 `-1`，不能让"一位都选不出"的循环静默吞掉。

## 六、常见变式

| 变式 | 差异 | 备注 |
| --- | --- | --- |
| 求**最大**数 | 位数取上界 $\lfloor n/2 \rfloor$，逐位从大到小贪心 | 判据完全复用 |
| 允许前导 0 / 定长 L 位 | 直接在 $[2L,7L]$ 内逐位贪心 | 签到难度 |
| 每个数字成本改变 | 只要"单位成本区间连续"，判据仍充要 | 否则要改成背包判定 |
| n 达 10^7 | 输出本身成为瓶颈，需 `putchar` 级 IO | 算法仍是 O(n) |

## 七、一句话提炼

**"位数少先摆小数字"的贪心要成立，得先有一个充要可行性判据**——本题判据朴素到能板书：$k$ 个空位装 $r$ 根 ⇔ $2k \le r \le 7k$。DFS 骗分每多悟出一条剪枝，就离正解近一步；两条剪枝（下界+上界）齐了，回溯自动消失。
