## 题目大意

逐字引自 `problem.txt`：

> 机器人的状态由位置和朝向两部分组成……朝向用一个 $0 \sim 3$ 的整数 $d$ 表示，其中 $d = 0$ 代表向东，$d = 1$ 代表向南，$d = 2$ 代表向西，$d = 3$ 代表向北。
> 每一步：若面朝方向的下一步 $(x',y')$ 满足「在地图内且是空地」，则向前走一步（朝向不变）；否则执行"向右转"，令 $d' = (d+1) \bmod 4$，位置保持不变。
> 问执行完 $k$ 步后，地图上所有**被机器人经过的位置（包括起始位置）**有几个。

一句话：**照规则走 $k$ 步，数一共踩过多少个不同的格子。**

样例 1 第 1 组手算（$n{=}1,m{=}5,k{=}4$，起点 $(1,1)$，$d{=}2$ 朝西，地图 `....x`）：

| 步 | 动作 | 位置 | 朝向 | 已经过的格子 |
| --- | --- | --- | --- | --- |
| 初 | — | (1,1) | 2 西 | {(1,1)} = 1 |
| 1 | 下一步 (1,0) 越界 → 右转 | (1,1) | 3 北 | 1 |
| 2 | 下一步 (0,1) 越界 → 右转 | (1,1) | 0 东 | 1 |
| 3 | 下一步 (1,2) 空地 → 前进 | (1,2) | 0 东 | 2 |
| 4 | 下一步 (1,3) 空地 → 前进 | (1,3) | 0 东 | **3** |

⇒ 输出 `3`（与题面样例解释完全一致）。第 2 组按同样规则模拟得 `13`。

本题模拟部分人人都会写，**真正的分档在「怎么数经过了多少个不同格子」**：

### 档 1（点 1~4，$k\le 1$、地图很小）

规则照抄成循环即可，去重再笨也跑得动。约 **40 分**。

### 档 2（点 5~6，$n=1$ 一条走廊，$k\le 2000$）：本目录 `solution_partial.cpp`

把「经过的格子」依次塞进一个 `vector<pair>`，每要前进就**线性扫一遍**看走过没有：

```cpp
vector<pair<int,int>> visited; visited.push_back({x,y});
...
if (!seen(x,y)) visited.push_back({x,y});   // seen = 线性扫描，O(visited.size())
```

- 去重代价 $O(k^2)$，$k\le 2000$ 时约 $4\times10^6$，完全够。
- **累计约 60 分**（点 1~6）。
- **实测**：暴力版在 $T{=}5,n{=}m{=}100,k{=}2000$ 上跑 **11 ms**。

### 档 3（点 7~10，$k\le 10^6$）：暴力版在这里超时

$k=10^6$ 时 $O(k^2)$ 直接爆。**实测**：暴力版在最坏数据（$T{=}5,n{=}m{=}1000,k{=}10^6$）上跑 **5319 ms**，远超 1000 ms 时限 ⇒ 点 7~10 拿不到。要过这一档，就得把去重换成下面正解的 $O(1)$ 二维标记。

> 特殊性质「地图上所有位置均为空地」（点 5、7）：此时机器人只会沿边界绕圈、从不撞障碍，但**照规则模拟天然覆盖**，不必为它单写特判。

## 二、正解：模拟 + 二维 bool 数组去重

### 关键观察

1. **位移用方向表统一表达**，别写 4 段 `if`。朝东列 +1、朝南行 +1、朝西列 −1、朝北行 −1：
   `dx[4]={0,1,0,-1}`、`dy[4]={1,0,-1,0}`，于是下一步永远是 `(x+dx[d], y+dy[d])`，右转是 `d=(d+1)%4`。
2. **数不同格子要 $O(1)$ 查重**：地图格子总数只有 $n\cdot m\le 10^6$，直接开一张 `bool vis[n+1][m+1]`，踩到第一次才让计数 +1。

### 算法设计

每组数据：
1. 读入，起点 `vis[x][y]=1`，`cnt=1`（**起点算已经过**）；
2. 重复 $k$ 次：算 `(nx,ny)`；若「在界内且是 `.`」就前进，且首次踩到则 `++cnt`；否则 `d=(d+1)%4`；
3. 输出 `cnt`。

### 正确性

循环不变式：每轮开始时 `vis` 恰好标记了机器人到目前为止踩过的格子、`cnt` 为其数量。前进时若目标未标记则补标记并 `++cnt`，右转时位置不变（不新增）。故 $k$ 轮后 `cnt` = 含起点在内的不同经过格数。$\blacksquare$

### 复杂度

时间 $O(nm + k)$ 每组（`vis` 初始化 $O(nm)$ + 模拟 $O(k)$），$T\le5$ 合计约 $10^7$；空间 $O(nm)\le10^6$ 字节。**实测**：最坏数据正解 **31 ms**（含进程启动），远在时限内。

## 四、讲解代码

### 正解（`solution.cpp`）核心

```cpp
const int dx[4]={0,1,0,-1}, dy[4]={1,0,-1,0};   // 东 南 西 北
vis[x][y] = 1; int cnt = 1;                       // 起点算已经过
for (long long step = 0; step < k; ++step) {
    int nx = x + dx[d], ny = y + dy[d];
    if (inside(nx,ny) && g[nx][ny] == '.') {      // 界内且是空地才走
        x = nx; y = ny;
        if (!vis[x][y]) { vis[x][y] = 1; ++cnt; } // 首次踩到才计数
    } else {
        d = (d + 1) % 4;                           // 否则原地右转
    }
}
```

### 骗分版（`solution_partial.cpp`）的差别

模拟逻辑**一模一样**，只有去重不同：

```cpp
vector<pair<int,int>> visited;                     // 顺序存经过的格子
auto seen = [&](int xx,int yy){                    // 查重 = 线性扫描 O(visited)
    for (auto &p : visited) if (p.first==xx && p.second==yy) return true;
    return false;
};
...
if (!seen(x,y)) visited.push_back({x,y});
```

把「线性查重的 vector」换成「$O(1)$ 查重的 `bool vis[n][m]`」，就是 60 分到 100 分的那一步。两版在 100 组随机小数据上输出**完全一致**。

## 五、易错点与坑（每条都附本机实测输出，官方样例 1 正确答案 `3 / 13`）

1. **起点忘了算进经过数**（`cnt` 初值 0、没标 `vis[x][y]`）。实测输出 **2 / 12**（少 1）。
2. **只判越界、忘了判障碍**（`if(inside)` 漏了 `&& g[nx][ny]=='.'`），机器人会穿过 `x`。实测输出 **3 / 16**（第 2 组多踩了障碍格）。
3. **右转写成左转**（`d=(d+3)%4` 或 `%4` 漏写）。实测输出 **3 / 9**（转向规律反了，路径完全不同）。
4. **`dx/dy` 与朝向对不上**：题面 $d{=}0$ 是**向东 $(x,y{+}1)$**（列 +1），别按数学极角把东写成行变化；本解用 `dx[4]={0,1,0,-1}, dy[4]={1,0,-1,0}` 严格对应「东南西北」。
5. **$k$ 用 `int` 存循环变量勉强够（$10^6$），但累加/边界易越界**：`inside` 判断必须 `1<=nx<=n && 1<=ny<=m` 先做，再访问 `g[nx][ny]`，顺序反了会越界读。

## 六、常见变式

| 变式 | 差异 | 备注 |
| --- | --- | --- |
| 问最终位置/朝向 | 不用去重，模拟到底输出 $(x,y,d)$ | 更简单 |
| 问某格子被踩几次 | `bool vis` 换成 `int cnt[n][m]` 累加 | 一行改动 |
| 走到障碍就停（不转向） | 把右转分支换成 `break` | 逻辑更短 |
| $k$ 极大（$10^{18}$） | 需找**状态循环节**（位置+朝向 周期） | 从模拟跳到找环 |

## 七、一句话提炼

**模拟本身没有难度，分差全在"怎么数不同格子"**——用 `dx/dy` 方向表把"走/转"统一成两行代码，再用一张 `bool vis[n][m]` 把去重降到 $O(1)$，$O(nm+k)$ 稳过；而用 vector 线性查重的 $O(k^2)$ 暴力只能兜住 $k\le2000$ 的前 60 分。
