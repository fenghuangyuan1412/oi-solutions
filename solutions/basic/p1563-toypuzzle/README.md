## 题目大意

$n$ 个玩具小人围成一圈，每人有朝向（题面逐字：**$0$ 表示朝向圈内，$1$ 表示朝向圈外**）和职业名。输入按**逆时针**顺序给出这 $n$ 个人。从第 1 个人开始，依次执行 $m$ 条指令，第 $i$ 条指令是 $a_i, s_i$：题面逐字：**"若 $a_i = 0$，表示向左数 $s_i$ 个人；若 $a_i = 1$，表示向右数 $s_i$ 个人。"** 输出最后停在那个小人身上的职业名。

朝向为什么关键？题面原话：

> 面朝圈内的玩具小人，它的左边是顺时针方向，右边是逆时针方向；而面向圈外的玩具小人，它的左边是逆时针方向，右边是顺时针方向。

数据范围（逐字摘录）：字符串长度不超过 10 且仅由英文字母构成；保证不会出现其他的数，$1 \le s_i < n$；子任务表按测试点给出 $n, m$ 与四个特殊性质列（全朝内、全左数、$s_i = 1$、职业长度为 1），最大到 $n = 10^5$、$m = 10^5$（第 17 号测试点）；时间限制 1000 ms，内存限制 512 MB。

## 思路推导

### 1. 暴力想法：在环上一格一格数

把小人存在数组里，每次指令就循环 $s_i$ 次，一次挪一格，挪到头/尾就回绕。$s_i < n \le 10^5$、$m \le 10^5$ ⇒ 最坏 $\sum s_i$ 可达 $10^{10}$ 步，**必超时**。所以"逐格数"只能当理解规则的工具，不能当实现。

### 2. 关键观察一：左右只决定"下标 +1 还是 -1"

数组是按**逆时针**存的，所以"逆时针挪一格" = 下标 $+1$，"顺时针挪一格" = 下标 $-1$。把题面四句话翻译成一张表：

| 当前小人的朝向 | 指令 | 等价于 | 下标变化 |
| --- | --- | --- | --- |
| 朝内（0） | 左数（0） | 顺时针 | $-1$ |
| 朝内（0） | 右数（1） | 逆时针 | $+1$ |
| 朝外（1） | 左数（0） | 逆时针 | $+1$ |
| 朝外（1） | 右数（1） | 顺时针 | $-1$ |

**注意取的是"当前所在小人"的朝向**，不是下一个人的朝向 —— 这是本题第二大坑。

### 3. 关键观察二：一次算完，不要循环 $s$ 次

数 $s$ 个人 = 走 $s$ 步 = 下标平移 $s$ 格（方向由上表决定）。于是一条指令 $O(1)$：

$$\text{cur} \leftarrow (\text{cur} + \text{step} \cdot s) \bmod n, \qquad \text{step} \in \{+1, -1\}$$

C++ 的 `%` 对负数可能返回负值（$-1 \bmod 7 = -1$），所以要先加 $n$ 再取模，写成 `((cur + step*s) % n + n) % n`。

### 4. 算法设计

1. 读 $n, m$，把朝向存 `dir[]`、职业存 `job[]`（0 基下标）；
2. `cur = 0`（从第 1 个小人出发）；
3. 每条指令：按 `dir[cur]` 与 $a$ 查上表得 `step`，`cur = ((cur + step*s) % n + n) % n`；
4. 输出 `job[cur]`。

### 5. 正确性说明

- **等价性**：连续走 $s$ 格同方向的步子，下标净变化恰为 $\pm s$（模 $n$），与一次平移相同 —— 因为每步的 $+1/-1$ 在模 $n$ 下构成群，累加即乘以步数。
- **方向表**：四行分别由题面两句原话直接改写（朝内：左=顺时针、右=逆时针；朝外：左=逆时针、右=顺时针），加上"数组按逆时针存 ⇒ 逆时针 $+1$"这一约定，映射唯一。
- **取模合法性**：$\text{cur} + \text{step}\cdot s \in (-n, 2n)$，`+n` 后落在 $(0, 3n)$，再 `% n` 即得 $[0, n)$ 内的唯一代表。
- 规则映射本身不靠推理拍脑袋：本仓库把"输入顺序按顺时针/逆时针"×"0 表示朝内/朝外"×"$a_i=0$ 表示左数/右数"共 $2^3 = 8$ 种读法全部编成程序跑两组官方样例，**通过的有 4 种**（例如"逆时针 + 0 朝内 + 左数"和"顺时针 + 0 朝外 + 右数"）—— 但它们只是同一支读法的不同命名，**在 $2 \times 10^4$ 组随机数据上给出的答案完全相同（不一致 0 组）**；另外 4 种读法在第 1 组样例上就输出 `mengbier` 而不是 `writer`。题面逐字规定的是"逆时针顺序给出 + 0 朝内 + $a_i=0$ 左数"，正好落在通过的那一支里。

## 板书演示（不用可视化）

官方样例 1：$n = 7$，按逆时针顺序（下标 0 起）：

| 下标 | 朝向 | 职业 |
| --- | --- | --- |
| 0 | 0 朝内 | singer |
| 1 | 0 朝内 | reader |
| 2 | 0 朝内 | mengbier |
| 3 | 1 朝外 | thinker |
| 4 | 1 朝外 | archer |
| 5 | 0 朝内 | writer |
| 6 | 1 朝外 | mogician |

| 指令 | 当前在下标 | 当前朝向 | 数法 | 下标变化 | 落到 | 职业 |
| --- | --- | --- | --- | --- | --- | --- |
| `0 3`（左数 3） | 0 | 朝内 | 左 = 顺时针 = $-1$ | $0 - 3 = -3 \equiv 4$ | 4 | archer |
| `1 1`（右数 1） | 4 | 朝外 | 右 = 顺时针 = $-1$ | $4 - 1 = 3$ | 3 | thinker |
| `0 2`（左数 2） | 3 | 朝外 | 左 = 逆时针 = $+1$ | $3 + 2 = 5$ | 5 | **writer** |

输出 `writer` ✅。第三步尤其说明"必须用当前所在小人（3 号 thinker，朝外）的朝向"，若误用下标 5 号 writer 的朝内，就会算成 $3-2=1$，输出 `reader`。

## 讲解代码

完整带注释版本见 `solution.cpp`。核心：

```cpp
int step;
if (dir[cur] == 0) step = (a == 0 ? -1 : 1);   // 朝内：左顺右逆
else               step = (a == 0 ? 1 : -1);   // 朝外：左逆右顺
cur = ((cur + step * s) % n + n) % n;          // 一次平移 + 负数取模兜底
```

| 检验项 | 结果 |
| --- | --- |
| 官方样例 1（$7\times3$） | 输出 `writer` ✅ |
| 官方样例 2（$10\times10$） | 输出 `y` ✅ |
| 随机对拍 800 组（$n \le 10$，$m \le 10$，$s < n$，朝向随机）vs **一步一步挪**（不取模跳跃）的参照实现 | 不一致 0 组 |
| 8 种"读法"组合逐一跑两组官方样例 | 4 种通过、4 种在第 1 组样例就错；通过的 4 种在 $2\times10^4$ 组随机数据上答案两两相同 |

## 易错点与坑

- **用错朝向**：方向由**当前所在位置**的小人决定，不是指令参数、也不是上一个人。
- **负数取模**：`cur = (cur - s) % n` 在 C++ 里可能是负下标，`job[-3]` 越界（可能 RE，也可能读到脏数据给出错误职业）。必须 `((… % n) + n) % n`。
- **$s$ 与"人数"混淆**：题面"左数 $s$ 个人"是走 $s$ 步（数到第 $s$ 个），不是走 $s-1$ 步。官方样例第 1 条 `0 3` 走 3 步落到下标 4，若走 2 步会到 5，直接错。
- **职业名长度不一**：必须用 `string` 存，不能用固定长度 `char[]` 拼接后再比较。
- **$n = 1$**：题面 $1 \le s_i < n$ 保证 $n \ge 2$ 才有指令；若 $n=1$ 则不会有合法 $s$，不必特殊处理。

## 常见变式

| 变式 | 差异 | 应对 |
| --- | --- | --- |
| 子任务"全朝内" | 方向恒为一种，可省朝向判断 | 保留通用写法更稳 |
| 子任务"$s_i = 1$" | 每步只走一格 | 逐格模拟也能过，但不是正解规模 |
| 求每条指令后的位置 | 需输出 $m$ 行 | 循环内直接输出，复杂度仍是 $O(m)$ |

## 小结

环形模拟的两件套：先把"左右/顺逆"这种自然语言规则**压缩成一张 ±1 对照表**，再用"一次平移 + 归一化取模"替代逐步循环；C++ 里负数取模一定别忘了补 `+n`。
