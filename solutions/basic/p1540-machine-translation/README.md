## 题目大意

翻译软件逐个处理文章里的 $N$ 个单词。内存里有 $M$ 个单元：

- 词**已在内存** ⇒ 直接用，**不查外存**；
- 词**不在内存** ⇒ 查一次外存（计数器 +1），然后把这个词放进内存；
- 放之前若内存已满 $M$ 个，**清空最早进入内存的那个单词**；若还没满（不超过 $M-1$ 个），直接找一个空位放。

求查外存的总次数。

数据范围（逐字）：

- 对于 $10\%$ 的数据有 $M = 1$，$N \le 5$；
- 对于 $100\%$ 的数据有 $1 \le M \le 100$，$1 \le N \le 1000$。

第二行是 $N$ 个非负整数，大小不超过 1000，相同的整数代表同一个单词。

## 思路推导

### 1. 暴力想法：完全照着规则做

开一个数组当"内存"，每来一个词就线性扫一遍看在不在；不在就查词典，然后按规则放进去：满了就删掉最早的。$N \le 1000$、$M \le 100$，最坏 $10^5$ 次比较，怎么暴力都来得及。

**这题的暴力就是正解**，唯一要写对的是"淘汰谁"。

### 2. 关键观察：淘汰规则是 FIFO，不是 LRU

题面原话：**"软件会清空最早进入内存的那个单词"** —— 淘汰的是**进入时间最早**的词，和"最近有没有被用到"完全无关。

所以命中一个已经在内存里的词时，**内存内容一个字都不动**。很多同学习惯性地写"把命中的词挪到队尾"，那就变成了 LRU，答案会偏小（LRU 命中率更高），这是本题唯一的、也是最致命的坑。

### 3. 算法设计

1. 读入顺序是 **先 $M$（内存单元数）再 $N$（文章长度）**；
2. `queue<int> mem` 保存内存里的词，队头 = 最早进入；
3. `set<int> inMem` 提供 $O(\log M)$ 的存在性判断（$M$ 很小，用 `bool exist[1001]` 或线性扫都对）；
4. 对每个词：命中 → `continue`；未命中 → `lookup++`，若 `mem.size() == M` 则弹出队头并从 `inMem` 删掉，然后压入队尾。

### 4. 正确性说明

归纳可证：处理到第 $i$ 个词时，`mem` 里恰好是"所有未命中而被查词典、且尚未被淘汰"的词，按进入顺序排列。

- 命中分支不修改 `mem`，与"内存中有则直接用"一致；
- 未命中分支先判断是否装满：装满才淘汰队头，正是题面"已存入 $M$ 个才清空最早的那个"；没装满则填空位，`mem.size() < M` 时不淘汰，也与题意一致；
- `mem` 按进入顺序排列，队头即最早进入，淘汰它符合 FIFO。

因此 `lookup` 累加的次数恰等于题面定义的"查词典次数"。

### 5. 复杂度分析

$N$ 次操作，每次 $O(\log M)$ 查表 + 常数次队列/集合修改 ⇒ $O(N \log M) \le 10^3 \times 7$。空间 $O(M) \le 100$。

## 板书演示（不用可视化）

官方样例：$M = 3$，$N = 7$，词序 `1 2 1 5 4 4 1`。

| # | 词 | 命中? | 动作 | 内存（队头 → 队尾） | 查词典次数 |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 | 否 | 查词典、放入 | `{1}` | 1 |
| 2 | 2 | 否 | 查词典、放入 | `{1,2}` | 2 |
| 3 | 1 | **是** | **什么都不动** | `{1,2}` | 2 |
| 4 | 5 | 否 | 查词典、放入 | `{1,2,5}` | 3 |
| 5 | 4 | 否 | 满了，淘汰队头 1，放入 4 | `{2,5,4}` | 4 |
| 6 | 4 | **是** | 什么都不动 | `{2,5,4}` | 4 |
| 7 | 1 | 否 | 淘汰队头 2，放入 1 | `{5,4,1}` | 5 |

输出 `5`，与官方一致。

**注意第 3 步**：词 1 命中后仍在队头，于是第 5 步被淘汰的正是它。本机把命中后"挪到队尾"的 LRU 版本（`deque` + `find`/`erase`/`push_back`）真编译出来跑同一组样例，第 5 步淘汰的是 2，第 7 步的 1 变成命中，**实测输出 `4`**，与官方答案 5 不同。这组样例刚好能区分两种写法，务必带学生走一遍。

## 讲解代码

完整带注释版本见 `solution.cpp`。核心：

```cpp
if (inMem.count(w)) continue;            // 命中：内存不动（FIFO，不是 LRU）
lookup++;
if ((int)mem.size() == M) {              // 只有装满 M 个才淘汰
    inMem.erase(mem.front());
    mem.pop();
}
mem.push(w); inMem.insert(w);
```

## 验证结论

本机 `g++ -static -O2 -std=c++14` 编译**无警告**，实测：

| 检验项 | 结果 |
| --- | --- |
| 官方样例 `3 7 / 1 2 1 5 4 4 1` | 输出 `5` ✅ |
| 随机对拍 800 组（$M \le 6$，$N \le 40$，词表 8 个 ⇒ 大量重复命中）vs 用 `vector` 手工 `shift()` 淘汰队头的参照实现 | 不一致 0 组 |
| **读错题的代价**：2000 组随机数据（$M\le8$，$N\le60$）上 FIFO 与 LRU 两个参照实现的差异频率 | 两轮实测 **709 组（35.5%）与约 36.9%** 不同 ⇒ 三种读法里"读对规则"平均能救回三分之一以上的数据 |
| 极限规模 $M = 100$，$N = 1000$，词值随机 $[0,1000]$ | **8 ms** 出结果，答案 902（参照实现同为 902）；首次冷启动实测 124 ms，差额是进程启动 + 本机安全软件扫描 |

参照实现刻意不用 `queue`/`set`，而是"数组从头扫 + 删第一个元素整体前移"，用来验证淘汰对象选得对。**洛谷提交结果未获取，因此不下 AC 结论。**

## 易错点与坑

- **写成 LRU**：命中后把词挪到队尾。这是本题最常见的错误，而且样例只有一组，第 3 步恰好能暴露它 —— 一定要用样例手动跑一遍。
- **读入顺序读反**：题面第一行是 `M N`（内存容量在前），很多同学习惯先读长度，读到 `7 3` 就直接挂。
- **未满就淘汰**：`mem.size() == M` 写成 `>= M` 或无条件 `pop`，会在内存没满时误删。
- **淘汰时忘了同步 `inMem`**：下次查这个词仍然"命中"，答案偏小。
- **`mem.size()` 返回无符号数**：与 `int M` 比较时若写成 `mem.size() - 1` 可能在 0 时下溢成极大值；本代码用 `== M` 规避。

## 常见变式

| 变式 | 差异 | 应对 |
| --- | --- | --- |
| 淘汰"最久未使用"（真 LRU） | 命中后需把该元素移到队尾 | 用 `list` + 哈希表，或 $M$ 小时线性查找后手动移动 |
| 内存单元可存多个词 | 不再是队列 | 按题意重新设计淘汰判据 |
| $N \le 10^6$ | 线性扫内存变慢 | 保留 `set`/`bool[]` 判存在，队列仍是 $O(1)$ 淘汰 |

## 小结

模拟题的胜负点常常不在"会不会写数据结构"，而在**有没有逐字读清淘汰/更新规则**：`最早进入` 是 FIFO，`最久没用` 是 LRU，一词之差答案不同，而且往往只体现在某一步上。
