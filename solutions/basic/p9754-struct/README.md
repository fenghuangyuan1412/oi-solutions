## 题目大意

模拟一种类 C++ 语言的结构体。基本类型只有 4 种：`byte`(1)、`short`(2)、`int`(4)、`long`(8)，**对齐要求 = 自身大小**。

- **定义类型**：`struct T { 类型1 名1; 类型2 名2; … }`。成员按声明顺序排布，每个成员先对齐到自己的对齐要求，再占掉自己的大小；整个结构体的**对齐要求 = 成员对齐的最大值**，**大小**要补齐到对齐要求的整数倍。**定义类型不占内存。**
- **定义元素**：从内存地址 0 开始依次排开，每个元素的起始地址也要对齐；输出该元素的起始地址。
- **访问成员**：给 `a.b.c` 这种路径，输出**最内层**那个基本类型成员的起始地址。
- **反查地址**：给一个地址，判断是否有基本类型成员正好占据它，有就按 `a.b.c` 格式输出，没有输出 `ERR`。

样例 1：

```
5
1 a 2            ← 定义 struct a { short aa; int ab; }
short aa
int ab
1 b 2            ← 定义 struct b { a ba; long bb; }
a ba
long bb
2 b x            ← 定义元素 b x
3 x.ba.ab        ← 访问 x.ba.ab 的地址
4 10             ← 地址 10 被哪个基本类型成员占据
```

输出：

```
8 4              ← struct a 大小 8，对齐 4
16 8             ← struct b 大小 16，对齐 8
0                ← 元素 x 起始地址 0
4                ← x.ba.ab 在地址 4
x.bb             ← 地址 10 落在 x.bb（long，占 8..15）里
```

## 一、骗分：四个特殊性质，四档分

这道题的**正解就是老老实实模拟**，没有算法上的巧思；但它的**部分分设计得非常清晰**，是"特殊性质分档"的教科书。题面给出的四个特殊性质，每一个都能砍掉一块实现量。

### 特殊性质 C：操作 1 的成员类型全是基本类型

**价值：最大的一档。** 结构体不再嵌套 ⇒ **不需要递归**，每个类型的成员偏移表一层就能算完。

- 只需一个 `map<string, pair<大小, 对齐>>`；
- 操作 3 也退化成"查一层偏移"；
- 代码量大约能砍掉一半。

**为什么值得先写这一档**：它是本题**唯一**的"结构性简化"，其余三个性质都只是"少一类操作"。

### 特殊性质 D：基本类型只有 `long`

所有基本类型大小都是 8 ⇒ **所有对齐要求都是 8**，`alignUp` 退化成"直接按 8 向上取整"。

- 连"成员对齐要求"这张表都不用存，恒为 8；
- 结构体的大小 = $\lceil \text{成员总大小} / 8 \rceil \times 8$。

这一档和 C 是**可以叠加**的（题面给的测试点里就有 `C、D` 同时满足的），叠加后代码极短。

### 特殊性质 A：没有操作 4

操作 4（反查地址）是**整个程序里最容易写错的一段**——它需要递归展开所有元素、判断地址落在哪个基本类型成员内。

- 不写它 ⇒ 直接省掉 `search()` 那 10 行；
- 代价：只丢掉"含操作 4"的那些测试点。

**考场策略**：先写操作 1/2/3，交一次（覆盖 A 档）；如果还有时间，再补操作 4。

### 特殊性质 B：只有一个操作 2

元素表只会有一条记录 ⇒ 反查时不用遍历，访问时不用查找。

- 这一档单独看价值最小，但它常和别的性质叠加出现。

### 骗分路线图

| 优先级 | 写什么 | 覆盖的性质 | 说明 |
| --- | --- | --- | --- |
| 1 | 操作 1 + 2 + 3（**不写操作 4**） | A | 最省力，且 1/2/3 是主干 |
| 2 | 再补操作 4 | — | 补上后覆盖所有无特殊性质的测试点 |
| 3 | 若性质 C 出现，加一个"成员全基本类型"的快分支 | C | 其实是"写了也不亏"的通用优化 |

> **注意**：本题**没有**"输出样例骗分"的空间——样例 1 的输出是 5 行具体数字，蒙不出来。想拿分只能真写。

## 二、正解：递归维护偏移表

### 数据结构

| 结构 | 内容 |
| --- | --- |
| `Type` | 结构体类型：大小 `sz`、对齐 `al`、成员表 `mem` |
| `Member` | 成员：名字、类型名、**相对本类型的偏移 `off`** |
| `Elem` | 已定义元素：名字、类型名、起始地址 `st` |

`basicSz` 存四种基本类型的大小（对齐 = 大小）。

### 计算一个结构体的布局

```cpp
long long off = 0, mx = 1;
for (每个成员 (mt, mn)) {
    info(mt, msz, mal);              // 取该成员的大小与对齐要求
    off = alignUp(off, mal);         // ① 先对齐到该成员的边界
    mem.push_back({mn, mt, off});    // ② 记下偏移
    off += msz;                      // ③ 再占掉它的大小
    mx = max(mx, mal);
}
al = mx;                             // ④ 整体对齐 = 成员对齐的最大值
sz = alignUp(off, mx);               // ⑤ 整体大小补齐到对齐的整数倍
```

这五步是本题的**全部核心**。把 `① 先对齐、② 记偏移、③ 再占用` 的次序记牢，就不会算错。

### 四种操作

| 操作 | 做法 |
| --- | --- |
| 1 定义类型 | 跑上面的五步，输出 `sz` 和 `al` |
| 2 定义元素 | `st = alignUp(curAddr, mal)`，输出 `st`，然后 `curAddr = st + msz` |
| 3 访问成员 | 按 `.` 切分路径；从元素出发，逐层查成员表、累加偏移 |
| 4 反查地址 | 对每个元素递归展开，看目标地址是否落在某个**基本类型成员**的 `[st, st+sz)` 区间内 |

### 操作 4 的递归写法

```cpp
bool search(const string& tn, long long base, long long target, string& rel) {
    if (basicSz.count(tn))                       // 到了基本类型，直接判区间
        return target >= base && target < base + basicSz[tn];
    for (const auto& m : types[tn].mem) {        // 结构体：逐个成员试
        size_t save = rel.size();
        rel += "." + m.name;
        if (search(m.type, base + m.off, target, rel)) return true;
        rel.resize(save);                        // 回溯时把路径恢复
    }
    return false;
}
```

用样例 1 的 `4 10` 走一遍：元素 `x` 是 `b` 类型、起始 0 ⇒ 试 `x.ba`（偏移 0，类型 `a`）⇒ 试 `x.ba.aa`（`short`，地址 0..1，不含 10）⇒ 试 `x.ba.ab`（`int`，地址 4..7，不含 10）⇒ 回退 ⇒ 试 `x.bb`（`long`，地址 8..15，**含 10**）⇒ 命中，输出 `x.bb` ✓

**注意**：地址 10 落在 `x.ba` 的"洞"里（`a` 大小 8，但内部只用了 0..7 中的 0..1 和 4..7）——所以**必须真的递归到基本类型去判断**，不能只看"是否落在某个结构体范围内"。

## 三、复杂度与数值

- **时间**：每个操作 $O(\text{路径长度})$，路径长度 $\le Q$；反查 $O(\text{定义总量})$。$Q \le 100$ 时怎么都够。
- **空间**：与定义总量同阶。
- **数值**：地址可达 $10^{18}$，**必须 `long long`**。`int` 会在"大结构体连续定义"的数据上溢出。
- 名称长度 $\le 10$、类型数 $\le 100$，字符串比较的常数完全可忽略。

## 四、易错点与坑

1. **对齐与占用的次序写反**：必须是「先对齐 `off`，再记录 `off`，最后 `off += size`」。写成"先 `off += size` 再对齐"会让每个成员的偏移都错位。
2. **忘记最后一步 `sz = alignUp(off, mx)`**：结构体整体大小也要补齐。样例 1 里 `struct a` 若不补齐会输出 `8 4` 之外的错值（本例恰好齐，但换成 `short aa; short bb;` 就必须补）。
3. **结构体对齐要求算错**：是**成员对齐的最大值**，不是"第一个成员的对齐"，也不是"所有成员大小之和"。
4. **元素起始地址忘了对齐**：元素也要 `alignUp(curAddr, mal)`，不能直接接在 `curAddr` 后面。
5. **操作 4 只判到结构体层**：地址落在结构体的"洞"里时要输出 `ERR`（样例 2 专门考这个），必须递归到基本类型。
6. **`curAddr` 用 `int`**：地址到 $10^{18}$，`int` 直接爆。全程序地址相关变量一律 `long long`。
7. **路径切分**：`a.b.c` 要按 `.` 切成 3 段，别把整串当一个名字。**注意首段是"元素名"，后面才是成员名**。

## 五、一句话提炼

**这道题不考算法，考"把一段规格说明一字不差地翻译成代码"**——`先对齐、再记偏移、最后占用，整体大小再补齐` 这四句就是全部。而它的**部分分设计**值得单独记：四个特殊性质分别对应"少写一类操作"和"少写一层递归"，考场上先按性质交一版，再逐档补全，是**大模拟题最标准的得分路线**。
