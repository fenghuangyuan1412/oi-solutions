## 题目大意

一把 5 个拨圈的密码锁，每圈 $0\sim9$ 循环。小 Y 每次锁车都**从正确密码出发只转一次**，转法是二选一：

- 只转**一个**拨圈（幅度 $1\sim9$ 任意）；
- 或同时转**两个相邻**拨圈，且**两个拨圈幅度相同**（题面原话："两个拨圈转动的幅度相同"，并明确"不会转成 `1 2 1 1 5`"）。

现在给出锁车后观察到的 $n$ 个状态（题面保证"这 $n$ 个状态都不是正确密码"），问有多少个可能的正确密码，能按上面的方式转出**全部** $n$ 个状态。

官方样例（`problem.txt` 第 29~34 行）：输入 `1` / `0 0 1 1 5`，输出 `81`。

**这个 81 怎么来的**（题面样例解释原话：**"转动一个拨圈的方案有 $45$ 种，转动两个拨圈的方案有 $36$ 种"**）：

| 反推方式 | 位置数 | 幅度选择 | 候选个数 | 例子（观测状态 `0 0 1 1 5`） |
| --- | --- | --- | --- | --- |
| 只转一个拨圈 | 5 个位置任选 1 | $1\sim9$ 共 9 种 | $5\times 9 = 45$ | `0 0 1 1 4`（第 5 圈差 1）、`1 0 1 1 5`（第 1 圈差 9） |
| 同时转相邻两圈 | 4 对相邻 $(1,2)(2,3)(3,4)(4,5)$ | $1\sim9$ 共 9 种 | $4\times 9 = 36$ | `9 9 1 1 5`（前两圈都差 1） |
| 合计 | | | **81** | 本机脚本实测：单圈前像 45、双圈前像 36、去重后 81 ✅ |

单圈前像只改 1 位、双圈前像改 2 位，两类不可能重合，所以 45 + 36 = 81 无重复计数。

## 一、骗分：这一档怎么拿

先把题面的数据范围表逐字抄下来（`problem.txt` 第 50~57 行）：

| 测试点 | $n\le$ | 特殊性质 |
| :---: | :---: | :---: |
| $1\sim3$ | $1$ | 无 |
| $4\sim5$ | $2$ | 无 |
| $6\sim8$ | $8$ | A |
| $9\sim10$ | $8$ | 无 |

> 特殊性质 A（逐字）："保证所有正确密码都可以通过仅转动一个拨圈得到测试数据给出的 $n$ 个状态。"

**分数口径先说清楚**：`problem.txt` 只写了"分值 100"，没写每个测试点几分。下面按 CCF 惯例把 100 分平均分给 10 个测试点（**每点 10 分**）来估档，属于**推断**，不是实测；实际分数以评测为准（本目录未提交）。

### 档 1（$n=1$，测试点 1~3，约 30 分）：直接输出 81，一行代码

上面那张表里 $n=1$ 的答案和观测状态**长什么样毫无关系**：任何状态都有恰好 $5\times9 + 4\times9 = 81$ 个前像。于是

```cpp
if (n == 1) { cout << 81 << "\n"; return 0; }   // 45 + 36，与状态无关
```

这是本题最便宜的档：**不需要想清楚任何算法**，只需要数清"一次操作有几种"。实测：`solution_partial.cpp` 在官方样例上输出 `81`，与正解一致。

### 档 2（特殊性质 A，测试点 6~8，约 30 分）：只认"转一个拨圈"

性质 A 已经承诺"所有正确密码都只靠转一个拨圈就能解释全部状态"，那判定条件可以砍掉一半：

```cpp
// 只认单拨圈：恰好一个位置的差值非零
bool reachable_one_dial(const int p[6], const int s[6]) {
    int nz = 0;
    for (int i = 1; i <= 5; ++i) if ((s[i] - p[i] + 10) % 10 != 0) ++nz;
    return nz == 1;
}
```

候选仍然靠 $10^5$ 全枚举。**性质 A 保证这样做不会漏掉任何正确密码**，所以这一档是满分逻辑在受限数据上的正确特化，不是"赌"。本目录 `solution_partial.cpp` = 档 1 的特判 + 档 2 的判定，两档合起来是"约 60 分"的兜底。

### 档 3（反面教材，实测）：只认单拨圈在多拨圈数据上会塌

自己造一组只能靠"双拨圈"解释的数据（$n=2$，状态 `1 1 0 0 0` 和 `2 2 0 0 0`）：

```
输入                      本机实测输出
2                         solution.cpp         => 10
1 1 0 0 0                 solution_partial.cpp =>  2
2 2 0 0 0
```

正解数出的 10 个密码是 `00000, 12000, 21000, 33000, 44000, 55000, 66000, 77000, 88000, 99000`（独立 JS 脚本打印出来的原样）。骗分版只剩 `12000` 和 `21000` 两个 —— 另外 8 个密码要靠"同时转两个相邻拨圈"才能解释，被那一行判定直接砍掉了。**结论：档 2 只在性质 A 的数据上成立，4~5、9~10 号点必须用正解。**

## 二、正解：把 10 万个密码全部试一遍

### 关键观察

1. **搜索空间小到离谱**：密码只有 $10^5$ 个，$n$ 只有 8。$10^5\times 8\times 5 = 4\times10^6$ 次基本运算，1 秒时限下连 10 ms 都用不完（实测 6 ms）。这种题**枚举就是正解**，不需要任何优化。
2. **把"一次操作"翻译成差值**：设候选密码为 $p$，观测状态为 $s$，逐位算 $dif_i=(s_i-p_i+10)\bmod 10$。拨圈是循环的，"向前拨 $k$ 格"和"向后拨 $10-k$ 格"是同一件事，所以 $dif_i\in\{0,\dots,9\}$ 已经把两种方向都覆盖了。
3. 于是要么"恰好一位非零"，要么"恰好两位非零、这两位相邻、且差值相等"，别的形状都不可能是转一次得到的。

### 算法设计

```
枚举 x = 0 .. 99999
    把 x 拆成 5 位（不足 5 位就在高位补 0）得到候选 p[1..5]
    对每个观测状态 s[k]：用差值判定 reachable(p, s[k])
    全部 n 个状态都可达 → ans++
输出 ans
```

拆位的写法 `for (int i = 5; i >= 1; --i) { p[i] = t % 10; t /= 10; }` 天然带前导零：`00007` 会拆成 `0 0 0 0 7`，不会漏。

### 正确性

判定函数与题面规则**逐条对应**，没有中间假设：

- *题面"仅转动一个拨圈"* ⇔ $dif$ 只有 1 个非零。幅度可取 $1\sim9$ 任意值，非零就合法；
- *题面"同时转动两个相邻拨圈，幅度相同"* ⇔ $dif$ 有 2 个非零、位置相邻、值相等；
- *题面"这 $n$ 个状态都不是正确密码"* ⇔ $dif$ 全 0 的情况必须判**不合法**（否则会把观测状态本身也算成密码）；
- 其他形状（3 个以上非零、两个非零但不相邻、相邻但幅度不同）都无法用"一次操作"实现。

枚举覆盖了 $10^5$ 个候选且每个候选只在其 $n$ 个状态**全部**可达时才计数 —— 这正是题目要求的"能够产生全部 $n$ 个状态的正确密码"的定义。所以 $ans$ 精确等于答案，无重复、无遗漏。

### 复杂度

- 时间 $O(10^5\cdot n\cdot 5)$，$n\le 8$ ⇒ 上界 $4\times10^6$；
- 空间 $O(n)$（存 $n$ 个状态）；
- 全程用 `int` 足够：答案 $\le 10^5$。

## 四、讲解代码

### 正解（`solution.cpp`，判定部分全文）

```cpp
bool reachable(const int p[6], const int s[6]) {
    int dif[6], pos[6], nz = 0;
    for (int i = 1; i <= W; ++i) {
        dif[i] = (s[i] - p[i] + 10) % 10;   // 循环拨圈的差，必须先取模归到 0..9
        if (dif[i] != 0) pos[nz++] = i;      // 记下"动了哪几圈"
    }
    if (nz == 0) return false;               // 状态 = 密码，题面保证不该出现
    if (nz == 1) return true;                // 只转一个拨圈
    if (nz == 2 && pos[1] == pos[0] + 1 &&   // 相邻
        dif[pos[0]] == dif[pos[1]]) return true;   // 且幅度相同
    return false;
}
```

外层就是一个 $x = 0\sim99999$ 的枚举，`for (int k = 0; k < n && ok; ++k)` 里的 `&& ok` 是**短路**：一个状态解释不通就直接淘汰，不用把剩下 7 个也查完。

### 骗分版（`solution_partial.cpp`）与正解的差别

只有两处：

1. 判定函数删掉双拨圈分支，变成 `return nz == 1;`（**只认单圈**）；
2. 开头多一句 `if (n == 1) { cout << 81 << "\n"; return 0; }` 把档 1 的分捡回来。

想从骗分版升级成正解，就是把第 1 条那两行加回去 —— 考场上"先写单圈版拿性质 A 的档，再补双圈分支"是很自然的推进顺序。

## 五、易错点与坑

下面 6 条都**实测过**：每份都在"判定函数那一行"故意写错，编译成独立 exe，喂官方样例 `1` / `0 0 1 1 5`（正确答案 `81`），输出逐字照抄。

| # | 错误写法 | 官方样例实际输出 | 应该是 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | 漏掉"幅度必须相同"，只判相邻 | `369` | `81` | $45+4\times9\times9=369$，多算了 288 个非法前像 |
| 2 | 漏掉"必须相邻"，只要两处非零且同幅度就算 | `135` | `81` | $45+\mathrm C_5^2\times9=135$ |
| 3 | 把"状态就是密码"（`dif` 全 0）也算可达 | `82` | `81` | 多加的正是观测状态自己 |
| 4 | 只认单拨圈（= 本目录骗分版的判定，不加特判） | `45` | `81` | 少掉 36 个双圈前像 |
| 5 | 差值直接相减不取模 `s[i]-p[i]` | `76` | `81` | 负差被当成"另一个幅度"，同幅度判定错乱 |
| 6 | 枚举范围写成 `x < 10000`（漏一位） | `63` | `81` | 只统计了首位为 0 的密码 |

另外三条不实测也要记住：

7. **`+10` 再取模**：C++ 里负数取模可能得负值（`-1 % 10 == -1`），所以必须写 `(s[i] - p[i] + 10) % 10`，不能省那个 `+10`。
8. **前导零**：`00007` 是合法密码，靠"整数拆位"枚举时拆出来天然是 `0 0 0 0 7`；但如果改用字符串读入再比长度，就会把 4 位写法漏掉。
9. **输出就是一行整数**：本题没有多组数据（第一行是 $n$ 不是 $t$），也别输出多余空格/提示语 —— 评测是按行精确比的。

## 六、常见变式

| 变式 | 差异 | 备注 |
| --- | --- | --- |
| 拨圈数从 5 变成 $k$ | 枚举规模变 $10^k$ | $k=6$ 就是 $10^6$，仍可枚举；$k\ge 8$ 要换成"由第一个状态反推 81 个前像" |
| 允许同时转任意两个拨圈（不必相邻） | 判定去掉相邻条件 | 前像数变 $45+\mathrm C_5^2\times9=135$（就是上表第 2 行的数字） |
| 允许多次转动 | 变成图上可达/最短路问题 | 完全换赛道，本题的"枚举+判定"失效 |
| 问"最少几次操作能把 A 变成 B" | 逐位独立，取 $\min(d, 10-d)$ 相加 | 循环拨圈的入门题，和本题共用差值技巧 |
| $n$ 个状态里可能有重复 | 用 `set` 去重再判 | 不影响本题：重复状态判定结果相同 |

## 七、一句话提炼

**看到"$10^5$ 种可能 + 只要 8 个约束"就想全枚举**：把题面那条"转一个圈 / 转相邻两个圈且同幅度"的规则逐字翻译成差值判定函数 `reachable()`，剩下的活枚举替你干 —— 骗分时只需要把判定函数"写窄一点"（只认单圈 + $n=1$ 特判），就能稳稳搬回档 1 和特殊性质 A 的分。
