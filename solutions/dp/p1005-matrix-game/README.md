## 题目大意

$n$ 行 $m$ 列的矩阵，每个元素是非负整数。规则（题面逐字）：

1. 每次取数时须从**每行各取走一个元素**，共 $n$ 个，经过 $m$ 次取完；
2. 每次取走的元素只能是该元素所在行的**行首或行尾**；
3. 每次取数有一个得分值，为每行取数的得分之和，每行得分为**被取走的元素值 $\times 2^i$**，$i$ 表示第 $i$ 次取数（从 1 开始编号）；
4. 游戏结束总得分为 $m$ 次取数得分之和。

求最大总得分。

数据范围（逐字）：

- 对于 $60\%$ 的数据，满足 $1 \le n, m \le 30$，**答案不超过 $10^{16}$**；
- 对于 $100\%$ 的数据，满足 $1 \le n, m \le 80$，$0 \le a_{i,j} \le 1000$。

## 骗分第二课：分档表里的"答案不超过 $10^{16}$"就是给你的 60 分

多数题目的分档只放宽 $n, m$，而这道题**直接承诺了答案的大小上限**。这一行字就是白送的 60 分：

| 你用的类型 | 上限 | 结论 |
| --- | --- | --- |
| `int` | $2.147\times10^9$ | $m = 30$ 一行全 1000 就要 $2.1\times10^{12}$，**当场爆** |
| `long long` | $9.22\times10^{18}$ | 覆盖 $60\%$ 档的承诺（$\le 10^{16}$）⇒ **稳拿 60 分** |
| `__int128`（GCC 扩展） | $\approx 1.7\times10^{38}$ | 满分上限 $80 \times 1000(2^{81}-2) \approx 1.9\times10^{29}$，够用 ⇒ 100 分，但要**自己写输出** |
| 手写高精度 | 无上限 | 100 分，且是纯标准 C++ |

本机实测（`g++ -static -O2 -std=c++14`）：

| 数据 | 真值（`BigInt`） | `int` 版 | `long long` 版 | `__int128` 版 |
| --- | --- | --- | --- | --- |
| 官方样例 $2\times3$ | 82 | 82 | 82 | 82 |
| $1\times30$，元素全 1000 | 2147483646000 | **-2000** | 2147483646000 | 2147483646000 |
| $80\times80$，元素全 1000 | 193428131138340667952988000000 | — | **-160000** | 与真值逐位相等 |

`long long` 版在极限数据上输出 `-160000`（溢出后变负数）—— 这就是"算法全对、数据类型错"的典型死法：不是 WA 在小数据，而是 WA 在最后 40 分。

**教学要点**：骗分不一定靠"弱化算法"。读分档表时，"答案不超过 X""保证 X 在 int 范围内"这类**数值承诺**往往比 $n, m$ 的限制更值钱，因为它允许你用一个简单类型换一整档分数。

## 思路推导

### 1. 关键观察：行与行完全独立

每次操作"从每行各取一个"，得分是**各行得分之和**，乘数 $2^i$ 只跟"第几次操作"有关，对所有行一致。因此：

$$\text{总得分} = \sum_{\text{每一行}} (\text{该行按规则取完的得分})$$

各行互不影响，最优解就是"每行各自取最优"再相加。（严格说法：第 $i$ 次操作的乘数对所有行相同，所以行 $r$ 的第 $i$ 次取值只由行 $r$ 自己的取法序列决定 ⇒ 目标函数是各行贡献之和，无耦合约束 ⇒ 逐行独立最大化即为全局最优。）

于是一行变成：**$m$ 个数排成一行，每次从两端取一个，第 $i$ 次取的数乘 $2^i$，求最大总分。**

### 2. 区间 DP

设 $f[l][r]$ = "区间 $[l, r]$ 还没取，把它取完能拿到的最大分"。区间还剩 $\text{len} = r-l+1$ 个数，说明已经取走了 $m-\text{len}$ 个，**下一次是第 $k = m-\text{len}+1$ 次**，乘数是 $2^k$：

$$f[l][r] = \max\big(a_l \cdot 2^k + f[l+1][r],\;\; a_r \cdot 2^k + f[l][r-1]\big)$$

边界：$l > r$ 时 $f = 0$。答案 $f[1][m]$。填表顺序按区间长度从小到大 ⇒ 转移用到的都是更短的区间，已算好。

### 3. 复杂度分析

单行 $O(m^2)$ 个状态、$O(1)$ 转移，共 $n$ 行 ⇒ $O(n m^2)$？不对 —— 每个状态要 $O(1)$，但**每行都要重算 $m^2$ 个状态**，所以是 $O(n m^2)$。$n = m = 80$ ⇒ $5.12 \times 10^5$，轻松。空间每行一张 $m \times m$ 表。

> 注：这里 $k$ 依赖 $\text{len}$，所以不能把 $2^k$ 提到外面合并成"一行一个结论"，逐行 DP 是必要的。

### 4. 正确性说明

对固定行，任意取法序列对应唯一的一棵"从外向内剥区间"的决策树，第 $i$ 次取走的是当时区间的一个端点；反之每个 $[l,r]$ 的选择也唯一确定一种取法。$f[l][r]$ 覆盖了"该区间所有可能的取完方式"，转移枚举第一次取左端还是右端，两种情况不重不漏，且乘数 $2^k$ 由剩余个数唯一决定，因此 $f[1][m]$ 是该行的最大值。逐行相加由第 1 节的独立性成立。

## 板书演示（不用可视化）

官方样例第一行 `[1 2 3]`，$m=3$。8 种 L/R 序列里有很多其实取到同一串数（区间只剩 1 个时左右是同一种），去掉重复只剩 4 种本质取法：

| 取法（L=取左端，R=取右端） | 依次取到的数 | 得分（×2, ×4, ×8） | 合计 |
| --- | --- | --- | --- |
| **LLL** | 1, 2, 3 | 2, 8, 24 | **34** ← 最大 |
| LRL | 1, 3, 2 | 2, 12, 16 | 30 |
| RLL | 3, 1, 2 | 6, 4, 16 | 26 |
| RRL | 3, 2, 1 | 6, 8, 8 | 22 |

第二行 `[3 4 2]` 同理 4 种：

| 取法 | 依次取到的数 | 合计 |
| --- | --- | --- |
| **RLL** | 2, 3, 4 | **48** ← 最大 |
| LRL | 3, 2, 4 | 46 |
| RRL | 2, 4, 3 | 44 |
| LLL | 3, 4, 2 | 38 |

$34 + 48 = 82$ ✅ 与官方输出一致（上表由程序枚举得到，不是手算）。

顺带说明"为什么不能贪心"：第一行 `1 2 3` 若按"每次取较大的一端"贪心，会先取 3（×2 = 6），而最优化是先取 1，让 3 乘上更大的 $2^3$ —— **越大的数越要留到后面取**，这正是 DP 要自己算的东西。

## 讲解代码

- `solution.cpp`：$60$ 分档（`long long` 版），逻辑就是满分算法，只是类型不够；
- `solution_full.cpp`：满分档（`__int128` 版），多了一个手写输出函数。

核心转移（两版相同）：

```cpp
int k = m - len + 1;                          // 这是第 k 次取数
f[l][r] = max(a[l] * pw[k] + f[l + 1][r],
              a[r] * pw[k] + f[l][r - 1]);
```

`__int128` 版唯一的新东西是输出：

```cpp
void printInt128(i128 v) {
    if (v == 0) { cout << '0'; return; }
    if (v < 0) { cout << '-'; v = -v; }
    char buf[50]; int top = 0;
    while (v > 0) { buf[top++] = char('0' + (int)(v % 10)); v /= 10; }
    while (top--) cout << buf[top];           // 除 10 取余，倒着输出
}
```

```bash

g++ -static -O2 -std=c++14 -Wall solution_full.cpp -o sol_i128.exe   # 满分档（__int128）
g++ -static -O2 -std=c++14 -Wall int_array.cpp     -o sol_int.exe    # 反面教材：数组全用 int

```

| 检验项 | 结果 |
| --- | --- |
| 官方样例 `2 3 / 1 2 3 / 3 4 2` | 两版都输出 `82` ✅ |
| 随机对拍 800 组（$n \le 3$，$m \le 5$，值 $0..1000$）vs **逐行枚举 $2^m$ 种取法**的暴力 | 不一致 0 组（同时验证了"各行独立"这一前提） |
| 两版互拍 400 组（$m \le 4$，保证不溢出） | 不一致 0 组 |
| 溢出边界实测（单行全 1000，真值取闭式 $1000(2^{m+1}-2)$） | $m=40$、$45$、$50$ 与真值相等；$m=58$ 起 `long long` 版错（4.6e18 vs 真值 5.76e20）；$m \ge 60$ 输出 `-2000` |
| 极限 $80 \times 80$ 全 1000 | `__int128` 版输出 193428131138340667952988000000，与闭式真值逐位相等；`long long` 版输出 `-160000` |
| `int` 数组版（`int_array.cpp`，$m=30$ 全 1000） | 输出 `-2000`，真值 2147483646000；$80\times80$ 输出 `-160000` |

（溢出扫描那一段的"真值"用闭式 $v(2^{m+1}-2)$ 算，**不是**用 $2^m$ 枚举：整行取值相同时无论从左还是从右拿，第 $k$ 次都拿到 $v$，总和与取法无关。顺带记一笔 JS 的坑：`1 << m` 按 `m % 32` 计算，$m \ge 32$ 时枚举会静默alias成一个"看着小、跑到天荒地老"的循环，`verify.js` 里的 `rowBrute` 已经改成 $m>20$ 直接抛错。）

## 易错点与坑

- **只把答案变量改成 `long long`**：`int a[]`、`int pw[]` 参与乘法时仍按 `int` 计算，溢出发生在相加之前。要改就整条链一起改。
- **$2^k$ 用 `pow(2, k)`（浮点）**：`double` 只有 53 位有效二进制，$k > 50$ 就丢精度，且返回浮点。必须整数递推 `pw[i] = pw[i-1] * 2`。
- **乘数编号算反**：$k$ 是"第几次取"，剩余 $\text{len}$ 个时 $k = m - \text{len} + 1$；写成 $k = \text{len}$ 会让先取的数乘 $2^m$，恰好是反向策略，样例就可能过不了。
- **`__int128` 不能直接 `cout`**：忘了写输出函数会编译错误（或在别处被隐式转换悄悄截断）。
- **`__int128` 是 GCC 扩展**：如果评测环境只允许标准 C++，就得手写高精度（大整数加法 + 乘 2）。
- **每行忘了清空 `f`**：行与行独立，但表是复用的，`memset(f, 0, sizeof f)` 必须在每行开始前执行。

## 常见变式

| 变式 | 差异 | 应对 |
| --- | --- | --- |
| 只有一行（$n=1$） | 经典"取牌游戏" | 同一套区间 DP，注意乘数仍是 $2^i$ |
| 乘数是 $i$ 而不是 $2^i$ | 数值小很多，`long long` 全程够 | 改 `k` 的用法即可 |
| 两端都能选但要求先左后右 | 无决策 | 直接按公式求和 |

## 小结

骗分不只有"写不出正解就交暴力"这一条路：**分档表里的数值承诺能直接换成一个类型的选择**，`long long` 换来 60 分、`__int128`/高精度换来满分。而算法本身（区间 DP）在两档里是同一份代码 —— 写一次，靠类型分档拿分，是考场性价比极高的一招。
