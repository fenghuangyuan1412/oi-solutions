# P1752 点菜 · 本机验证记录

全部数字为本机实测（Windows 10 / Git Bash / g++ `-static -O2 -std=c++14`，2026-10-02）。
exe 与临时大数据不进仓库；对拍脚本 [`stress.js`](stress.js)、暴力 [`brute.cpp`](brute.cpp) 仅用于验证，非讲解代码。

## 1. 官方样例

```bash
$ printf '2 3 1 1\n5 2\n5 3\n6 4\n5\n1\n' | ./sol.exe
3
$ printf '2 3 1 1\n5 2\n5 3\n6 4\n5\n1\n' | ./verify/brute.exe
3
```

两份代码一致，且与洛谷页面官方样例输出一致（题面样例 `2 3 1 1 / 5 2 / 5 3 / 6 4 / 5 / 1 → 3`）。

## 2. 随机对拍（sol vs 网络流暴力，逐字节比较）

| 轮次 | 参数（组数 / 最大 n / 最大 m） | 结果 |
| --- | --- | --- |
| 1 | 5000 / 6 / 8 | 不一致 0 组 |
| 2 | 1500 / 15 / 25 | 不一致 0 组 |
| 3 | 300 / 30 / 40 | 不一致 0 组 |

生成器特征（`stress.js` 内置）：约 15% 全挑剔、15% 全贫穷、25% 无普通人（n=p+q）、其余含普通人；约 1/3 的组值域压到 0..2，制造大量"美味度恰好等于下限 / 价格恰好等于上限"的边界与并列。累计 **6800 组，0 不一致**。

历史插曲：修复前的一版把美味度、价格拆在两个数组里各自排序，第 10 组即报不一致（正解 1 / 暴力 2），数据为 `6 6 4 1 / (0,2)(1,2)(1,2)(0,2)(0,1)(1,0) / 下限 1 0 1 1 / 上限 0`——del=0 的三道菜只有"下限 0 的挑剔者 + 普通人"两人能吃，一周装不下，正确答案 2。改成结构体捆绑排序后全部通过。该数据保留为回归用例。
