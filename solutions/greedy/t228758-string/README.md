## 题目大意

给你两个字符串 $s_1, s_2$，要拼出一个 $s_3 = s_1' + s_2'$，其中

- $s_1'$ 是 $s_1$ 的**非空**前缀（至少取 1 个字符，至多取完）；
- $s_2'$ 是 $s_2$ 的**非空**前缀；
- 要求 $s_3$ 的**字典序尽可能小**。

- 输入：一行两个字符串 $s_1, s_2$，空格隔开
- 输出：字典序最小的 $s_3$
- 数据范围：$1 \le |s_1|, |s_2| \le 10^5$
- 样例：`happy birthday` → `hab`；`abc defg` → `abcd`

**一句话翻译成人话**：从第一个串前面撕一段下来，从第二个串前面也撕一段下来，粘一起，要让粘出来的东西字典序最小。

> 先提醒一个最容易读错题的地方：**不是**"把两个串都用完"，也**不是**"各取一半"。两边都可以只取一个字符，"非空"是唯一的硬约束。

## 思路推导

### 1. 暴力想法与它的瓶颈

最老实的做法：枚举 $|s_1'| = i$（$1 \le i \le |s_1|$）和 $|s_2'| = j$（$1 \le j \le |s_2|$），把 $10^5 \times 10^5 = 10^{10}$ 种拼法全造出来，两两比字典序取最小。

$10^{10}$ 次连"造串"都造不完（每次还要 $O(n)$ 拷贝），时限直接爆。所以必须**把 $10^{10}$ 个候选砍成 1 个**。

砍的办法不是优化循环，而是**用字典序的性质把候选空间整个塌缩**。下面三步，每一步都只问一个问题。

### 2. 关键观察

#### 观察 1：答案的第一个字符已经被钉死了 —— 一定是 $s_1[0]$

因为 $s_1'$ 非空，所以 $s_3$ 的第 1 个字符就是 $s_1$ 的第 1 个字符，**没得选**。

这一步看起来废话，但它定下了本题的基调：字典序比较只看**第一个不同位**，所以我们每做一步选择，都要问"这个选择会不会改变第一个不同位"。

#### 观察 2：$s_2'$ 只取 1 个字符，取多了必亏

先固定 $s_1' = p$，只让 $s_2'$ 变。比较两种取法：

$$p + s_2[0] \quad\text{vs}\quad p + s_2[0..j]\ (j \ge 2)$$

第二个串**以第一个串开头**（前缀相同），而且更长。字典序的铁律：

> **若 X 是 Y 的真前缀，则 X < Y。**（短的那个更小）

所以对**任何**固定的 $p$，$q$ 取长度 1 都比取更长更小。全局最优一定在"$s_2'$ 只取首字符"里产生。

记这个字符为 $c = s_2[0]$。于是问题变成：

$$\min_{k \ge 1}\ \big(s_1[0..k-1] + c\big)$$

**只剩一个变量 $k$ 了。** $10^{10}$ 个候选当场变成 $10^5$ 个。

> 讲课时的反面教材：很多同学第一反应是"$s_2$ 也要贪心地多取几个小的"，方向就错了 —— 追加字符永远只会让串变长，而"变长的同前缀串"一定更大。**只有当追加的字符能改变某个更早的分岔位时，追加才有意义**，这一点在观察 3 里会看得非常清楚。

#### 观察 3：两个候选怎么比，只看"分岔的那一位"

设 $A_k = s_1[0..k-1] + c$（长度 $k+1$），$A_m = s_1[0..m-1] + c$，且 $m > k$。

前 $k$ 个字符两边**完全相同**（都是 $s_1$ 的那段前缀）。第一个可能不同的位置是第 $k+1$ 位：

- $A_k$ 在这里已经放完了 $s_1$ 的部分，这一位是 $c$；
- $A_m$ 在这里还要继续吃 $s_1$，这一位是 $s_1[k]$。

于是得到本题**最重要的一条判据**：

$$A_k \;<\; A_m \iff c \le s_1[k]$$

- $c < s_1[k]$：第 $k+1$ 位上 $A_k$ 更小 ⇒ $A_k < A_m$；
- $c > s_1[k]$：第 $k+1$ 位上 $A_m$ 更小 ⇒ $A_k > A_m$；
- $c = s_1[k]$：这一位打平，但 $A_k$ 到此结束、$A_m$ 后面还有字符 ⇒ $A_k$ 是 $A_m$ 的真前缀 ⇒ $A_k < A_m$。

**注意结论里根本没出现 $s_1[k+1], s_1[k+2], \dots$，也没出现 $m$。** 也就是说：

> 要不要再吃一个字符，只取决于"**下一个字符**和 $c$ 谁大"，跟后面还有什么、跟一共吃多长，**全都无关**。

这一条就是贪心的全部依据。

### 3. 算法设计

把观察 3 直接翻译成代码：

1. $c \leftarrow s_2[0]$，$k \leftarrow 1$（先取最短的合法前缀 $s_1[0]$）。
2. 只要还能延长（$k < |s_1|$）**且延长有利**（$s_1[k] < c$），就 $k \leftarrow k+1$。
3. 一遇到 $s_1[k] \ge c$ 立刻停；或者 $s_1$ 吃完了自然停。
4. 输出 $s_1[0..k-1]$ 和 $c$。

时间 $O(|s_1|)$，空间 $O(1)$。

### 4. 正确性说明

设算法停在长度 $k$。要证 $A_k$ 是**所有** $A_m\ (m \ge 1)$ 中唯一最小的。

**比它长的候选（$m > k$）**：算法停在 $k$，说明要么 $s_1[k] \ge c$（在 $k<|s_1|$ 处停），要么 $k = |s_1|$（此时不存在更长的候选）。前一种情形由观察 3，$c \le s_1[k] \Rightarrow A_k < A_m$ 对**一切** $m>k$ 成立。

**比它短的候选（$j < k$）**：算法能走过位置 $j$，说明当时判据成立，即 $s_1[j] < c$。再由观察 3（取 $m>k>j$ 时同样只看第 $j+1$ 位），$A_j > A_m$ 对一切 $m > j$ 成立，特别地 $A_j > A_k$。

两类合起来：$\forall m \ne k,\ A_k < A_m$。$\blacksquare$

> 这个证明值得在课上强调一遍：贪心题最怕"局部最优 ≠ 全局最优"，而本题之所以没有这个隐患，正是因为观察 3 把**任意两个**候选的比较结果都一次性定死了 —— 我们不是在比相邻两项，而是拿到了"$A_k$ 与所有更长的比"和"与所有更短的比"两张通行证。

### 5. 复杂度分析

- 时间：找 $c$ 是 $O(1)$，$k$ 只单调前进，最多 $|s_1|$ 步 ⇒ $O(|s_1|)$；输出 $O(|s_1|)$。总计 $O(|s_1| + |s_2|)$，$n=10^5$ 时约 $2\times10^5$ 次操作，远低于 $10^8$ 量级的时限余量。
- 空间：一个下标变量 + 输入串，$O(1)$ 附加空间。
- 实现陷阱：**不要**边延长边做 `ans = ans + ch` 之类的字符串拼接（$O(n)$ 拷贝 × $n$ 次 = $O(n^2)$，最坏 $10^{10}$）。只记下长度 $k$，最后一次性 `substr` 输出。

## 板书演示（本题不需要动画，纸上一张表就够）

### 样例 1：`happy birthday`

$c = s_2[0] = \texttt{'b'}$。逐个看 $s_1$ 的下一个字符：

| 当前 $s_1'$ | 下一个字符 | 与 $c=\texttt{'b'}$ 比 | 动作 | 候选 $s_1'+c$ |
| --- | --- | --- | --- | --- |
| `h` | `a` | `a < b` | **延长** | — |
| `ha` | `p` | `p >= b` | **停** | `hab` ✅ |

答案 `hab`。手算复核一下"为什么不是 `hb` 或 `happb`"：

- `hb` vs `hab`：第 2 位 `b` vs `a` ⇒ `hab` 小（这就是"延长有利"的意思：多吃的 `a` 出现在分岔位上，把 `b` 顶掉了）。
- `hab` vs `happb`：第 3 位 `b` vs `p` ⇒ `hab` 小（再吃 `p` 就是把 `p` 摆到分岔位上，亏）。

**看懂这两行就看懂了本题**：$c$ 是"守门员"，每次延长都是拿 $s_1$ 的下一个字符去和守门员换位置，换了个更小的才换。

### 样例 2：`abc defg`

$c=\texttt{'d'}$。`a` → 下一个 `b < d` 延长 → `c < d` 延长 → $s_1$ 吃完，停。答案 `abc` + `d` = `abcd`。

这一例说明另一种停止条件：**$s_1$ 被全部吃光**也是合法的终点。

### 三个必须会手算的边界（都是真实跑过的输出）

| $s_1$ | $s_2$ | 程序输出 | 讲什么 |
| --- | --- | --- | --- |
| `zzz` | `z` | `zz` | **相等不延长**。若把判据写成 `<=`，会输出 `zzzz`，错。 |
| `ba` | `b` | `bab` | 答案长度可以超过 2：`bb` vs `bab`，第 2 位 `b > a` ⇒ `bab` 更小。 |
| `hboy` | `a` | `ha` | $c=\texttt{'a'}$ 已是最小字母，$s_1$ 里没有任何字符 $< a$，一步都不延长。 |

> 这三行不是编的，是 `node verify.js` 里"定向边界"一节和暴力枚举同时给出的结果，贪心与暴力完全一致。

## 讲解代码

完整逐段注释版见 [`solution.cpp`](solution.cpp)，核心就 3 行：

```cpp
const char c = s2[0];                 // 观察 2：s2' 只取首字符
int k = 1;                            // s1' 至少取 1 个字符（非空）
while (k < (int)s1.size() && s1[k] < c) ++k;   // 观察 3：只有严格更小才值得延长
cout << s1.substr(0, k) << c << '\n';
```

```
mode0(正确) happy birthday -> hab
mode1(<=)   zzz / z        -> zzzz      ← 相等还延长，错
mode0(正确) zzz / z        -> zz
mode2(k=0)  happy birthday -> b         ← 忘了 s1' 非空，不合法
```

## 易错点与坑

1. **判据写成 `<=`（相等也延长）**：这是本题第一大坑。$s_1[k] = c$ 时延长，$A_k$ 与 $A_{k+1}$ 的第 $k+1$ 位打平，接下来 $A_k$ 结束、$A_{k+1}$ 还有字符 ⇒ $A_k$ 是**真前缀**，本来就更小。所以**相等必须停**。反例：`zzz` / `z` 正确答案 `zz`，`<=` 会给你 `zzzz`。
2. **$s_2'$ 取了整串或取了多字符**：追加只会让串变长，同前缀下长的更大。$s_2'$ 永远只取 1 个字符。
3. **忘了 $s_1'$ 也必须非空**：写成 `int k = 0;` 会输出 `b`（只留 $s_2$ 的首字符），比正确答案还"小"，但不合法 —— 字典序最小不能违反约束。评测会直接 WA。
4. **边扫边拼接字符串**：`s += ch` 在最坏 $|s_1|=10^5$ 时是 $O(n^2)$ 拷贝，可能 TLE。记下标、最后 `substr` 一次输出。
5. **输入读法**：题面说"空格隔开"，`cin >> s1 >> s2` 正确；若真出现含空格的串才需要 `getline`。样例 `happy birthday` 恰好是两个词，别被"这是一句英文"骗了。
6. **`k < s1.size()` 的符号比较**：`size()` 返回无符号数，`int` 与它比较会有编译警告，显式写 `(int)s1.size()`。

## 常见变式

| 变式 | 差异 | 备注 |
| --- | --- | --- |
| 拼数（把若干数拼成**最大**的数） | 比较对象是 $a+b$ 与 $b+a$ 两种拼接 | 洛谷 P1012（NOIP2002），本仓库 [P14357 拼数](../p14357-number/README.md) |
| 本题改成"字典序**最大**" | $s_2'$ 要取整串；相等时**不能**一句话说清，得继续往后比 | 关键差别：取整串后 $A_k$ 不再是 $A_m$ 的真前缀，"打平"不再自动判负 ⇒ 直接把 `<` 换成 `>` 是错的。实测反例 $s_1=$`ca`, $s_2=$`a`：正确答案 `caa`，镜像规则给 `ca`（3 字母小数据上暴力与镜像共不符 2102 组） |
| 允许 $s_1'$ 为空 | 首字符不再钉死，答案可能是 $s_2$ 的前缀 | 观察 1 失效，需要重新讨论 |
| 字典序最小旋转 / 最小表示 | 候选是循环移位而非前缀拼接 | POJ 1509，用最小表示法 $O(n)$ |

## 小结

> **字典序最小 = 第一个不同位最小。** 本题两个"非空"约束把首字符钉成 $s_1[0]$、把尾巴钉成 $s_2[0]$，于是"要不要多取一个字符"只看**下一个字符**与 $s_2[0]$ 的大小 —— 严格更小才延长，相等就停。
