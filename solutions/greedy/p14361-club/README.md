## 题目大意

$n$（偶数）个人分到 3 个部门，第 $i$ 个人对部门 $j$ 的满意度是 $a_{i,j}$，方案满意度 = 所有人满意度之和。限制只有一条（题面原话）：**"不存在一个部门被分配多于 $\frac{n}{2}$ 个新成员"**。求满足限制的最大满意度。多组数据。

**三组官方样例的手算**（本机实测两份代码都输出 `18 / 4 / 13`）：

| 组 | 数据 | 先不管限制（每人选最爱） | 违反限制？ | 修补 | 答案 |
| --- | --- | --- | --- | --- | --- |
| ① $n=4$ | `4 2 1` / `3 2 4` / `5 3 4` / `3 5 1` | 部门 1 得 2 人、部门 2 得 1 人、部门 3 得 1 人，总分 $4+4+5+5=18$ | 部门 1 有 2 人 $=\frac n2$，**没超** | 不用改 | **18** |
| ② $n=4$ | `0 1 0` / `0 1 0` / `0 2 0` / `0 2 0` | 4 人全进部门 2，总分 $1+1+2+2=6$ | 部门 2 有 4 人 $>2$，超了 $r=2$ | 走损失最小的 2 个：损失 $1,1,2,2$ → 减 $1+1=2$ | $6-2=$ **4** |
| ③ $n=2$ | `10 9 8` / `4 0 0` | 2 人全进部门 1，总分 14 | 超 $r=1$ | 两人损失各 $10-9=1$、$4-0=4$，走小的那个 | $14-1=$ **13** |

第 ③ 组很关键：要走的是**损失小的那个人**（第 1 个人改去部门 2 拿 9 分），不是"人多的部门里满意度最低的那个"（第 2 个人只有 4 分，走他损失 4）。

> 特殊性质 A：`a[i][2] = a[i][3] = 0`；性质 B：`a[i][3] = 0`；性质 C：所有 $a_{i,j}$ 在 $[0, 2\times10^4]$ 中**独立均匀随机**生成。

**分数口径**：`problem.txt` 只写"分值 100"，没标每个测试点几分。下面按 20 个测试点均分（**每点 5 分**）估档，属于**推断**；本目录未提交，实际分数以评测为准。

### 档 1（测试点 1~4，$n\le10$，约 20 分）：DFS 硬枚举 $3^n$

最朴素的写法：一个人一个人地试三个部门，超编就剪枝。

```cpp
void dfs(int i, int c1, int c2, int c3, long long s) {
    if (c1 > half || c2 > half || c3 > half) return;      // 已经超载，剪掉
    if (i > n) { best = max(best, s); return; }
    dfs(i+1, c1+1, c2, c3, s + a[i][1]);
    dfs(i+1, c1, c2+1, c3, s + a[i][2]);
    dfs(i+1, c1, c2, c3+1, s + a[i][3]);
}
```

**本机实测的天花板**（同一份 DFS，随机数据，值域 0~9）：$n=10$ 用时 **5 ms**（答案 72）、$n=16$ **139 ms**（110）、$n=18$ **1230 ms**（124）—— $n=18$ 就已经撞破 1 秒时限。$3^{10}=59049$、$3^{18}=387420489$、$3^{30}=205891132094649$（$n=30$ 比 $n=18$ 再乘 $531441$ 倍），所以这一档**只保 $n\le10$**。

### 档 2（测试点 1~11，$n\le200$，约 55 分）：二维计数 DP（本目录 `solution_partial.cpp`）

把"部门 1 有几人、部门 2 有几人"当状态：`dp[c1][c2]` = 已分配若干人、部门 1 占 `c1`、部门 2 占 `c2` 时的最大满意度；**部门 3 的人数不用存**，它等于"已分配人数 $-c_1-c_2$"。转移每人 3 个选择，各自判一下对应部门是否还能加人。

**本机实测**：$n=30$（$t=5$）**5 ms**、$n=200$（$t=5$）**28 ms**、$n=1000$ **386 ms**、$n=2000$ **3274 ms**（超时）。到 $n=10^5$，状态表要有 $(50001)^2 = 2500100001$ 项、约 **9.0 GiB**，转移量约 $7.5\times10^{14}$ —— 本机跑 60 s 没出结果（被脚本掐掉），根本没到拼速度的阶段。**这就是"档次不对"和"常数太大"的区别。**

### 档 3（测试点 12，性质 A，约 5 分）：只有一个部门有分

$a_{i,2}=a_{i,3}=0$ ⇒ 部门 2、3 谁去都是 0 分，于是"把部门 1 装满 $n/2$ 个最值的人"就是最优：

```cpp
sort(v.rbegin(), v.rend());            // v[i] = a[i][1]
for (int i = 0; i < n/2; ++i) ans += v[i];
```

**实测**：自造性质 A 极限数据（$t=5,n=10^5$）时它与正解输出**逐字相同**（`751454270 749571634 750221134 749715270 749651459`），9 次实测最快 176 ms。

### 档 4（测试点 13~14，性质 B，约 10 分）：最优解一定不碰部门 3

$a_{i,3}=0$，而部门 1、2 的容量加起来正好 $n$ ⇒ 把任何待在部门 3 的人挪进"还没满"的那个部门，满意度只增不减。于是问题变成"恰好 $n/2$ 人进部门 1"，按 $a_{i,1}-a_{i,2}$ 从大到小排序取前 $n/2$ 个即可，$O(n\log n)$。**实测**：自造性质 B 极限数据（$t=5,n=10^5$）与正解输出**逐字相同**（`1331976291 1331990135 1333124455 1331709650 1332983330`）。

### 档 5（测试点 15~16，性质 C 随机数据）：侥幸能拿，但别赌

"完全不设限制、每人取最大"在随机数据下几乎不会超载（三个部门各摊到约 $n/3<n/2$）。**实测**：100 组 $n=1000$ 的随机数据里，它与正解输出相同 **100/100**；换成 $n=4$ 只剩 **80/100**、$n=2$ 只剩 **77/100**。官方样例第 ②③ 组就是它翻车的地方（实测输出 `18 6 14`）。**结论**：性质 C 确实能"蒙"到分，但正解只比它多十几行，考场上不值得赌。

## 二、正解：先随便选，再把超编的人"最便宜地"请出去

### 关键观察

1. **超载的部门至多一个。** 两个部门都严格多于 $n/2$ 人，人数和就超过 $n$ 了，矛盾。所以"修一个地方"就够了，不用平衡三个部门。
2. **要请出去的人数是定死的**：若部门 $b$ 有 $m$ 人，则 $r=m-\frac n2$，必须至少有 $r$ 个人离开 $b$。
3. **请出去的人各自只关心"次好的部门"**：第 $i$ 个人从 $b$ 走的代价 $\text{loss}_i = a_{i,b}-\max_{c\ne b} a_{i,c}\ge 0$。
4. **接收部门的容量自动够用**（这一步是本题最漂亮的地方）：另外两个部门在基准方案里一共只有 $n-m=\frac n2-r$ 人，所以**任意一个**接收部门的空位 $\frac n2-c_j \ge \frac n2-\left(\frac n2-r\right)=r$。哪怕 $r$ 个人全挤进同一个部门也放得下 —— 于是"选哪 $r$ 个人"和"他们去哪"这两件事**彻底解耦**，各选各的最优即可。

### 算法设计

```
① 每人先选自己满意度最大的部门，得到基准方案 B，总分 tot = Σ max_j a[i][j]，同时记下每人的 loss
② 找出人数 > n/2 的那个部门 b（找不到就直接输出 tot）
③ r = cnt[b] - n/2；把 loss[b] 排序，tot 减去最小的 r 个 loss
输出 tot
```

### 正确性

*下界*：任取一个合法方案 $A$。基准方案里部门 $b$ 有 $m$ 人，而 $A$ 中部门 $b$ 至多 $n/2$ 人 ⇒ 至少有 $r$ 个"B 里在 $b$ 的人"在 $A$ 中去了别的部门。这些人每人至少付出自己的 $\text{loss}_i$（因为 $b$ 是她的最优部门，去别处最多拿次优），其余人付出 $\ge 0$。所以

$$\text{Loss}(A)\ \ge\ \text{「}b\text{ 里最小的 } r \text{ 个 loss 之和」}.$$

*可达*：算法正是把损失最小的那 $r$ 个人改派到各自的次优部门。由观察 4，接收部门容量一定够，方案合法；损失恰好等于上面的下界。

*结论*：算法输出 $= \text{基准总分} - \text{最小可能损失}$，不劣于任何合法方案，即最优。基准方案里"最爱部门"的平局怎么破都不影响结论（$\text{loss}$ 会相应变成 0，下界与可达同时成立）。$\blacksquare$

### 复杂度

排序 $O(n\log n)$、其余 $O(n)$；空间 $O(n)$（存三组 loss 与计数）。
**数值**：单组答案上界 $2\times10^4\times10^5=2\times10^9$，离 `int` 上限 $2147483647$ 只差 7%，本机极限数据实测答案 `1500801469` —— **`tot` 必须 `long long`**。

## 四、讲解代码

### 正解（`solution.cpp` 的骨架）

```cpp
while (T--) {
    int n; cin >> n; const int half = n / 2;
    vector<int> cnt(3, 0); vector<vector<int>> loss(3);
    long long tot = 0;
    for (int i = 0; i < n; ++i) {
        int a[3]; cin >> a[0] >> a[1] >> a[2];
        int b = 0; if (a[1] > a[b]) b = 1; if (a[2] > a[b]) b = 2;   // 最爱的部门
        int second = -1; for (int j = 0; j < 3; ++j) if (j != b) second = max(second, a[j]);
        ++cnt[b]; tot += a[b];
        loss[b].push_back(a[b] - second);      // 改派代价，>= 0
    }
    int heavy = -1; for (int j = 0; j < 3; ++j) if (cnt[j] > half) heavy = j;
    if (heavy != -1) {
        int r = cnt[heavy] - half;             // 必须走 r 个人
        sort(loss[heavy].begin(), loss[heavy].end());
        for (int k = 0; k < r; ++k) tot -= loss[heavy][k];
    }
    cout << tot << "\n";
}
```

## 五、易错点与坑

下面每条都**实测过**：在正解/骗分版上只改一处，编译成独立 exe，喂官方样例（正确答案 `18 4 13`），再喂一组手算得答案 20 的小数据 `1 / 4 / 0 0 10 ×4`（4 人只对部门 3 给 10 分，最多 2 人能进 ⇒ 正确 20）。输出逐字照抄。

| # | 错误写法 | 官方样例实际输出 | 小数据实际输出 | 为什么错 |
| --- | --- | --- | --- | --- |
| 1 | 不设限制，每人直接取 $\max_j a_{i,j}$ | `18 6 14` | `40` | 第 ②③ 组都超载；小数据里 4 人全进部门 3 |
| 2 | 忘了第一行是 $t$，把 $t$ 当成 $n$ 读 | `11`（只有一行） | `0` | 读入错位，后面全乱 |
| 3 | 改派人数写死成 1（正确是 $r=\text{cnt}[b]-\frac n2$） | `18 5 13` | `30` | 样例第 ② 组要一次走 2 个人 |
| 4 | 代价算成"减去**最差**备选"而不是"次优备选" | `18 4 12` | `20`（抓不出来） | $\text{loss}$ 被放大，第 ③ 组多扣 1 分；小数据两个备选同为 0 所以看不出来 |
| 5 | DP 版忘了判部门 3 的容量 | `18 4 13`（样例全过！） | `40` | 样例没覆盖到这个洞，小数据才暴露 |
| 6 | DP 里 $c_3$ 用 $i-c_1-c_2$ 而非 $(i-1)-c_1-c_2$ | `18 4 13`（样例全过！） | `10` | off-by-one 把"已分配人数"记错一位 |

第 5、6 条是本讲最想强调的：**"官方样例过了"离"正确"还差得远**，评测的坑往往在样例没照到的角落。

另外三条不实测也要记住：

7. **`tot` 用 `int`**：极限答案 $2\times10^9$ 已经贴着 $2147483647$，只要 $a_{i,j}$ 或 $n$ 稍大就翻车；本机实测答案已达 `1500801469`。
8. **"至多一个部门超载"要真去证明**：写成品尝试三轮改派（每个部门都改一次）会把已经合法的方案改坏。
9. **$n$ 是偶数**这个条件只保证 $n/2$ 是整数，别把它当成"每个部门正好 $n/2$ 人"——限制是**不多于**，允许某部门人数为 0（官方样例第 ② 组就是 $2,2,0$）。

## 六、常见变式

| 变式 | 差异 | 备注 |
| --- | --- | --- |
| 部门数变成 $k$，限制仍是"不超过 $n/2$" | 超载部门依然至多一个，改派目标有 $k-1$ 个 | 观察 4 仍然成立：任一其他部门空位 $\ge r$ |
| 限制改成"每个部门不超过 $m$"（$m$ 任意） | 可能同时有多个部门超载 | 贪心失效，要最小费用流 |
| 要求"每个部门至少 1 人" | 多一条下界 | 在 loss 排序时把最小的几个位置特殊处理，或二分答案 |
| 满意度可正可负 | 基准方案可能"谁都不想去" | 每人仍取 $\max$，逻辑不变；答案可能为负，输出别当无符号 |
| 只求"是否存在合法方案" | 变成计数可行性 | 三个部门容量和 $=3n/2>n$，恒有解 |

## 七、一句话提炼

**先按最喜欢的选（不管限制），再只修那一处被破坏的限制**：本题的限制是"没有部门超过一半人"，而**超载的部门至多一个**、**接收部门的空位一定够**，于是"请谁出去"就退化成"取最小的 $r$ 个改派代价" —— 交换论证最干净的样子；想不通这一步，就先写 $O(n\cdot(n/2)^2)$ 的计数 DP 把 $n\le200$ 的 55 分搬走。
