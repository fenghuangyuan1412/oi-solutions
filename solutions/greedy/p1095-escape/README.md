## 题目大意（数字逐字）

守望者要逃离荒岛，**每秒**只能做下面三件事之一（题面："每次活动的持续时间为整数秒"）：

| 动作 | 这一秒推进的距离 | 魔法变化 |
| --- | --- | --- |
| 跑步 | $17\text{m}$ | 不变 |
| 闪烁 | $60\text{m}$ | **消耗 $10$ 点** |
| 原地休息 | $0\text{m}$ | **恢复 $4$ 点** |

题面逐字："守望者的跑步速度为 $17\text{m/s}$，可在 $1\text{s}$ 内移动 $60\text{m}$，不过每次使用闪烁法术都会消耗魔法值 $10$ 点。""守望者的魔法值恢复的速度为 $4$ 点每秒，**只有处在原地休息状态时才能恢复**。"

已知魔法初值 $M$、到出口的距离 $S$、岛沉没的时间 $T$。求最短逃离时间；若逃不掉，输出 $T$ 秒内能走的最远距离。

数据范围（逐字）：

- 对于 $30\%$ 的数据，$1 \le T \le 10$，$1 \le S \le 100$；
- 对于 $50\%$ 的数据，$1 \le T \le 10^3$，$1 \le S \le 10^4$；
- 对于 $100\%$ 的数据，$1 \le T \le 3\times 10^5$，$0 \le M \le 10^3$，$1 \le S \le 10^8$。

**两个输出**：第一行 `Yes` / `No`，第二行一个整数（最短时间 或 最远距离）。

## 骗分第二课：贪心最容易漏掉的，是"看起来没用"的那个动作

拿到题，最自然的贪心是"这一秒干最划算的事"：

```
if (魔法 >= 10) 闪烁（60m）       // 60 > 17，看起来很划算
else           跑步（17m）        // 闪不动就跑
```

这份写法就放在本目录 **`solution_partial.cpp`**（反面教材，故意保留）。它的实测表现：

| 检验 | 结果 |
| --- | --- |
| 样例 1 `39 200 4` | `No / 197` ✅ 与官方一致 |
| 样例 2 `36 255 10` | `Yes / 8` ❌ 官方是 `Yes / 6` |
| 500 组随机数据（$M\le40,S\le3000,T\le22$）与正确答案比对 | 两轮实测分别对 125 组、107 组，正确率 **25.0% / 21.4%** |

**连样例都过不去**——这是本题最好的教学点：样例 2 的 $M=36$ 只够闪 3 次（$36\to6$），贪心版第 4 秒开始只会跑步；而正确答案先**休息 1 秒**把魔法补到 $10$，再闪，10 秒走 $255$m 只需 $6$ 秒。

漏掉"休息"这条规则，贪心就退化成"局部最优 ⇒ 全局劣"。教课时可以让学生先写这份错的，再拿样例砸它——比直接讲正解记得牢。

## 思路推导（正解：`solution.cpp`）

### 1. 关键观察：不要逐秒决策，先定"一共闪几次"

三个动作的每秒距离是 $60 > 17 > 0$，所以**闪一定比跑划算**，闪的次数越多越好；但闪要消耗魔法，而魔法**只能靠休息攒**。于是整个策略被一个变量完全决定：

> 设一共闪 $k$ 次。

给定 $k$：

- 需要魔法 $10k$ 点，初值 $M$，缺口 $10k - M$，只能靠休息补，每次休息 $+4$：
$$\text{rest}(k) = \left\lceil \frac{\max(0,\;10k - M)}{4} \right\rceil \text{ 秒}$$
- 这 $k$ 次闪烁 + $\text{rest}(k)$ 次休息共占 $k + \text{rest}(k)$ 秒，推进 $60k$ 米；
- 剩下的秒数全用来跑步，每秒 $17$ 米。

于是"闪 $k$ 次"时走完 $S$ 米所需的最少秒数：
$$t(k) = k + \text{rest}(k) + \left\lceil \frac{\max(0,\; S - 60k)}{17} \right\rceil$$

答案 $= \min_k t(k)$，再与 $T$ 比较。

### 2. 为什么可以"先算总量，再随便排顺序"？

学生最容易卡在这里。两点：

1. **总距离只跟各动作的秒数有关**，跟先后顺序无关（$60k + 17\cdot\text{run} + 0\cdot\text{rest}$）；
2. **魔法没有上限**（题面只给初值 $M$ 和恢复速度，没有"最多存 $M$ 点"这样的规定）。所以"缺多少补多少"总是可行：把每次休息插紧贴在需要魔法的那一闪之前即可，不存在"休息时魔法溢出浪费"的问题。

⚠️ 如果题目规定魔法上限（很多变式题会加），这个式子立刻失效——必须回到逐秒 DP。**读题时要专门找"有没有上限"这一句。**

### 3. $k$ 枚举到几就够？

再多闪也没意义，两个上界取小的：

- 时间约束：$k + \text{rest}(k) \le T$，超了就 `break`（$k$ 变大只会更糟，因为 $\text{rest}(k)$ 单调增）；
- 魔法约束：$T$ 秒全休息也只能有 $M + 4T$ 点魔法，故 $k \le (M + 4T)/10$。

代码里写 `kmax = (M + 4*T)/10 + 2`，配合 `if (k + rest > T) break;`。$T=3\times10^5$ 时 $k_{\max} \approx 1.2\times10^5$，循环量级完全不是问题（实测 6~8 ms，见验证结论）。

### 4. 逃不掉时输出什么

第二问是"最大距离"而不是"最少时间"，公式换一个：$T$ 秒内闪 $k$ 次的最大距离
$$\max_k \big(60k + 17\,(T - k - \text{rest}(k))\big) \quad \text{s.t. } k + \text{rest}(k) \le T$$
（代码里就是第二个循环，同一套 `rest(k)` 复用。）

### 5. 整数向上取整的写法（本课反复出现的坑）

$$\lceil a/b \rceil \;(a\ge 0,\,b>0) \;=\; (a + b - 1) / b$$

代码：`(lack + 3) / 4`、`(left + 16) / 17`。写成 `lack / 4` 会**少算休息秒**，于是魔法不够却假装够 —— 这类 off-by-one 在小数据上常常看不出来。

### 6. 复杂度

| 项 | 值 |
| --- | --- |
| 时间 | $O(k_{\max}) = O((M+4T)/10)$，$T=3\times10^5$ 时约 $1.2\times10^5$ |
| 空间 | $O(1)$ |

## 板书演示：样例 2（$M=36,\;S=255,\;T=10$）

| $k$（闪几次） | 缺口 $10k-36$ | $\text{rest}(k)$ | 已用秒 $k+\text{rest}$ | 闪的里程 $60k$ | 还需跑 $\lceil(255-60k)/17\rceil$ | $t(k)$ |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | — | 0 | 0 | 0 | 15 | 15 |
| 1 | 否（够） | 0 | 1 | 60 | 12 | 13 |
| 2 | 否 | 0 | 2 | 120 | 8 | 10 |
| 3 | 否（$36\to6$） | 0 | 3 | 180 | 5 | 8 |
| 4 | $4$ | 1 | 5 | 240 | 1 | **6** |
| 5 | $14$ | 4 | 9 | 300 ≥ 255 | 0 | 9 |
| 6 | $24$ | 6 | 12 > 10 | — | — | 非法 |

$\min t(k) = 6$ ⇒ `Yes / 6`。对照贪心版：它只会"闪 3 次 + 跑 7 秒"= $180 + 119 = 299 \ge 255$，但它第 4 秒起每秒只算 17m，累计到 $255$m 落在第 **8** 秒 —— 输出 `Yes / 8`，与官方差 2 秒。**差的就是第 4 秒那一次休息。**

## 讲解代码

完整带注释版本见本目录 `solution.cpp`（正解）与 `solution_partial.cpp`（反面教材）。核心 8 行：

```cpp
long long kmax = (M + 4 * T) / 10 + 2;                 // 再多闪，魔法也攒不出来
for (long long k = 0; k <= kmax; k++) {
    long long lack = 10 * k - M;                       // 魔法缺口
    long long rest = lack > 0 ? (lack + 3) / 4 : 0;    // ceil(lack/4)
    if (k + rest > T) break;                           // 光闪+休息就超时，k 再大只会更糟
    long long left = S - 60 * k;
    long long run  = left > 0 ? (left + 16) / 17 : 0;  // 剩下的用跑
    best = min(best, k + rest + run);
}
```

## 验证结论

本机 `g++ -static -O2 -std=c++14 -Wall` 编译**无警告**。复现：

```bash
g++ -static -O2 -std=c++14 -Wall solution.cpp -o sol.exe
g++ -static -O2 -std=c++14 -Wall solution_partial.cpp -o sol_partial.exe

```

实测输出（`verify.js` 里的参照实现是**逐秒 DP**：状态 = 当前魔法值，值 = 该秒能到达的最远距离，三个动作各转移一次 ⇒ 穷举一切策略，与公式法思路完全独立）：

| 检验项 | 结果 |
| --- | --- |
| 官方样例 `39 200 4` | `No / 197` ✅ |
| 官方样例 `36 255 10` | `Yes / 6` ✅ |
| 枚举 $k$ 版 vs 逐秒 DP，1200 组（$M\le40,S\le3000,T\le22$） | 不一致 **0** 组 |
| 反面教材（`solution_partial.cpp`）vs 逐秒 DP，500 组同规模 | 三轮实测：一致 **125 / 107 / 106 组**，正确率 **25.0% / 21.4% / 21.2%**（随机数据每轮不同，量级稳定在"五分之一到四分之一"） |
| 极限 $M=1000,\;S=10^8,\;T=3\times10^5$ | 输出 `No / 5147142`，耗时 **6~7 ms**（两轮各三次） |

## 易错点与坑

1. **漏"只有休息才能恢复魔法"** —— 写成"跑步时也回魔法"会把答案算小（太乐观），是另一类典型错误。
2. **向上取整写成向下** —— `(lack)/4` 少算休息；`(lack+3)/4` 才是 $\lceil\rceil$。
3. **`Yes` / `No` 大小写** —— 题面是 `Yes`、`No`，首字母大写，写成 `YES`/`NO` 直接 0 分（输出格式类题目一律逐字抄题面）。
4. **两行输出** —— 第一行字符串、第二行整数，不要写成一行。
5. **`int` 溢出** —— $S$ 到 $10^8$，$17T$ 到 $5.1\times10^6$，`60k` 到 $7.2\times10^6$：单独看都不炸，但用 `int` 累加中间量（例如把 $M+4T$ 再乘别的东西）很容易越界。统一 `long long` 最省心。
6. **只考虑"能闪就闪"的顺序** —— 本题正解不需要关心顺序（见 §2），但**前提是魔法无上限**。如果哪天题目加了上限，先别套用公式。

## 常见变式

| 变式 | 影响 | 应对 |
| --- | --- | --- |
| 规定魔法上限 $M$（不能超过初值） | `rest(k)` 公式失效，休息可能浪费 | 逐秒 DP：状态 $(t, \text{mana})$，$O(T\cdot M)$ |
| 三种动作每秒收益改为任意值 | 结论仍成立（闪最优、跑次优、休息 0） | 只需替换 $60/17/4/10$ 常数 |
| 问 $T$ 秒内最远距离（不判 Yes/No） | 少一个分支 | 只保留代码第二个循环 |
| 距离 $S$ 极大（$>10^{14}$） | 可能爆 `long long`？ $60k+17T$ 仍 $\le 10^{7}$ 量级 | 本题不会，但读题时要按 $S$ 上限重算一次 |

## 骗分阶梯：这题怎么拿分

| 时间投入 | 写法 | 预期 |
| --- | --- | --- |
| 5 分钟 | `solution_partial.cpp`（能闪就闪，不休息） | **样例都过不去**，只能靠 $T$ 极小、魔法本就不够用的点；实测正确率约 $1/5 \sim 1/4$。当作反面教材，不建议交 |
| 15 分钟 | 逐秒 DP：`dp[秒][魔法] = 最远距离` | $O(T\cdot(M+4T))$，$T\le10^3$ 档（50%）能过，$T=3\times10^5$ 必挂 —— 但**它是可靠的对拍参照**，本课就是靠它验证正解 |
| 25 分钟 | 枚举 $k$ + 公式（`solution.cpp`） | 满分思路，$O(T+M)$ |

**教学落点**：中间那档 DP 不是"半成品"，它同时是**验证工具**。考场上写不出公式时，交 DP 拿 50 分 + 用它的输出验证你的小数据直觉，比赌一个贪心强得多。

## 小结

这道题的"骗分"教训不在代码量，而在**读题完整度**：题面里"只有处在原地休息状态时才能恢复"这一句，值得单独在草稿纸上抄一遍。漏一条规则的贪心，正确率只有两成；把规则补全变成"枚举闪烁次数"，就是满分。
